# 经营分析驾驶舱数据源核查

> 核查对象：`html/applefarm_dataanlye/da_business.html`（智慧果园 · 经营分析驾驶舱）  
> 核查范围：后台管理系统（`html/applefarm_backhand`）、移动端（`html/applefarm_mobile`）、H5 消费者端（`html/applefarm_h5`）  
> 核查日期：2026-11-10

> **P0 实施说明（2026-11-10）**：本文档表格记录改造前的核查结果。P0 已完成：财年切至 2026，年度营收 753.10 万元、成本 439.94 万元、净利 313.16 万元；营收目标 960 万元可在收入构成页维护；成本结构改为读取 `snzg_cost_structure`；认养占比改为按金额实时计算。
>
> **P1 实施说明（2026-11-10）**：① 净利润/净利率由 `report_profit.html` 地块汇总经 `BizStore.setFinanceSummary()` 写入，顶部与指标卡同源；② 各基地利润由地块数据按基地主数据聚合（秦州/清水县/武山/张家川县），合计 = 净利润 313.16 万元；③ 销售渠道占比、Top10 客户、订单总数改接 `SalesStore`（渠道含认养管理订单实收，订单数口径为销售管理，含 H5 镜像，不与商城重复计数）；④ 认养订单数/金额改取 `AdoptionStore.stats()`（订单口径），`snzg_adoptions` 仅作 H5 展示；⑤ 近 12 月趋势保持 753.09 万与年度营收一致。P2 项（应收/库存/坪效联动、近 5 年归档、抖动与更新时间）仍按下文待办。

> **认养金额口径修复（2026-11-10）**：此前「认养」在三处各有一套数值且互相矛盾——经营分析驾驶舱「认养金额」取 `AdoptionStore` 订单实收（4.9 万）、收入构成「认养收入」取财务口径（291.58 万）、认养管理页「认养收入」取台账合同额。修复后确立唯一口径：
> - **经营口径（对外展示）**：`BizStore.adoption.amount` = 收入构成中的「认养收入」= 291.58 万元。`setAdoption()` 写认养时回写收入构成，`setRevenueMix()` 改认养收入时反向同步 `adoption.amount`，两处恒等。
> - **管理台账口径（对内）**：认养管理页统计卡原「认养收入」改标为「合同额（台账）」，仅表示后台已录订单的合同金额，与经营口径分属两套定义，不参与大屏计算。
> - **驾驶舱渠道饼图**：改为与收入构成同源的营收口径（认养收入 38.7% / 批发 34.1% / 零售 14.2% / 观光 8.7% / 其他 4.3%），不再混用销售订单渠道金额。
> - **企业管理驾驶舱**：`EnterpriseStore.outcomes()` 的 `adoptionRevenue` / `adoptionOrders` 改由 `BizStore.adoption()` 派生，原 918 万元 / 3260 单作废；`EnterpriseStore` 版本升到 2，旧快照自动迁移。
> - **营收报表**：分类收入曲线与金额改由 `BizStore.revenueTrendByName()` / `revenueMix()` 按月分摊，认养全年累计 = 291.58 万元，与其他页一致。
> - 附带修复：驾驶舱 `renderDonut()` 把 `sumId` 当 id 二次查询，导致「合计 / 成本合计」文案长期停留在旧值（2656 / 1624），已修正为直接写 DOM。

## 一、结论摘要

1. 驾驶舱当前只有三条真实取数链路：
   - `BizStore`（`applefarm_biz_v1`）：收入构成、营收趋势、成本结构、基地利润、应收、经营指标、渠道、客户排行、认养汇总、近 5 年序列，**大部分为静态默认值**；
   - `MallStore`（`h5_orders` / `mall_member_profiles` 等）：只用于覆盖客单价、复购率，并向来源注释追加 GMV、订单数、会员数、券核销率；
   - 直读 `localStorage`：`snzg_adoptions`（认养订单 KPI）与 `applefarm_adoption_v1`（续费率）。

2. 共核查 18 项指标/图表：**5 项已动态打通**（客单价、复购率、认养订单、收入构成、续费率），**12 项后台有源但驾驶舱未接入或口径不一致**，**1 项无源**（近 5 年营收/净利）。另有 3 个二级指标（库存周转、坪效产值、人均产值）在后台无对应字段。

3. 后台已具备但驾驶舱未使用的真实数据层：
   - `SalesStore`：销售订单、客户成交/回款/应收、渠道维度、客户排行、年度目标 960 万元；
   - `AdoptionStore`：认养订单、金额、续费率；
   - `report_profit.html`：按地块汇总的营收、成本、利润；
   - `snzg_cost_structure`：成本科目占比配置。

4. H5 端只有 C 端交易原始数据（`h5_orders`、`snzg_adoptions`、`applefarm_adoption_v1` 认养订单、会员、优惠券、社区），**没有营收、成本、利润、应收、渠道、客户排行等经营数据**；移动端只有认养只读数据与农事/采收/物料/设备数据，**对经营分析驾驶舱无直接取数贡献**。

5. 驾驶舱内部存在明显口径冲突：
   - 顶部净利率 16.1%（428 / 2,656）与关键指标“净利率 18.5%”同屏不一致；
   - 关键指标“毛利率 42.0%”，按营收 2,656 万、成本 1,624 万计算实际为 38.9%；
   - 近 12 月营收趋势合计 3,918 万元，年度营收却为 2,656 万元；
   - 5 个基地利润合计 408.4 万元，净利润为 428 万元；
   - 驾驶舱标注“2025 财年”，后台销售、认养、采收种子数据均为 2026 年。

## 三、按端汇总

| 端 | 可提供的源数据 | 不能提供 / 缺失的数据 | 结论 |
|----|----------------|----------------------|------|
| 后台管理系统 | `BizStore` 经营分析全量字段；`MallStore` 订单/会员/券；`AdoptionStore` 认养订单/金额/续费率；`SalesStore` 销售订单、客户回款、渠道、目标；`report_overview / report_revenue / report_cost / report_profit` 报表数据；`snzg_cost_structure` 成本科目 | 统一口径的年度营收、成本、净利润；可维护的营收目标；年度历史序列；库存周转、坪效、人均产值字段；与基地主数据一致的基地利润 | 后台是唯一能支撑经营分析的一端，但现状是“多套数据、互不连通”，驾驶舱主要读 BizStore 静态默认值 |

## 四、主要口径冲突

| 指标 | 驾驶舱 | 后台其他页面 / 数据层 | 影响 |
|------|--------|----------------------|------|
| 年度营收 | 2,656 万元 | 报表总览 753.10 万元；营收报表约 384.7 万元；企业信息年产值 2,512 万元；销售管理年度目标 960 万元 | 同一指标四种口径，无法对外自洽 |
| 年度成本 | 1,624 万元 | 报表总览 439.94 万元；成本报表按地块成本合计 | 成本口径与营收口径不匹配 |
| 净利润 / 利润率 | 428 万元 / 16.1% | 报表总览与利润报表 313.16 万元 / 41.6% | 驾驶舱净利润偏高、利润率偏低程度不同 |
| 净利率 | 顶部 16.1%，关键指标 18.5% | `biz-store.js` 仅存 18.5% 指标值，未与 `netProfit / totalRevenue` 联动 | 同屏两个值 |
| 毛利率 | 42.0% | 按 2,656 万营收、1,624 万成本计算为 38.9% | 指标值不可复算 |
| 近 12 月营收 | 合计 3,918 万元 | 年度营收 2,656 万元 | 月度序列与年度值矛盾 |
| 基地利润 | 5 个基地，合计 408.4 万元 | 利润报表 7 个地块、4 个基地名称；基地主数据 22 个基地 | 基地对不上、利润合计对不上 |
| 认养订单 | 3,260 单，或 `snzg_adoptions` 记录数 | 认养订单数据层种子 25 单 | 播种后 KPI 从 3,260 骤降为 25 |
| 财年 | 2025 财年 | 销售/认养/采收种子数据为 2026 年 | 驾驶舱时间口径落后一年 |
