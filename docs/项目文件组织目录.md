## 二、各目录职责说明

| 目录/文件 | 作用 | 谁需要关注 |
|---|---|---|
| `docs/` | 需求、规则、数据模型、建表脚本 | 业务方（验收依据）+ AI |
| `html/` | 前端原型，**原样保留，界面 1:1 复刻** | 前端（不改界面，只改数据层） |
| `server/` | 后端 API + 数据库脚本 + 文件存储 | 后端 |
| `docker/` | Docker 编排与镜像，一键部署 | 部署（你只需 `docker compose up -d`） |
| `README.md` | 项目启动说明书 | 你（业务方） |

## 三、关键设计说明

### 1. 前端 `html/` 原样保留，只做"最小侵入"

- 界面代码（HTML/CSS/布局）**一行不改**，保证 1:1 复刻验收。
- 只把页面里 `localStorage` / 内嵌 mock 数据的读写，替换为调用后端 `/api/*` 接口。
- 建议新增一个 `html/common/js/api.js` 统一封装请求（基址、鉴权头、错误提示）。

### 2. 后端 `server/` 保持"单体 + 简单"

- **一个 Node.js 服务**搞定，不拆微服务。
- 路由按模块分文件（`routes/base.js`、`routes/plot.js`…），一个模块一个文件，好读好改。
- `controllers/` 初期可省略，业务逻辑直接写在路由里，降低层级复杂度。

### 3. 数据库脚本集中管理（单一数据源）

- `schema.sql`（建表）、`seed.sql`（种子数据）**唯一存放在 `server/db/`**，Docker 启动与后端迁移都读这里。
- `docs/` 下**不重复存放 SQL 文件**，只放 `.md` 文档；表结构以《核心数据模型.md》为文档查阅依据。
- `server/db/migrate.js` 在服务启动时**自动按顺序执行** schema → seed，实现"Docker 启动即建库灌数"。

### 4. Docker 一键部署（最小镜像）

- 三个容器：`web`（前端 Nginx）、`api`（后端 Node）、`mysql`（数据库）。
- 数据持久化：MySQL 数据挂载到本地 volume，容器重启不丢数据。
- 上传文件 `server/uploads/` 挂载到本地，不随容器销毁。
- **最小推送**：镜像只含运行必需（`html/`、`server/`、`server/db/*.sql`、`package.json`），**不含** `docs/`、`.git/`、`node_modules/`、`server/uploads/`；用 `.dockerignore` 自动排除。

### 5. 分阶段实施顺序（对齐你的计划）

1. **全量建表** → 完善 `schema.sql`（地基表已就绪，逐步补全业务表）；
2. **生成 Seed** → 把原型 mock 数据整理进 `seed.sql`；
3. **打通后端** → `server/` 下写 Node 服务与各模块路由；
4. **连通前端** → `html/` 页面的数据读写切到 `/api/*`；
5. **Docker 部署** → `docker/` 一键起全栈。

## 四、命名与约定（回顾）

- 后端接口统一前缀 `/api`，如 `/api/plot/list`、`/api/plot/create`；
- 表名 `sf_` 前缀、字段小写+下划线、逻辑删除 `is_deleted`；
- 所有查询默认过滤 `is_deleted = 0`；
- 登录态用 JWT（token），前端存 localStorage/sessionStorage，请求头携带。
