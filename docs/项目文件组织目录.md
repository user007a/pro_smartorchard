## 三、关键设计说明

### 1. 前端 `html/` 原样保留，只做"最小侵入"

- 界面代码（HTML/CSS/布局）**一行不改**，保证 1:1 复刻验收。
- 只把页面里 `localStorage` / 内嵌 mock 数据的读写，替换为调用后端 `/api/*` 接口。
- 建议新增一个 `html/common/js/api.js` 统一封装请求（基址、鉴权头、错误提示）。

### 2. 后端 `server/` 保持"单体 + 简单"

- **一个 Node.js 服务**搞定，不拆微服务。
- 路由实际分三类：`auth.js`（三端登录）、`meta.js`（字典/菜单）、`crud.js`（通用 CRUD，
  资源白名单制）+ **17 个 `*-aggregate.js` 模块聚合路由**（一个模块一个文件，好读好改）。
- 不设 controllers 层，业务逻辑直接写在路由里，降低层级复杂度。

### 3. 数据库脚本集中管理（单一数据源）

- `schema.sql`（建表）、`seed.sql`（基础系统数据）**唯一存放在 `server/db/`**。
- `docs/` 下**不重复存放 SQL 文件**，只放 `.md` 文档；表结构以 `server/db/schema.sql` 为唯一权威。
- 建库灌数由 MySQL 容器首次初始化自动完成（脚本挂载到 `/docker-entrypoint-initdb.d`）；
  已有数据卷上重建时按 README 用 `docker exec` 手动导入。

### 4. Docker 一键部署（最小镜像）

- 三个容器：`web`（前端 Nginx）、`api`（后端 Node）、`mysql`（数据库）。
- 数据持久化：MySQL 数据挂载到本地 volume，容器重启不丢数据。
- 上传文件 `server/uploads/` 挂载到本地，不随容器销毁。
- **最小推送**：镜像只含运行必需（`html/`、`server/`、`server/db/*.sql`、`package.json`），**不含** `docs/`、`.git/`、`node_modules/`、`server/uploads/`；用 `.dockerignore` 自动排除。

### 5. 分阶段实施顺序（历史计划，已全部走完）

1. **全量建表** → `schema.sql` 143 张表；
2. **基础数据** → `seed.sql` 仅灌系统基础数据（账号/角色/菜单/字典/配置），**业务表严格为空**；
3. **打通后端** → 三端登录 + 通用 CRUD + 17 个模块聚合路由；
4. **连通前端** → 各模块 store/mapper 接 `/api/*`（策略 A：只换 store 出入口，界面零改动）；
5. **Docker 部署** → 三容器一键起全栈。

**实际部署形态**：

```bash
docker compose up -d
# → http://localhost:8080/portal.html
```

- 首次启动：MySQL 容器自动执行 `schema.sql` + `seed.sql`（init 脚本挂载到 `/docker-entrypoint-initdb.d`）
- 页面与接口同源：Nginx 托管 `html/` 并反代 `/api` → `api:3000`
- 数据持久化：`mysql-data` volume（MySQL）+ `api-uploads` volume（上传文件）
- 容器名：`so-web`（8080）/ `so-api`（3000）/ `so-mysql`（3306）

## 四、命名与约定（回顾）

- 后端接口统一前缀 `/api`，RESTful 风格：`GET/POST /api/:resource`、`GET/PUT/DELETE /api/:resource/:id`，
  模块聚合为 `GET/POST /api/{module}/aggregate`（**不是** `/api/plot/list` 这类动词风格）；
- 表名 `sf_` 前缀、字段小写+下划线、逻辑删除 `is_deleted`；
- 所有查询默认过滤 `is_deleted = 0`；
- 登录态用 JWT（token），前端存 localStorage（仅 token 等会话键允许落盘），请求头携带。
