# 智能预警驾驶舱修复实施计划

> 依据文档：`docs/智能预警驾驶舱数据源.md`
> 编制日期：2026-11-10
> 修复对象：`html/applefarm_dataanlye/da_alert.html` 及其数据源 `html/applefarm_backhand/js/shared/alert-data.js`
> 覆盖范围：后台管理系统、移动端数据链路、驾驶舱展示口径
> 不在本次范围：消费者 H5 新增预警模块、真实 GIS 多边形测绘、服务端完整业务中台（单列阶段四）

---

## 一、修复原则

1. **单一数据源**：驾驶舱、后台、移动端统一从 `window.AlertStore` 取数，页面内不再维护业务常量、`SRC_META`、`CAT_META` 或静态预警文案。
2. **结构化优先**：地块聚合使用 `base + plotCode`，停止用正则解析 `location`；无法匹配的记录进入“未匹配地块”桶，不静默丢弃。
3. **口径显式**：所有“今日 / 近 24h / 累计”指标在标题或副标题中写明时间窗；响应、处置、闭环三个时长分别定义。
4. **配置驱动**：SLA 时限、达标阈值、来源与分类字典统一由数据层和预警设置页提供，页面只负责渲染。
5. **空态可解释**：无样本、无今日数据、无匹配地块时展示明确的空态，不显示 `100%`、`--` 或历史数据冒充当日数据。
6. **分阶段可回滚**：每个阶段独立提交；localStorage 结构升级前先备份旧键，支持按阶段回滚。

## 三、公共能力（阶段零，所有修复的前置）

> 本阶段只改数据层与自检脚本，不改变驾驶舱视觉，先建立统一契约。

### 0.1 数据版本与迁移备份

- 在 `alert-data.js` 提升 `SCHEMA_VERSION`（当前结构为 v2，本次升级到 v3），存储结构升级时执行迁移。
- 迁移前复用现有 `BACKUP_KEY`（`applefarm_alert_state_v1_backup_v1`）备份；若备份键已存在，追加时间戳避免覆盖。
- 迁移失败时保留旧数据并给出控制台错误，不覆盖原键。
- 验收：旧数据升级后字段完整；删除新键可从备份恢复；迁移只执行一次。

### 0.2 新增/规范的预警字段

| 字段 | 用途 | 说明 |
| --- | --- | --- |
| `base` | 基地 | 统一使用地块主数据的基地名称 |
| `plotSlot` | 原始地块槽位 | 如 `A1`，保留展示兼容 |
| `plotCode` | 标准地块编码 | 与 `smartorchard_plot_master.code` 对齐，如 `D-001` |
| `acceptedAt` | 受理时间 | 平均响应、超时判断 |
| `closedAt` | 闭环时间 | 平均处置、平均闭环 |
| `respondDue` / `handleDue` | 响应/处置截止 | 超时率 |

- `plot` 字段继续保留为展示文本，避免影响现有后台列表。
- 验收：新字段在 `all()`、`topN()`、`stats()` 返回值中可见；旧数据迁移后字段齐全或明确为空。

### 0.3 数据层新增查询能力

在 `alert-data.js` 中新增并导出：

| API | 作用 | 关键规则 |
| --- | --- | --- |
| `windowAlerts(hours)` | 取近 N 小时创建的预警 | 以 `time` 为准，`hours=24` 即近 24h |
| `statsWindow(hours)` | 近 N 小时统计 | 复用现有 `stats()` 结构 |
| `topToday(n, statuses)` | 今日 TopN | 默认状态 `pending/processing/transferred`，按级别+时间排序 |
| `dailyTrend(days)` | 连续 N 天趋势 | 固定补齐日期，无数据补 0 |
| `sourceMeta()` / `categoryMeta()` | 字典与颜色 | 由 `SOURCES` / `CATEGORIES` 派生 |
| `slaMinutes(level, kind)` | SLA 字符串转分钟 | 支持“15 分钟”“2 小时”“无时限” |
| `resolvePlot(alert)` | 解析标准地块 | 优先 `plotCode`，其次基地+槽位别名，最后返回未匹配 |
| `aggregateByPlot(alerts)` | 地块聚合 | 返回已匹配与未匹配两组 |

- 验收：自检脚本对每个 API 至少 1 条断言；`windowAlerts(24)` 条数等于手工过滤结果。

### 0.4 SLA 与看板阈值配置

- 在 `readConfig()` 的默认配置中增加 `targets`（存储键 `snzg_alert_targets`，与现有 `sla` 配置并列）：
  - `avgRespond`：默认 30 分钟
  - `avgHandle`：默认 120 分钟
  - `avgClose`：默认 1440 分钟
  - `overdueRate`：默认 10%
- `slaMinutes()` 解析现有 `DEFAULT_SLA` 的四个级别（紧急/重要/提醒/通知）。
- `alert_settings.html` 增加“看板达标阈值”配置区，保存后写入 `config().targets`；扩展现有 `AlertStore.saveConfig()` 支持 `targets` 分支并校验、持久化。
- 验收：修改阈值后驾驶舱判定随刷新变化；非法值（负数、空）不可保存。

### 0.5 种子数据时间戳补齐

- 在 `DEFAULT_ALERTS` 的 `dynamicTimes()` 之后增加 `hydrateSeedTimes()`：
  - 所有记录补齐 `respondDue`、`handleDue`。
  - `processing/closed/transferred` 补齐 `acceptedAt`。
  - `closed/completed` 补齐 `closedAt`，且 `closedAt >= acceptedAt >= time`。
  - 偏移量按记录序号确定性生成，避免每次刷新数值跳动。
- 对已存在的旧 localStorage 数据，在迁移中按同样规则补齐；无法推导的标记为空。
- 无闭环样本时，平均处置、平均闭环显示“暂无样本”，不显示 `--` 或 `100%`。
- 验收：清空 localStorage 后首次打开，闭环预警均有 `closedAt`；SLA 卡不再出现“按时处理 100% / 平均处置 --”的矛盾组合。

### 0.6 自检脚本扩展

- 扩展 `html/applefarm_backhand/js/shared/_alert-store.check.js`，新增断言：
  - 种子 46 条，时间均在最近 30 天内且不晚于今天 23:59。
  - 每条种子有 `plotCode` 或明确的 `unmatched` 标记。
  - `topToday` 不含昨日与已闭环记录。
  - `windowAlerts(24)` 为全量真子集。
  - `sourceMeta()` 长度为 6，`categoryMeta()` 长度为 10。
  - `slaMinutes('urgent','respond') === 15`，`slaMinutes('notice','handle')` 为“无时限”时返回 `null`。
  - `dailyTrend(7)` 长度恒为 7 且日期连续。
  - `slaMetrics()` 的 `avgResp/avgHandle/avgClose` 三项分别有定义且不完全相等。
- 验收：脚本全部通过，失败时输出可定位的断言名。

## 四、P0 修复清单

### P0-01 地图地块主数据接入与编码统一

**对应问题**：文档问题 1；影响数据项 7–13。

**方案**

1. **统一基地字典**
   - 以 `enterprise_plot.html` 的 `smartorchard_plot_master` 为地块主数据源。
   - 主数据键不存在时，地图显示“地块主数据未初始化”，不使用硬编码名称兜底；可引导先打开地块管理完成初始化。
   - 在 `alert-data.js` 建立基地别名表：
     - `天水秦州基地` → `天水秦州区基地`
     - `天水甘谷基地` → `天水甘谷县基地`
     - 麦积区名称保持原样。
   - `青岛莱西基地`、`龙口南山基地`、`招远基地` 若不在主数据中，统一标记为“外部基地”，不得伪造品种/负责人。
2. **建立地块解析器**
   - 新增 `resolvePlot(alert)`：
     - 有 `plotCode` 且主数据存在 → 直接返回主数据记录。
     - 否则用 `base + plotSlot` 查 `PLOT_ALIAS`（演示别名表）。
     - 仍无法匹配 → 返回 `{ matched:false, base, slot }`。
   - 别名表集中维护在 `alert-data.js`，禁止写在 `da_alert.html`。
3. **改造驾驶舱地图**
   - 保留现有 12 块 SVG 示意几何，作为“重点地块示意（非真实地理边界）”。
   - 新增 `SLOT_PLOT_MAP`，把 `A1–D1` 12 个槽位绑定到主数据真实地块编码。
   - 删除 `PLOTS[].name/variety/manager` 硬编码，改为：
     - 名称、品种、负责人：从 `resolvePlot()` 读取。
     - 预警数量、级别构成：从 `aggregateByPlot()` 读取。
   - 未匹配的基地/地块放入地图下方“未匹配主数据”列表，显示基地、槽位、预警数量。
   - 已匹配但不在 12 个槽位内的地块放入“其他地块”摘要列表，保证 23 块主数据中的预警不被漏展示。
4. **改造聚合逻辑**
   - `renderMap()` 不再用 `/地块\s*([A-D]\d)/` 解析 `location`。
   - 统一按 `base + plotCode` 聚合；未匹配记录单独计数。
   - 地图详情中的“处置建议”改为按级别/分类的固定规则文案，并标注“建议规则”，不冒充业务数据。
5. **移动端与人工上报**
   - `mb_patrol.html` 上报人工预警时增加地块选择（来自主数据或当前巡园点），写入 `base/plotCode/plotSlot`。
   - `mb_alert.html` 保持 `location` 展示；按地块筛选作为后续增强，不纳入本次必做范围。

**改动文件**

- `html/applefarm_backhand/js/shared/alert-data.js`
- `html/applefarm_dataanlye/da_alert.html`
- `html/applefarm_mobile/mb_patrol.html`
- `html/applefarm_backhand/enterprise_plot.html`（仅确认主数据写入与事件，不新增依赖）

**验收**

- 在后台修改某地块负责人/品种，刷新驾驶舱后地图详情同步更新。
- 驾驶舱源码中不再出现固定的“张建国/李红/王强”等负责人名和固定品种。
- 地图预警总数 = 已匹配数量 + 未匹配数量；与 `AlertStore.all()` 手工统计一致。
- 未匹配记录可见，不被静默丢弃。

**待确认**

- 12 块示意地图是否继续保留，或改为 23 块真实地块卡片/重绘图。默认按“保留 12 块示意 + 真实数据绑定”实施。

## 五、P1 修复清单

### P1-01 “今日预警 Top10”口径修正

**对应问题**：文档问题 2；影响数据项 15。

**方案**

- 新增 `AlertStore.topToday(10)`：
  - 过滤 `time` 日期等于今天。
  - 默认状态为 `pending/processing/transferred`；不含 `closed/ignored/voided`。
  - 按级别（紧急→重要→提醒→通知）+ 时间倒序。
- `da_alert.html` 的 `renderTop()` 改用 `topToday(10)`。
- 标题保留“今日预警 Top10”；无数据时显示“今日暂无预警”，不回退历史数据。

**验收**

- 昨日及更早的预警不出现。
- 已闭环/已忽略的预警不出现。
- 当日无数据时显示空态，不展示旧数据。

### P1-02 近 24h 指标口径修正

**对应问题**：文档问题 3；影响数据项 5、6、25–28、38–41。

**方案**

- 指标标题增加“近 24h”标识，并在副标题显示样本量，如“样本 12 条”。
- 后台 `alert_overview.html` 的累计指标保持全量，但标题改为“累计闭环率/累计平均响应”，避免同名不同义。

**验收**

- 手工按 `time >= now-24h` 过滤，条数与页面一致。
- 24h 内无样本时显示“暂无样本”，不显示 100%。
- 后台累计指标与驾驶舱近 24h 指标名称可区分。

### P1-04 重点预警提示动态化

**对应问题**：文档问题 5；影响数据项 43、44。

**方案**

- 新增 `buildKeyAlerts(3)`，候选优先级：
  1. 紧急且待确认。
  2. 已超过 `respondDue` 且未闭环。
  3. 已转工单超过 2 小时未闭环。
  4. 紧急处理中。
- 文案模板：
  - `{title}｜{base} {plotName}｜已持续 {duration}｜{statusText}`
- 状态标签使用 `statusText` 与剩余/超时时长，不再写死“已升级/28min/待回应”。
- 无候选时显示“暂无重点预警”。
- 删除 `da_alert.html` 中固定三条研判文案及固定基地/地块名。

**验收**

- 三条内容随 `AlertStore` 数据变化。
- 源码中不再出现“麦积基地 2 号北”“清水基地”等固定文案。
- 无数据时显示空态。

### P1-05 设备/资质预警自动写入

**对应问题**：文档问题 10；影响数据项 29、34。

**方案**

- **设备侧**
  - 在 `device-store.js` 增加 `syncDeviceAlerts()`：
    - `status=offline` → 重要预警；离线超过 24 小时 → 紧急预警。
    - `status=maintain` → 提醒预警。
    - 存在 `pending/processing` 的“故障维修”维保单 → 提醒或重要预警。
    - `assetStatus=repair` → 提醒预警。
    - 去重键：`device:{deviceId}:{status}`，避免重复生成。
    - 位置使用设备台账的 `base + plotId + location`，并在 `plotId` 可匹配主数据时写入 `plotCode`。
    - 设备恢复 `status=online` 后，从同步清单中移除该设备；复用 `AlertStore.syncSource()` 既有的“清单消失即自动闭环”机制，不另写关闭逻辑。
  - 扩展 `syncSource()` 的字段透传，使 `plotCode`、`plotSlot`、`respondDue`、`handleDue` 可随同步项写入。
  - 在 `device_info.html`、`device_maintain.html` 的状态变更后调用 `syncDeviceAlerts()`；页面需在 `device-store.js` 之前引入 `alert-data.js`，或通过 `window.AlertStore` 守卫懒加载。
- **资质侧**
  - 在 `cert-store.js` 增加 `syncCertAlerts()`，复用现有 `expiringList()` 清单：
    - `expired` 或 ≤30 天 → 紧急预警；≤90 天 → 重要预警。
    - 去重键：`cert:{certId}:expire`。
    - 续期后有效期 >90 天，该证书从清单消失，由 `syncSource()` 自动闭环原预警。
  - 在 `cert_manage.html`、`cert_issue.html` 保存/续期后调用；引入 `alert-data.js`。
- 所有同步操作写入 `history`，包含“自动生成/自动闭环”来源说明。

**验收**

- 将设备状态改为离线 → 驾驶舱设备来源 +1，Top10/重点提示可见。
- 恢复在线 → 对应预警自动闭环，不再重复生成。
- 证书临期 → 资质来源 +1；续期 → 自动闭环。
- 页面反复刷新不产生重复预警。

### P1-06 源数据持久化（生产化，单独立项）

**对应问题**：文档问题 12；影响全部数据项。

**方案**

## 六、P2 修复清单

### P2-01 SLA 时限与达标阈值配置化

**对应问题**：文档问题 7；影响数据项 22、42。

**方案**

- 驾驶舱升级链路不再逐节点写死 `15min/30min/2h/4h`，改为一条“响应时限（按级别）”图例，读取 `slaMinutes()`：
  - 紧急 15 分钟、重要 30 分钟、提醒 2 小时、通知 4 小时（以配置为准）。
- 处置时效表的达标判定读取 `config().targets`：
  - 平均响应 ≤ `avgRespond`
  - 平均处置 ≤ `avgHandle`
  - 平均闭环 ≤ `avgClose`
  - 超时率 ≤ `overdueRate`
- `alert_settings.html` 增加阈值编辑与校验。

**验收**

- 修改 SLA 或阈值后，刷新驾驶舱图例与判定颜色同步变化。
- 配置非法值不可保存；恢复默认值有入口。

### P2-02 响应/处置/闭环三项指标拆分

**对应问题**：文档问题 8；影响数据项 39、40。

**方案**

- 明确口径：
  - 平均响应 = `acceptedAt - time`
  - 平均处置 = `closedAt - acceptedAt`
  - 平均闭环 = `closedAt - time`
- `slaMetrics()` 同时返回三项；处置时效表分别展示，不再复用同一字段换算。
- 任一时段无样本时显示“暂无样本”。

**验收**

- 构造一条 `time=09:00、acceptedAt=09:10、closedAt=11:00` 的预警，三项分别为 10 分钟、110 分钟、120 分钟。
- 表格三列数值不再相同（除极端数据）。

### P2-03 近 7 日趋势连续化

**对应问题**：文档问题 9；影响数据项 36、37。

**方案**

- `dailyTrend(7)` 固定生成今天往前 7 个自然日，按日初始化 0，再填充各级别数量。
- 横轴日期格式 `MM-DD`，保证 7 个刻度连续。
- 全零时仍展示 0 线，并在图例旁标注“近 7 日无预警”。

**验收**

- 横轴始终 7 个连续日期，无跳日。
- 无数据日期显示 0，不消失。

### P2-04 后台首页预警数据同步

**对应问题**：文档问题 11；影响参考源一致性。

**方案**

- `home.html` 的“活跃预警”KPI 与“实时预警”列表改为读取：
  - `AlertStore.stats().byStatus.pending + processing + transferred`
  - `AlertStore.topN(5)` 或 `topToday(5)`
- 订阅 `AlertStore.subscribe()` 与 `storage` 事件，保持与驾驶舱同步。
- 空态显示“暂无预警”。

**验收**

- 首页活跃预警数与驾驶舱升级链路“待确认+处置中+转工单”一致。
- 新增/闭环预警后首页列表自动更新。

### P2-05 演示数据标识

**对应问题**：文档问题 12 的演示环境说明。

**方案**

- 在驾驶舱顶部右侧或底部状态栏增加“演示数据 · 本机 AlertStore”标识。
- 不改变布局与指标；仅在无后端 API 模式下显示。

**验收**

- 本机演示模式下标识可见；接入 API 后自动隐藏。

## 八、关键实现示意

### 8.1 时间窗与今日 TopN

```js
function windowAlerts(hours) {
  var since = Date.now() - hours * 3600 * 1000;
  return all().filter(function (a) {
    var t = new Date(String(a.time).replace(/-/g, '/')).getTime();
    return t >= since;
  });
}

function topToday(n, statuses) {
  var today = todayStr();
  var allow = statuses || ['pending', 'processing', 'transferred'];
  return all()
    .filter(function (a) {
      return String(a.time).slice(0, 10) === today && allow.indexOf(a.status) >= 0;
    })
    .sort(function (a, b) {
      return (levelWeight(b.level) - levelWeight(a.level)) ||
        String(b.time).localeCompare(String(a.time));
    })
    .slice(0, n);
}
```

function minutesBetween(from, to) {
  return (new Date(to.replace(/-/g, '/')) - new Date(from.replace(/-/g, '/'))) / 60000;

### 8.3 地块解析

```js
function resolvePlot(alert) {
  var master = plotMaster();
  var byCode = master.filter(function (p) { return p.code === alert.plotCode; })[0];
  if (byCode) return { matched: true, plot: byCode };

  var base = normalizeBase(alert.base);
  var slot = alert.plotSlot || parseSlot(alert.location);
  var code = PLOT_ALIAS[base + '|' + slot];
  var hit = master.filter(function (p) { return p.code === code; })[0];
  return hit
    ? { matched: true, plot: hit }
    : { matched: false, base: base, slot: slot };
}
```

### 8.4 SLA 解析

```js
function slaMinutes(level, kind) {
  var raw = config().sla[level][kind]; // 如 '15 分钟' / '2 小时' / '无时限'
  if (!raw || raw.indexOf('无') >= 0) return null;
  var n = parseFloat(raw);
  return raw.indexOf('小时') >= 0 ? n * 60 : n;
}
```

## 十、风险与回滚

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 基地字典不统一（5 基地 vs 8 基地） | 地图/预警无法完全匹配 | 阶段一先确认主数据口径；未匹配项显式展示，不伪造数据 |
| 12 块 SVG 非真实地理边界 | 无法按真实地块渲染 | 明确标注“重点地块示意”；真实 GIS 作为独立设计任务 |
| SLA 语义按级别配置、链路按节点展示 | 文案可能误读 | 改为“响应时限（按级别）”图例；节点只保留流程含义 |
| 自动生成设备/证书预警过多 | 预警风暴 | 去重键 + 阈值 + 恢复自动闭环 + 静默时段 |
| localStorage 迁移失败 | 演示数据丢失 | 迁移前备份、失败保留旧键、自检脚本覆盖 |
| 今日/24h 过滤后大屏为空 | 演示效果变差 | 空态文案 + 种子数据动态时间 + 样本量说明 |
| H5 仍无预警数据 | 消费者端看不到预警 | 明确为业务边界；如需新增，单独立项 |

**回滚方式**

- 按阶段回滚 Git 提交。
- localStorage 升级前自动备份，回滚时恢复备份键。
- 新配置字段缺省时回退到默认值，不阻断旧页面。
