# 后台管理菜单改造清单

> 目标：让后台管理系统的数据能力完整支撑 8 个数据驾驶舱（大屏端）的指标需求。
> 基准：`html/applefarm_dataanlye/`（8 个驾驶舱）与 `html/applefarm_backhand/index.html`（改造前 15 个一级菜单 / 63 个叶子节点）。
> 生成日期：2026-10-21
>
> **实施状态：已全部完成并通过验收**（2026-10-21）。验收结果：静态校验 210 项全通过、16 个后台页与 3 个大屏页渲染零报错、后台→大屏联动 3/3 生效。
> 需求说明书对应章节：[6.6 V4.1 后台数据支撑改造变更记录](file:///d:/dev/pro_smartorchard/docs/需求说明书.md)。

## 一、背景与结论

| 项目 | 结论 |
|---|---|
| 后台菜单结构 | 硬编码于 `applefarm_backhand/index.html` L47-L378，无 key/id/权限标识，以 `href` 为唯一标识 |
| 覆盖率 | 后台可支撑大屏约 45% 的指标 |
| 缺口构成 | 约 20 项后台完全无数据源（大屏只能 mock）；约 14 项有部分字段但需补齐 |
| 改造策略 | 新起 2 个一级菜单（销售管理、数据运营），改 1 个现有一级菜单（统计分析 → 经营分析），其余缺口按业务域归入现有菜单 |
| 孤儿页面 | `user_settings.html`、`vr_panorama.html` 在后台完全无入口 |

## 六、阻塞项（须优先处理）

### 1. performanceData 未定义（现存 bug）

`performance_dashboard.html` L596-L603 引用的 `performanceData` 在整个 `applefarm_backhand` 目录内无任何定义，被 try/catch 静默吞异常。结果：绩效结果无法落库，大屏「人员效率」指标拿不到任何数据。

> 这是 bug 修复，不是功能新增，建议最先处理。

### 2. 数据层约定未打通

大屏目前只能通过 localStorage 读数，`js/shared/alert-data.js` 的 `AlertStore` 是唯一已打通的范例（后台 alert_device / alert_farming / alert_overview 与大屏 da_alert 共用）。

本清单中所有新增字段若不同步写入共享存储层，大屏仍会是 mock。建议沿用 `js/shared/` 模式，为数据运营、溯源统计、经营分析各建一个 store。

| 新增 Store | 供数大屏 |
|---|---|
| `js/shared/data-store.js` | da_results（数据归集、模型监控） |
| `js/shared/trace-stat-store.js` | da_trace（扫码统计、上链成功率） |
| `js/shared/biz-store.js` | da_business（收入构成、成本结构、周转指标） |
