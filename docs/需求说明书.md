## 第一章 产品概述

### 1.1 产品背景

我国是全球最大的苹果生产与消费国之一，产业正经历从"经验种植"向"数据种植"的全面转型。当前，种植企业普遍面临以下挑战：

- **生产管理粗放**：农事记录依靠纸质本、Excel 数据散落多端，难以形成闭环分析；
- **信息时延明显**：病虫害、气象灾害、设备故障往往在事后才被发现，损失已成既定事实；
- **农资浪费严重**：盲目施肥用药，缺乏"地块-作物-物候"精准匹配的施用指引；
- **品质信任缺失**：消费者无法验证"绿色""有机"等认证真伪，产销信任成本高；
- **价值链条短**：单纯卖果溢价空间有限，缺乏参与式、体验式消费场景；
- **决策缺少抓手**：经验决策占比高，缺乏融合历史数据、物联网实时数据、AI 模型的科学辅助。

V4.0 版本以"数据驱动 · 模型研判 · 精准作业 · 提质增效"为核心理念，对门户、生产驾驶舱、移动作业端、消费者端进行一体化升级，构建"从土地到餐桌"的全链路数字化能力。

### 1.2 产品定位

智慧果园管理系统是面向**苹果种植全产业链**的产业互联网平台，定位于"种植企业的数字化中台 + 消费者的品质信任入口 + 政府的产业监管抓手"三位一体：

| 维度        | 定位                                       |
| --------- | ---------------------------------------- |
| 对企业       | 一体化数字管理平台，打通"基地-农资-设备-采收-销售-认养"全流程 |
| 对消费者      | 可验证的品质溯源入口 + 沉浸式认养体验入口               |
| 对政府/合作组织 | 产业大数据汇聚与分析中心，支撑区域品牌建设                |
| 对开发者/集成商 | 开放API 网关，支持与ERP、WMS、气象、电商等多系统对接    |

### 1.3 核心价值主张

| 价值维度      | 一句话概括                         | 关键支撑                            |
| --------- | ---------------------------- | ------------------------------- |
| **降本增效**  | 把每一笔农资、每一次作业、每一台设备的投入都变成可度量的资产 | 农事计划、农资全生命周期管理、绩效看板          |

## 第三章 用户故事与需求框架

### 3.1 Epic 级用户故事

#### Epic 1：统一门户与身份切换

> **US-001** 作为企业 IT 负责人，我希望公司所有数字化入口都收敛到一个统一门户，让员工根据角色一步进入对应的工作端，减少入口混乱与账号分散。

> **US-002** 作为基地管理员，我想用一个账号同时登录 PC 管理后台与移动工作端，不必重复申请账号，两端共享权限与待办。

> **US-003** 作为参观访客，我希望通过大屏和 VR 全景快速了解企业规模、生产指标、地理分布，不需要复杂登录即可看见"对外名片"。

#### Epic 2：生产管理数字化

> **US-004** 作为基地管理员，我想要在 PC 端创建年度农事计划（覆盖整地、修剪、施肥、灌溉、打药、采收等环节），按地块分配到人并下发到移动端。

> **US-005** 作为植保员，我在田间发现疑似腐烂病叶片后，可以使用手机拍照上传，AI 在 3 秒内给出病害类型与建议用药方案，我再决定是否一键下发施药任务。

> **US-006** 作为普通农工，早晨到地里前，我会在手机上看到当天分配给我的所有任务（带地块、物候期建议、要求完成时间），到田间后可以一键打卡并补充记录。

> **US-007** 作为采收员，接到采收任务后，我需要在现场逐箱称重、记录采收人，PC 端会自动形成采收批次与采收日报。

#### Epic 3：IoT 感知与预警

> **US-008** 作为基地管理员，当某地块土壤湿度低于阈值时，我希望立即收到预警，并能在手机上查看是哪个地块、哪个传感器、最近 24 小时曲线，并可下发灌溉指令。

> **US-009** 作为植保员，我想看到过去 7 天气象趋势，结合当前物候期，得到未来 3 天的病虫害风险指数，提前安排预防施药。

> **US-010** 作为基地管理员，我希望设置无人机定时巡检，飞行结束后自动回传轨迹、拍照点与异常检测结果，并保存到我的"巡检档案"。

#### Epic 4：品质追溯与区块链

> **US-011** 作为企业品控，我希望每一批次的苹果从育苗、农事作业、农资投入到采收、包装的全流程数据上链存证，消费者扫码即可查看无法篡改的生产履历。

> **US-012** 作为消费者，收到苹果后我扫箱码可以查看：本批次产地、采收日期、检测报告、农事记录、认证证书，并可以一键收藏到"我的溯源档案"。

#### Epic 5：云认养与消费互动

> **US-013** 作为认养用户，我在认养一棵苹果树后希望能随时查看这棵树的实时照片、农事记录、采收预测；苹果成熟时收到通知，可申请发货或到园采摘。

> **US-014** 作为基地管理员，我可以批量管理认养果树，统一推送生长动态、采收通知、节日活动，并将订单汇总到销售订单。

## 第五章 产品设计方案

### 5.1 设计原则

1. **一致性**：跨端统一设计语言（间距/字号/颜色），保证体验连贯；
2. **实用性**：以"任务"为导向设计页面，避免"功能堆叠"；
3. **高效性**：关键数据"屏内可读"，减少跳页与认知负担；
4. **可扩展性**：设计令牌（Design Token）化，便于主题切换与多端共享；
5. **情感化**：以果园绿 + 苹果橙为主色，体现"自然、丰收、可信"。

## 第七章 权限体系设计

### 7.1 总体思路

采用 **RBAC（角色基础）+ ABAC（属性条件）** 双轨：

- **角色决定"能做什么"**：菜单、按钮、数据范围；
- **属性决定"何时/对谁可做"**：基地归属、时间窗、物候期、数量等条件。

| 按钮级     | 操作能力     | "删除"、"导出"、"审核"            |
| 数据级     | 数据范围     | 用户 A 仅能看到"基地 1"的数据        |
| 字段级     | 脱敏        | 客户手机号"中间四位*"展示             |

### 7.4 多基地隔离

- 超级管理员可切换至任意基地；
- 基地管理员仅看本基地；
- 农工仅看任务范围内的地块。

### 7.5 审计与回溯

- 登录、操作、关键 CRUD 全部留痕；
- 关键操作触发审计日志看板，可按人/时间/对象检索；
- 审计数据不可篡改（同步上链或独立存储）。

### 9.2 安全要求

| 类目      | 要求                                                          |
| ------- | ----------------------------------------------------------- |
| **传输**   | 全站 HTTPS（TLS 1.2+），HSTS 强制                              |
| **认证**   | 双因子（账号+短信/人脸）、SSO、单点登录                                  |
| **授权**   | RBAC + ABAC，最小权限原则                                        |
| **加密**   | 国密 SM4/SM2 选项 + AES-256；密码 bcrypt 存储                       |
| **防注入**  | SQL/NoSQL 注入、命令注入、模板注入均拦截                                |
| **防爬**   | 接口限流、图形验证码、设备指纹                                           |
| **防泄漏**  | 数据库脱敏、字段级加密、日志脱敏                                          |
| **审计**   | 关键操作 100% 留痕，留存 ≥ 180 天                                   |
| **数据销毁** | 用户注销 30 天后匿名化、可选 90 天后物理删除                              |

### 9.3 隐私合规

- 收集最小化：仅采集业务所需的最小字段；

- 文件存储多副本 + 异地冷备；

### 11.3 接口签名与防重

```
StringToSign = HTTPMethod + "\n" + RequestURI + "\n" + QueryString + "\n" + BodyHash
Signature    = HMAC-SHA256(StringToSign, Secret) + "." + Timestamp + "." + Nonce
```

- 客户端生成签名；
- 服务端校验时间戳偏移 ≤ 5 分钟、Nonce 一次有效。

## 第十四章 产品亮点

### 14.1 四大前端亮点

#### 🌟 14.1.1 统一门户 · 4 入口聚合

- 单一入口可进入 PC 后台、移动作业端、数据大屏、消费者端；
- 4 张 3D 透视卡片，错位悬浮 + 流光动效；
- 标语"数据驱动 · 模型研判 · 精准作业 · 提质增效"强化品牌记忆。

#### 🌟 14.2.2 数据驾驶舱矩阵 4×2

- 8 大主题驾驶舱（管理 / 生产 / 经营 / 追溯 / 预警 / 物候 / 设备 / 成果）；
- 单屏 1920×1080 设计、自动等比缩放；
- 30 秒自动刷新、关键指标高亮、动效克制专业。

#### 🌟 14.2.3 移动端"现场工具箱"

- 任务、识病虫、领农资、查故障、画地块、问专家、采收预约、AI 助手等十余个工具；
- 离线可用 + GPS 自动注入 + 拍照自动打码；
- 与 PC 端权限共享、待办共享。

#### 🌟 14.2.4 H5 端"溯源 + 认养"双轮

- 数字履历（H5 长页叙事）+ 扫码溯源（详情页深链）；
- 我的认养：实时生长、采收预约、电子证书；
- 移动商城支持购物车、订单、收藏、社区四件套。

### 14.2 业务亮点

#### ⚡ 14.2.1 AI 模型六件套
- 生长、物候、气象、病虫害、产量、价格全方位辅助决策。

- 信息 → 入库 → 出库 → 领用 → 使用 → 退货 → 供应商对账 → 报表归集。

#### ⚡ 14.2.4 设备 IoT + 无人机
- 设备三件套 + 无人机巡检任务 + 实时数据回传。

#### ⚡ 14.2.5 任务与绩效

## 第十六章 数据表结构设计

### 16.1 设计原则

- **范式与反范式并用**：事务型表符合 3NF，报表型表反范式宽表化；
- **统一命名规范**：snake_case、复数表名；
- **审计字段统一**：created_at / updated_at / created_by / updated_by；
- **逻辑删除**：is_deleted + deleted_at 软删，关键业务保留硬删；
- **分区与归档**：时序大表按月分区，保留 36 个月在线数据。

## 第二十三章 异常处理流程

### 23.1 系统异常

| 场景     | 流程                                                  |
| ------ | --------------------------------------------------- |
| 接口超时   | 客户端重试 3 次 + 指数退避 → 失败则展示重试按钮                     |
| 服务降级   | 返回降级数据 + 顶部 Toast + 静默上报                           |
| 服务不可用  | 静态页 + 应急 QR + 服务热线                                 |
| 鉴权失败   | 跳登录 + 保留来源，回跳登录前页面                                 |
| 数据冲突   | 移动端冲突合并：服务器为权威，本地记录标记冲突→用户选择                  |

### 23.2 业务异常

| 场景     | 流程                                                |
| ------ | ------------------------------------------------- |
| 农资库存不足 | 触发采购预警，转采购流程                                    |
| 任务逾期   | 自动改派、通知责任人、纳入绩效                                 |
| 设备严重故障 | 触发工单、推维修主管、暂定关联任务                              |
| 病虫害爆发  | 启动应急 SOP、AI 给出施药方案、向农技员派单                    |
| 食品安全投诉 | H5 一键投诉 → 客服 → 自动拉取批次履历 → 责任判定                |
| 模型异常   | 切规则引擎兜底 + 上报样本                                    |

### 23.3 外部异常

| 场景       | 流程                       |
| -------- | ------------------------ |
| 气象服务中断   | 切到备用气象供应商                |

### 23.4 安全异常

## 第二十四章 数据驱动闭环

### 24.1 五层闭环

1. **采集**：人工 + IoT + 视频 + 第三方；
2. **存储**：原始库 + 主题库 + 应用库；
3. **分析**：BI 报表 + AI 模型；
4. **决策**：推荐、预警、调度；
5. **执行**：工人任务 + 自动设备指令；
6. **回流**：执行结果写到知识库，闭环回 AI 训练数据。

### 24.2 关键闭环场景

#### 24.2.1 病虫害闭环

采集 → 模型 → 推送 → 工单 → 执行 → 验收 → 数据回流

#### 24.2.2 灌溉闭环

土壤湿度→阈值→预警→派单→执行→回写历史

#### 24.2.3 价格闭环

批发市场行情 + 库存 + AI 模型 → 建议价 → 销售调整 → 复盘

#### 24.2.4 认养闭环

认养下单 → 自动同步农事 → 推送生长 → 采收预约 → 配送 → 评价 → 复购

### 24.3 数据治理

- 元数据管理：字段血缘、字段定义统一维护；
- 数据质量：5 项校验（唯一性、完整性、范围、一致性、时效）；
- 数据安全：分级分类、最小授权、动态脱敏；
- 数据资产化：将"地块档案""客户档案""批次档案"作为核心资产。

### 24.4 数据价值变现

- 政府报告：产业洞察、数据上报；
- 金融服务：基于产量/品质数据为农户授信（间接）；
- 保险数据：气象/产量数据支撑农业保险；
- 品牌赋能：数据资产沉淀为品牌叙事素材。

## 第二十九章 无障碍设计

### 29.1 原则与目标

- **WCAG 2.2 AA** 合规；
- **人人可用**：老人、农业工作者、视障/听障/色弱用户均可用；
- **可感知**：信息可被多种感官接收；
- **可操作**：键盘 + 触控 + 语音；
- **可理解**：界面一致、帮助可及；
- **健壮性**：兼容未来辅助技术。

### 29.2 视觉无障碍

- 文字对比度 ≥ 4.5:1（大字号 ≥ 3:1）；
- 不仅靠颜色传达信息，提供图标/文字；
- 焦点环清晰可见；
- 字号可放大 200% 不破版；
- 减少动效（`prefers-reduced-motion`）。

### 29.3 键盘可达

- 所有交互 Tab 可达；
- 焦点顺序合理；
- 弹窗聚焦陷阱；
- 快捷键：⌘+K 全局搜索、? 帮助、Esc 关闭。

### 29.4 屏幕阅读器

- 语义化 HTML：`header/main/nav/section/article/aside/footer`；
- ARIA 属性规范使用：`aria-label/aria-live/role`；
- 图表提供数据表格版本与 alt 摘要；
- 大屏为"屏幕阅读器友好"提供 alt 与摘要文本。

### 29.5 触控与语音

- 触控目标 ≥ 44×44pt；
- 关键操作支持语音输入（如"问专家"）；
- OCR + TTS 适配低文化用户。

### 29.6 田间强光环境

- 移动端高对比模式；
- 大字体选项；
- 简化动画、加快反馈。

### 29.7 验证

- 自动化：axe-core 接入 CI；
- 人工：键盘 + VoiceOver/NVDA 走查；
- 年度第三方无障碍审计。
