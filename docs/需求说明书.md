## 第一章 产品概述

### 1.1 产品背景

我国是全球最大的苹果生产与消费国之一，产业正经历从"经验种植"向"数据种植"的全面转型。当前，种植企业普遍面临以下挑战：

- **生产管理粗放**：农事记录依靠纸质本、Excel 数据散落多端，难以形成闭环分析；
- **信息时延明显**：病虫害、气象灾害、设备故障往往在事后才被发现，损失已成既定事实；
- **农资浪费严重**：盲目施肥用药，缺乏"地块-作物-物候"精准匹配的施用指引；
- **品质信任缺失**：消费者无法验证"绿色""有机"等认证真伪，产销信任成本高；
- **价值链条短**：单纯卖果溢价空间有限，缺乏参与式、体验式消费场景；
- **决策缺少抓手**：经验决策占比高，缺乏融合历史数据、物联网实时数据、AI 模型的科学辅助。

V4.0 版本以"数据驱动 · 模型研判 · 精准作业 · 提质增效"为核心理念，对门户、生产驾驶舱、移动作业端、消费者端进行一体化升级，构建"从土地到餐桌"的全链路数字化能力。

### 1.2 产品定位

智慧果园管理系统是面向**苹果种植全产业链**的产业互联网平台，定位于"种植企业的数字化中台 + 消费者的品质信任入口 + 政府的产业监管抓手"三位一体：

| 维度        | 定位                                       |
| --------- | ---------------------------------------- |
| 对企业       | 一体化数字管理平台，打通"基地-农资-设备-采收-销售-认养"全流程 |
| 对消费者      | 可验证的品质溯源入口 + 沉浸式认养体验入口               |
| 对政府/合作组织 | 产业大数据汇聚与分析中心，支撑区域品牌建设                |
| 对开发者/集成商 | 开放API 网关，支持与ERP、WMS、气象、电商等多系统对接    |

### 1.3 核心价值主张

| 价值维度      | 一句话概括                         | 关键支撑                            |
| --------- | ---------------------------- | ------------------------------- |

## 第三章 用户故事与需求框架

### 3.1 Epic 级用户故事

#### Epic 1：统一门户与身份切换

> **US-001** 作为企业 IT 负责人，我希望公司所有数字化入口都收敛到一个统一门户，让员工根据角色一步进入对应的工作端，减少入口混乱与账号分散。

> **US-002** 作为基地管理员，我想用一个账号同时登录 PC 管理后台与移动工作端，不必重复申请账号，两端共享权限与待办。

> **US-003** 作为参观访客，我希望通过大屏和 VR 全景快速了解企业规模、生产指标、地理分布，不需要复杂登录即可看见"对外名片"。

#### Epic 2：生产管理数字化

> **US-004** 作为基地管理员，我想要在 PC 端创建年度农事计划（覆盖整地、修剪、施肥、灌溉、打药、采收等环节），按地块分配到人并下发到移动端。

> **US-005** 作为植保员，我在田间发现疑似腐烂病叶片后，可以使用手机拍照上传，AI 在 3 秒内给出病害类型与建议用药方案，我再决定是否一键下发施药任务。

> **US-006** 作为普通农工，早晨到地里前，我会在手机上看到当天分配给我的所有任务（带地块、物候期建议、要求完成时间），到田间后可以一键打卡并补充记录。

> **US-007** 作为采收员，接到采收任务后，我需要在现场逐箱称重、记录采收人，PC 端会自动形成采收批次与采收日报。

#### Epic 3：IoT 感知与预警

> **US-008** 作为基地管理员，当某地块土壤湿度低于阈值时，我希望立即收到预警，并能在手机上查看是哪个地块、哪个传感器、最近 24 小时曲线，并可下发灌溉指令。

> **US-009** 作为植保员，我想看到过去 7 天气象趋势，结合当前物候期，得到未来 3 天的病虫害风险指数，提前安排预防施药。

## 第五章 产品设计方案

### 5.1 设计原则

1. **一致性**：跨端统一设计语言（间距/字号/颜色），保证体验连贯；
2. **实用性**：以"任务"为导向设计页面，避免"功能堆叠"；
3. **高效性**：关键数据"屏内可读"，减少跳页与认知负担；
4. **可扩展性**：设计令牌（Design Token）化，便于主题切换与多端共享；
5. **情感化**：以果园绿 + 苹果橙为主色，体现"自然、丰收、可信"。

#### 6.2.2 生产管理

##### 6.2.2.1 农事计划 [farming_plan.html]

- **目的**：以年度/季度计划形式，把所有农事按"地块 × 物候期 × 作物"网格排期。
- **关键字段**：计划名称、年度、地块范围、物候期、关键作业节点、负责人、审核人、状态（草稿/已审批/执行中/已完成）。
- **核心操作**：新建 / 批量导入 / 复制上年 / 导出 PDF / 一键下发任务。
- **下钻**：点击节点可生成任务清单，分发给对应角色。

##### 6.2.2.2 农事记录 [farming_record.html]

- **目的**：一线农工上报完成的农事记录，作为审计与上链凭证。
- **关键字段**：地块、作物、物候期、作业类型、起止时间、用工人数、农资使用、备注、图片/视频、GPS、经手人。
- **异常处理**：网络异常暂存本地，恢复后自动重试；图片丢失要求重新上传。

##### 6.2.2.3 巡园管理 [farming_patrol.html]

- **目的**：支持植保员周期性巡查，发现问题即时派单。
- **关键流程**：扫码定位地块 → 选择物候期 → 上传问题照片 → 关联预警/任务。
- **下钻**：每条记录可关联到 AI 病虫害模型结果。

##### 6.2.2.4 无人机巡检 [drone_patrol.html]

- **目的**：定时/手动调度无人机巡检，回传轨迹与异常。
- **关键字段**：航线、起降点、覆盖面积、巡检时长、问题点、生成报告。
- **集成**：可对接大疆司空 2 / 经纬 M30。

##### 6.2.2.5 农事标准与计算器 [guide_standard.html] / [guide_calculator.html]

- **农事标准**：沉淀剪枝、施肥、灌溉等作业SOP，可关联至计划。
- **农事计算器**：根据作物、面积、目标产量推荐施肥量、用药量、灌溉量。

### 6.6 V4.1 后台数据支撑改造变更记录

> 本节记录 2026-10-21 实施的「后台菜单改造」专项，目标为消除大屏指标无后台数据源头的缺口，建立后台 → 大屏的数据链路。改造明细见 `docs/后台菜单改造清单.md`。

#### 6.6.1 改造背景

改造前对 8 个驾驶舱逐项比对后台数据源，结果为：后台仅能支撑大屏约 45% 的指标，其余为「后台无字段、大屏靠mock」或「后台有字段但口径不全」。其中数字成果、经营分析两屏缺口最集中（支撑度 0/4 与 1/4），无法通过在现有菜单内塞入字段解决。

#### 6.6.2 共享数据源（新增 3 个）

新增 `js/shared/` 目录下 3 个跨端共享数据源，替代大屏原有的本地 mock 数组。后台页面维护后经 localStorage 持久化并广播变更，大屏页面订阅后自动刷新，实现「后台改数→ 大屏同步」。

| `data-store.js` | `applefarm_data_ops_v1` | 数字成果驾驶舱 | 数据源接入、5 类数据归集、模型运行监控、提质增效、数字化里程碑 |

## 第七章 权限体系设计

### 7.1 总体思路

采用 **RBAC（角色基础）+ ABAC（属性条件）** 双轨：

- **角色决定"能做什么"**：菜单、按钮、数据范围；
- **属性决定"何时/对谁可做"**：基地归属、时间窗、物候期、数量等条件。

### 7.2 角色清单

| 编码     | 角色         | 关键能力                                |
| ------ | ---------- | ----------------------------------- |
| R_SUP  | 超级管理员     | 全平台最高权限                            |
| R_MGR  | 企业高管      | 全基地只读 + 战略指标                        |
| R_BASE | 基地管理员     | 单基地全权限                              |
| R_TECH | 农技员       | 农事、农资、模型、病虫害                       |
| R_WORK | 普通农工      | 任务、记录、农资领用、设备报障                   |
| R_HARV | 采收员       | 采收任务、打码                            |
| R_WHS  | 仓储管理员     | 采收发货、储藏管理                          |
| R_SALE | 销售/客户经理   | 客户、订单、认养、报表                        |
| R_GOV  | 政府/合作组织    | 大屏只读、区域聚合数据                        |
| R_VIEW | 参观访客      | 大屏只读                                |
| R_CON  | 溯源消费者     | H5 公开数据                             |
| R_FARM | 认养用户      | H5 + 认养相关                           |

### 7.3 权限粒度

| 级别      | 维度       | 示例                          |
| ------- | -------- | --------------------------- |
| 菜单级     | 一级/二级导航 | "AI 模型 → 病虫害模型" 可见性       |
| 页面级     | 页面访问     | 进入"系统设置"的权限                |
| 按钮级     | 操作能力     | "删除"、"导出"、"审核"            |
| 数据级     | 数据范围     | 用户 A 仅能看到"基地 1"的数据        |
| 字段级     | 脱敏        | 客户手机号"中间四位*"展示             |

### 7.4 多基地隔离

- 超级管理员可切换至任意基地；
- 基地管理员仅看本基地；
- 农工仅看任务范围内的地块。

### 7.5 审计与回溯

- 登录、操作、关键 CRUD 全部留痕；
- 关键操作触发审计日志看板，可按人/时间/对象检索；
- 审计数据不可篡改（同步上链或独立存储）。

### 9.2 安全要求

| 类目      | 要求                                                          |
| ------- | ----------------------------------------------------------- |
| **传输**   | 全站 HTTPS（TLS 1.2+），HSTS 强制                              |
| **认证**   | 双因子（账号+短信/人脸）、SSO、单点登录                                  |
| **授权**   | RBAC + ABAC，最小权限原则                                        |
| **加密**   | 国密 SM4/SM2 选项 + AES-256；密码 bcrypt 存储                       |
| **防注入**  | SQL/NoSQL 注入、命令注入、模板注入均拦截                                |
| **防爬**   | 接口限流、图形验证码、设备指纹                                           |
| **防泄漏**  | 数据库脱敏、字段级加密、日志脱敏                                          |
| **审计**   | 关键操作 100% 留痕，留存 ≥ 180 天                                   |
| **数据销毁** | 用户注销 30 天后匿名化、可选 90 天后物理删除                              |

### 9.3 隐私合规

- 收集最小化：仅采集业务所需的最小字段；
- 目的明确：所有采集字段都有明确用途说明；
- 用户可控：H5 提供"个人数据下载"与"账号注销"入口；
- 儿童保护：禁止 14 岁以下使用独立账号。

### 9.4 容灾与备份

- RPO ≤ 15 分钟，RTO ≤ 1 小时；
- 数据库主从 + 跨可用区灾备；
- 文件存储多副本 + 异地冷备；
- 演练每季度 1 次。

### 9.5 监控告警

- **指标**：CPU/内存/磁盘/网络/JVM/线程池/慢 SQL/错误码分布；
- **链路**：APM 全链路 Trace ID；
- **日志**：Loki + ELK 检索；
- **告警**：钉钉/电话 7×24。

### 11.3 接口签名与防重

```
StringToSign = HTTPMethod + "\n" + RequestURI + "\n" + QueryString + "\n" + BodyHash
Signature    = HMAC-SHA256(StringToSign, Secret) + "." + Timestamp + "." + Nonce
```

- 客户端生成签名；
- 服务端校验时间戳偏移 ≤ 5 分钟、Nonce 一次有效。

## 第十六章 数据表结构设计

### 16.1 设计原则

- **范式与反范式并用**：事务型表符合 3NF，报表型表反范式宽表化；
- **统一命名规范**：snake_case、复数表名；
- **审计字段统一**：created_at / updated_at / created_by / updated_by；
- **逻辑删除**：is_deleted + deleted_at 软删，关键业务保留硬删；
- **分区与归档**：时序大表按月分区，保留 36 个月在线数据。

## 第二十四章 数据驱动闭环

### 24.1 五层闭环

1. **采集**：人工 + IoT + 视频 + 第三方；
2. **存储**：原始库 + 主题库 + 应用库；
3. **分析**：BI 报表 + AI 模型；
4. **决策**：推荐、预警、调度；
5. **执行**：工人任务 + 自动设备指令；
6. **回流**：执行结果写到知识库，闭环回 AI 训练数据。

### 24.2 关键闭环场景

#### 24.2.1 病虫害闭环

采集 → 模型 → 推送 → 工单 → 执行 → 验收 → 数据回流

#### 24.2.2 灌溉闭环

土壤湿度→阈值→预警→派单→执行→回写历史

#### 24.2.3 价格闭环

批发市场行情 + 库存 + AI 模型 → 建议价 → 销售调整 → 复盘

#### 24.2.4 认养闭环

认养下单 → 自动同步农事 → 推送生长 → 采收预约 → 配送 → 评价 → 复购

### 24.3 数据治理

- 元数据管理：字段血缘、字段定义统一维护；
- 数据质量：5 项校验（唯一性、完整性、范围、一致性、时效）；
- 数据安全：分级分类、最小授权、动态脱敏；
- 数据资产化：将"地块档案""客户档案""批次档案"作为核心资产。

### 24.4 数据价值变现

- 政府报告：产业洞察、数据上报；
- 金融服务：基于产量/品质数据为农户授信（间接）；
- 保险数据：气象/产量数据支撑农业保险；
- 品牌赋能：数据资产沉淀为品牌叙事素材。

### 30.14 移动端巡园页补充「基地」维度（L-12）
