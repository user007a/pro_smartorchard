# 设备物联驾驶舱数据源核查

- 核查对象：[da_iot.html](../html/applefarm_dataanlye/da_iot.html)（智慧果园 · 设备物联驾驶舱）
- 核查范围：后台管理系统 `html/applefarm_backhand`、H5 端 `html/applefarm_h5`、移动端 `html/applefarm_mobile`
- 核查日期：2026-11-10
- 结论标记：**有源一致** / **有源不一致** / **部分有源** / **无源**

## 一、总体结论

1. **大屏本身未接任何数据层**。`da_iot.html` 全文只有 1 个内联 `<script>`（第 533 行起），没有任何 `<script src>`，也不引用 `device-store.js` / `production-store.js`；所有指标均为页面内硬编码，实时数据流和“今日上报/平均在线时长”由 `Math.random()` 每 30 秒微波动生成（第 752、765-771 行）。
2. **后台存在设备域权威数据层，但口径与大屏不一致**。`DeviceStore`（`html/applefarm_backhand/js/shared/device-store.js`，存储键 `applefarm_device_v1`，version 4）实际只有 **30 台**设备，而大屏写死 **186 台**；在线 23 台，实时在线率 **76.7%**，大屏写死 **93%**。
3. **H5 端没有设备驾驶舱指标**。仅 [h5_adoption.html](../html/applefarm_h5/h5_adoption.html)（第 308-331 行）按果树 `cameraId` 读取 `DeviceStore.cameras()` 的摄像头名称与状态，不涉及大屏的任何汇总指标。
4. **移动端设备页为静态页面**。[mb_device.html](../html/applefarm_mobile/mb_device.html)（第 450-463、478 行起）写死“在线 8 / 离线 2 / 预警 1”和 4 张设备卡片，且页面自身“共 4 台设备”与统计条不一致；未读取 `DeviceStore`。
5. **无人机架次后台有真实数据**，来自 `ProductionStore.sorties()`（18 条），但大屏“飞行中 2 架 / 今日累计 14 架次 / 航拍 420 亩”无对应数据。
6. **实时数据流只有数据结构、没有完整数据**。`DeviceStore` 仅 D-001、D-002、D-003、D-011、D-015、D-030 共 6 台设备有 `readings`；大屏 12 条数据流中的设备编号（S-2031、M-107、L-04 等）在后台不存在。
7. **近 7 日在线率趋势、今日数据上报、平均在线时长、运维提示**在后台均无对应字段或模块，属于大屏独有静态数据。

## 七、建议取数口径（改造时）

| 大屏指标 | 建议数据源 | 计算方式 |
|---|---|---|
| 设备总数 | `DeviceStore.devices()` | `length` |
| 在线 / 离线 / 维护中 | `DeviceStore.stats()` | `online` / `offline` / `maintain`；预警、闲置需单独补入状态分布 |
| 设备在线率 | `DeviceStore.stats().onlineRate` | 在线数 / 设备总数；需与 `avgOnlineRate` 明确区分 |
| 设备分类在线明细 | `DeviceStore.stats().byType` | 按 `type` 聚合 `total` / `online` |
| 设备状态分布 | `DeviceStore.stats()` | `online` / `offline` / `maintain`（补齐 warning、idle） |
| 各基地设备数 | `DeviceStore.stats().byBase` | 按 `base` 聚合 `total` / `online` |
| 接入 / 在线台数 | `DeviceStore.accessSummary()` | `total` / `online` |
| 设备分布地图 | `DeviceStore.devices()` + 地块主数据 | 按 `plotId` / `base` 聚合；需补充设备经纬度或按地块中心点聚合 |
| 无人机飞行任务 | `ProductionStore.sorties()` | 按 `status='执行中'` 取飞行中；按 `time` 前缀为今日筛选架次与面积 |
| 无人机台账 | `DeviceStore.devices().filter(type='drone')` | 执行无人机编号、在线状态 |
| 设备实时数据流 | `DeviceStore.readingsOf(id)` + `dataPointsOf(type)` | 只渲染有 readings 的设备；无 readings 标注“无上报” |
| 故障与维护记录 | `DeviceStore.maintains()` | 按 `createdAt` / `planDate` 倒序取 5 条，关联 `devices()` 取设备名 |
| 运维提示 | `devices()` + `maintains()` | 按离线时长、未闭环故障工单、类型在线率生成 |
| 今日数据上报 | 需新增 | 当前无日粒度字段，建议新增设备上报日汇总表或接口 |
| 近 7 日在线率趋势 | 需新增 | 当前无历史快照，建议新增在线率日快照表 |
| 平均在线时长 | 需新增或折算 | 当前仅有 `uptimeRate`，可按 `24 × uptimeRate / 100` 折算，但与大屏 23.4h 不保证一致 |

## 八、核查结论摘要

- **后台已有对应字段、可直接接线的**：设备总数、在线/离线/维护数量、分类在线明细、状态分布、基地分布、接入配置汇总、无人机架次、维护工单、设备实时测点（仅 6 台有值）。
- **有数据但需先统一口径的**：在线率（76.7% 实时 vs 96.1% 均值 vs 大屏 93%）、基地名称与数量（4 个有设备基地 vs 大屏 8 个）、地块数量（23 vs 12）。
- **后台当前无源、必须新增的**：今日数据上报、平均在线时长、近 7 日在线率趋势、运维提示。
- **H5 端不承载驾驶舱指标**；移动端仅设备报修可与后台形成闭环，设备监控页和无人机页需改为读取 `DeviceStore` / `ProductionStore` 后才能作为可信源。

## 九、修改建议（按优先级）

### P0 先统一口径，避免“越接越乱”

1. **确定设备总数口径**，二选一，不要继续让 186 与 30 并存：
   - 方案 A（推荐，成本低）：大屏改为展示 `DeviceStore` 的 **30 台**真实台账，同步修正分类、基地、状态分布和在线率。
   - 方案 B（保留 186 台演示规模）：把 `device-store.js` 种子扩充到 186 台，并补齐秦安、张川、武山、陇西 4 个基地的设备挂载；陇西还需先在基地档案和地块主数据中建档。
2. **固定在线率算法**：大屏统一使用 `stats().onlineRate`（在线数 / 设备总数）；`avgOnlineRate` 只用于台账卡片，并把文案改为“设备平均在线率”，避免 93% / 96.1% / 76.7% 三个数字互相矛盾。
3. **固定状态映射**：故障 = `status='offline'`；维护中 = `status='maintain'`；预警 = `status='warning'`；闲置 = `status='idle'`。状态分布环形图必须补齐 warning 和 idle，否则各分项之和永远不等于总数。
4. **统一基地名称**：大屏去掉“天水”“基地”前后缀后展示，数据源统一用 `stats().byBase` 的 `base` 字段；删除后台不存在的“陇西”，或先补基地档案。

### P1 让大屏真正接入数据层

5. **`da_iot.html` 引入数据层**：新增 `<script src="../applefarm_backhand/js/shared/device-store.js">` 和 `production-store.js`，把 KPI、分类、状态、基地、维护记录、实时流改为渲染函数，不再写死数字。
6. **分类明细改为字典映射**，建议在 `DeviceStore` 增加 `dashboardCategory` 字段做 1:1 归属，避免页面里再用 if/else 拼类型：
   - 气象站 → `weather_station` + `env_sensor`
   - 杀虫灯 → `insect_lamp`
   - 水肥一体机 → `water_fertilizer` + `irrigation_controller`
   - 监控摄像头 → `camera` + `ipc`
   - 植保无人机 → `drone` + `drone_hangar`
   - 土壤传感器 → `soil_sensor`
   - 虫情测报灯 → `pest_monitor`
7. **地图改用真实地块**：读取 `smartorchard_plot_master` 的 23 个地块 `lng/lat`，按设备 `plotId` 聚合到地块中心点；没有 `plotId` 的设备按 `base` 聚合；删除 SVG 示意坐标和“12 地块”文案。
8. **无人机任务接 `ProductionStore.sorties()`**：飞行中取 `status='执行中'`；今日架次按 `time` 前缀等于当天筛选；覆盖面积用 `sum(area)`；执行无人机用 `sortie.drone` 关联 `DeviceStore` 的无人机台账；删除后台不存在的 `#013`。
9. **实时数据流只展示真实 readings**：遍历有 `readings` 的在线设备动态生成，最多 12 条；无 readings 的设备显示“暂无上报”，不再用 `METRIC_BASE` 模拟值冒充实时值。
10. **维护记录接 `maintains()`**：按 `createdAt` / `planDate` 倒序取 5 条，关联 `devices()` 取设备名，状态映射为“待处理 / 处理中 / 已完成”，不要写死“西3水肥机”等设备名。
11. **运维提示改为规则生成**：离线超过 2 小时、存在未闭环故障工单、某类型在线率低于 90% 三类规则，替代当前静态文案。

### P2 补齐后台目前没有的数据源

12. **今日数据上报**：新增设备上报日汇总（如 `device_report_daily`，字段 `date / deviceId / count`），由设备接入层按日累加；在接入前大屏应显示“待接入”，不要用累计 1.248 亿条冒充今日 42.6 万条。
13. **平均在线时长**：新增 `onlineHoursToday` 或心跳累计字段，按 `在线时长 / 天数` 计算；不要用 `uptimeRate × 24` 折算后当作真实值。
14. **近 7 日在线率趋势**：新增每日快照（如 `device_online_snapshot`，字段 `date / total / online / onlineRate`），每日 0 点落库；无历史数据时展示“暂无趋势数据”，不要画静态折线。
15. **增加自检脚本**：参照 `_adoption-store.check.js`，新增 `_device-dashboard.check.js`，断言“大屏 KPI = `DeviceStore` 聚合值”，防止后续再次写死。

### P3 端侧一致性

16. **移动端 `mb_device.html` 改为读 `DeviceStore`**：设备卡片、在线/离线/预警数量、“共 N 台”全部动态渲染，避免出现“共 4 台设备”但统计条显示 8/2/1 的自相矛盾。
17. **移动端无人机页接 `ProductionStore`**：进度、架次、覆盖面积取自真实架次记录，取消本地 `progress:65` 模拟。
18. **H5 保持只读**：认养页继续按 `cameraId` 读取摄像头档案即可，不新增驾驶舱指标；设备离线时补充“监控暂不可用”提示。
19. **时间统一动态生成**：趋势横轴、记录时间、“今天/昨天”全部按当前日期计算，禁止写死 10-14 ~ 10-20。

### 建议的最小改造顺序

| 阶段 | 动作 | 验收标准 |
|---|---|---|
| 第一步 | 定口径 + 大屏接 `DeviceStore` 已有字段 | 大屏设备总数、在线率、状态分布、基地分布与 `DeviceStore.stats()` 完全一致 |
| 第二步 | 接 `ProductionStore` + 地块主数据 | 无人机架次、今日架次/面积、地图地块数与后台一致 |
| 第三步 | 实时流、维护记录、运维提示动态化 | 页面无写死设备编号/设备名，全部可在后台台账中查到 |
| 第四步 | 新增今日上报、平均在线时长、7 日快照 | 三项有独立数据表或接口，大屏不再随机波动 |
| 第五步 | 移动端设备页与无人机页动态化 | 移动端与后台同一设备总数、同一架次列表 |
