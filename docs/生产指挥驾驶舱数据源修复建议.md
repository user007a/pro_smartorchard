# 生产指挥驾驶舱数据源修复建议清单

> 依据文档：[生产指挥驾驶舱数据源.md](生产指挥驾驶舱数据源.md)  
> 修复对象：`html/applefarm_dataanlye/da_dashboard.html` 及其关联的后台、移动端、H5 页面与共享数据层  
> 生成日期：2026-11-10

## 一、修复原则

1. **单一数据源**：驾驶舱只做展示，不维护业务数据；所有数值必须来自共享数据层或地块主数据。
2. **口径唯一**：同一指标在驾驶舱、后台列表、移动端、H5 使用同一计算公式，禁止各页各自硬编码。
3. **缺失不伪造**：无源数据显示“暂无数据/未建模”，禁止用相近品类或近似值顶替。
4. **可追溯**：每个指标标注数据来源与更新时间，支持下钻到后台明细页。
5. **不破坏既有功能**：修复以接入数据层和统一口径为主，不删除现有页面与业务能力。

优先级定义：

| 优先级 | 判定标准 |
|--------|----------|
| P0 | 当前数值错误、同屏自相矛盾或无法与业务台账关联，直接影响指挥决策 |
| P1 | 后台已有源数据但未接入，或指标缺少关键字段，影响可用性与可信度 |
| P2 | 展示优化、跨端一致性、数据新鲜度与长期维护机制 |

## 三、P0 修复清单

### P0-01 统一地块主数据与编码

- **现状**：驾驶舱地图使用 12 块 A1～D1（合计 99.8 亩），后台地块管理为 23 块 D-001～D-023，设备、农事、采收均按 D-xxx 编码；两套体系无法关联。
- **目标口径**：`smartorchard_plot_master` 为唯一地块主数据；驾驶舱地图按该主数据渲染，模型健康/风险通过 `plotCode` 关联，无模型数据的地块标注“未建模”。
- **修复动作**：
  1. `da_dashboard.html` 删除内联 `PLOTS` 常量，改为读取 `smartorchard_plot_master`。
  2. 在 `ModelStore` 病虫害地块上新增 `plotCode` 字段，与 D-001～D-023 建立映射。
  3. 地块总览标题的“X 亩 · Y 地块”由地图数据实时汇总，不再写死。
  4. 移动端 `mb_map.html` 与后台 `enterprise_plot.html` 保持同一主数据键。
- **涉及文件**：`da_dashboard.html`、`js/shared/model-store.js`、`enterprise_plot.html`、`mb_map.html`
- **验收标准**：
  - [ ] 驾驶舱地块数与后台地块管理一致，编码全部为 D-xxx。
  - [ ] 任一点击地块可下钻到后台地块详情。
  - [ ] 无模型数据的地块显示“未建模”，不再套用 A1～D1 数据。

### P0-02 定义综合健康指数

- **现状**：大屏显示 86，后台只有 12 块单地块 `health`，算术均值 82.8、按面积加权 83.2，均无法得到 86。
- **目标口径**：`综合健康指数 = Σ(地块 health × 地块面积) / Σ地块面积`，仅统计已建模地块，并在卡片标注“样本 N 块”。
- **修复动作**：
  1. 在 `ModelStore` 增加 `healthIndex()` 聚合方法，输出 `{value, sampleCount, updatedAt}`。
  2. 大屏顶部与地图图例共用该结果，删除 86。
  3. 若后续引入长势/水分/养分/病虫四维评分，再升级为加权模型并保留版本号。
- **涉及文件**：`da_dashboard.html`、`js/shared/model-store.js`
- **验收标准**：
  - [ ] 按当前种子数据复算值为 83.2（面积加权），与页面一致。
  - [ ] 卡片可见“样本 12 块 · 模型口径”说明。

### P0-03 统一农事执行统计口径

- **现状**：大屏 128 计划 / 96 完成 / 22 执行中 / 3 逾期；`ProductionStore` 实际 23 计划 / 13 完成 / 5 执行中 / 0 逾期，且 96+22+3=121 与 128 不自洽。
- **目标口径**：以 `ProductionStore.plans()` 为计划口径、`tasks()` 为任务口径；页面明确标注统计对象，达成率 = 完成计划数 /（计划总数 − 已取消计划数）。
- **修复动作**：
  1. 大屏删除 128/96/22/3 常量，改为按 `status` 实时统计。
  2. 逾期数按 `tasks[].deadline < 今天 && status not in (completed,cancelled)` 计算。
  3. 顶部“农事达成率”与左栏“农事执行”共用同一统计函数，避免两处口径不同。
  4. 明确“计划”与“任务”的展示层级，禁止混用。
- **涉及文件**：`da_dashboard.html`、`js/shared/production-store.js`
- **验收标准**：
  - [ ] 当前种子数据下显示 23 / 13 / 5 / 0，达成率 56.5%。
  - [ ] 在后台新增或完成一条计划后，大屏刷新即同步变化。

### P0-04 统一设备状态与设备运转总览

- **现状**：大屏在线率 93%、故障 2；`DeviceStore` 30 台设备中 `online` 23 台（76.7%），另有 warning 1、maintain 1、offline 3、idle 2；气象站写 8/8、杀虫灯写 54/60，而台账仅 2 台气象站、1 台杀虫灯。
- **目标口径**：
  - 在线率 = `status==='online'` 台数 / 设备总数；
  - 故障 = `warning + offline`；
  - 维护、停用单列；
  - 分类卡片按 `DeviceStore.stats().byType` 显示“在线/总数”，不再写死。
- **修复动作**：
  1. 大屏顶部在线率、故障数改为 `DeviceStore.stats()`。
  2. 设备运转 6 类卡片改为按 `type` 聚合，删除“8/8”“54/60”“西3”“北4”等静态文案。
  3. 无人机“飞行中”单独读取 `ProductionStore` 架次状态，不与设备在线状态混用。
  4. 若确需展示 60 台杀虫灯，先在设备台账补齐设备，再允许大屏展示该数量。
- **涉及文件**：`da_dashboard.html`、`js/shared/device-store.js`、`device_info.html`、`device_stats.html`
- **验收标准**：
  - [ ] 在线率显示 76.7%，故障 4（warning 1 + offline 3），维护 1、停用 2。
  - [ ] 气象站显示 2/2、杀虫灯 1/1，且与设备台账一致。
  - [ ] 点击分类卡片可跳转设备列表并按类型筛选。

### P0-05 统一农资品类与保障率

- **现状**：顶部保障率 79%，底部按 `MaterialStore` 实时计算为 50%；“农膜”取 M-017 喷雾器、“套袋”取 M-004 疏花疏果剪，品类语义错误；覆盖天数使用硬编码日均。
- **目标口径**：保障率 = 库存 ≥ 安全库存的品类数 / 有安全库存要求的品类数；品类只允许使用 `MaterialStore` 已定义的 `fertilizer/pesticide/tool` 及后续正式新增品类；无该品类时显示“未配置”。
- **修复动作**：
  1. 删除驾驶舱 `GROUPS` 中对 M-017、M-004 的顶替映射。
  2. 在农资档案中正式新增“农膜、套袋”品类与 SKU 后，再恢复对应卡片；否则隐藏该两卡。
  3. 顶部 KPI 与底部保障率共用 `MaterialStore.categoryStats()` 结果。
  4. 覆盖天数改为 `可用库存 / Σ该品类 dailyUse`，无日均消耗时显示“—”。
- **涉及文件**：`da_dashboard.html`、`js/material-store.js`、`material_info.html`、`material_inventory.html`
- **验收标准**：
  - [ ] 同屏保障率只有一个值（当前种子为 50%）。
  - [ ] 不再出现用喷雾器、疏花疏果剪冒充农膜、套袋。
  - [ ] 覆盖天数与农资档案日均消耗可复算。

### P0-06 物候期与采收窗口动态计算

- **现状**：大屏固定“着色成熟期（自 09-05）”“采收窗口 10-15～10-31”，而物候模型字典 11-10 已处于采收期（10-01～12-31），且模型 `meta.today` 仍停留在 09-24。
- **目标口径**：按自然日匹配 `ModelStore.get('phenology').lists.stages` 的起止日期，输出当前阶段、已持续天数、下一阶段与采收窗口；跨年时正确处理年份。
- **修复动作**：
  1. 在 `ModelStore` 增加 `currentStage(date)`，按 `MM-DD` 解析并处理跨年。
  2. 大屏物候期、生长研判、左栏建议统一读取该结果。
  3. 采收窗口直接取“采收期”阶段的起止日期，不再单独写死。
  4. 将 `meta.today` 改为运行时当天日期。
- **涉及文件**：`da_dashboard.html`、`js/shared/model-store.js`、`model_phenology.html`
- **验收标准**：
  - [ ] 2026-11-10 显示“采收期（10-01～12-31）”。
  - [ ] 切换系统日期到 10-01 前显示“着色期”。
  - [ ] 页面无固定日期文案。

### P0-07 明确采收量统计口径

- **现状**：大屏接入 `HarvestStore.records()` 按当前月过滤，2026-11 无完成记录，实际渲染 0.0t；种子数据集中在 2026-09，10 月两条为待处理。

  - 方案 B：保留“本月采收量”，补 2026-11 业务数据，并在无数据时显示“本月暂无采收”。
- **修复动作**：
  1. 按选定方案修改大屏统计区间与标题。
  2. 增加空态文案，禁止用 0.0t 表示“无数据”。
  3. 建立采收记录月度补录机制，保证演示与业务月份同步。
- **涉及文件**：`da_dashboard.html`、`js/shared/harvest-store.js`、`harvest_record.html`
- **验收标准**：
  - [ ] 页面标题与统计区间一致。
  - [ ] 无数据时显示“本月暂无采收”，不再显示 0.0t。
  - [ ] 与后台采收报表同口径、同数值。

- **涉及文件**：`da_dashboard.html`、`js/shared/device-store.js`、`mb_home.html`、`device_info.html`
- **验收标准**：
  - [ ] 大屏气温 18.6℃、湿度 54.2%、光照 4.26 万 lx、土壤含水 32.8%，与 D-001/D-002 测点一致。

## 四、P1 修复清单

### P1-01 建立四维健康评分

- **现状**：长势 90、水分 72、养分 84、病虫 74 均无字段。
- **建议**：在 `ModelStore` 增加 `health.dimensions = {growth, water, nutrient, pest}`，分别由生长模型、墒情阈值、土壤检测、病虫害模型输出；综合指数按 30%/20%/20%/30% 加权，并保留权重版本号。
- **验收**：每项评分可追溯到一个模型与一组原始数据；无检测数据的维度显示“未检测”而非估值。

### P1-02 新建土壤检测数据层

- **现状**：有机质 2.4%、速效氮 62、速效磷 28、速效钾 186 全端无源。
- **建议**：新增 `js/shared/soil-store.js`，存储键 `smartorchard_soil_tests_v1`，字段：`plotCode、sampleDate、lab、organicMatter、availableN、availableP、availableK、ph、ec`；后台增加土壤检测记录录入与列表页，大屏按最新检测报告展示并标注采样日期。
- **验收**：大屏四项指标均能下钻到具体检测记录；无记录时显示“未检测”。

### P1-03 扩展气象趋势字段

- **现状**：降水 12.4mm、日照 6.8h、降水概率 70%、降温 6℃ 均无源；模型当前为 26℃ 夏季口径。
- **建议**：在 `ModelStore.get('weather')` 增加 `precipitation`、`sunshineHours`、`rainProbability`、`tempDrop`；`forecast` 每日补齐；更新种子为 11 月口径。
- **验收**：7 日趋势图同时具备气温与降水序列；天气提示可由字段生成。

### P1-04 明确环境样本口径并补设备

- **现状**：台账有 2 台气象站（D-001、D-009）、2 台土壤仪（D-002、D-025），但 D-009 未配置 `readings`、D-025 已停用报废，实际有效样本仅 1 台气象站 + 1 台土壤仪，无法支撑“全园均值”。
- **建议**：按基地补齐气象站与土壤仪台账并配置测点；在补齐前，大屏标注“样本 1 台 · 覆盖天水麦积区基地”，说明覆盖范围，不宣称全园均值。
- **验收**：环境卡片显示有效样本数与覆盖基地；设备台账、测点配置与大屏展示一致。

### P1-05 农资覆盖天数按实算

- **现状**：化肥日均基准 16.7、农药 6.3 为硬编码，与 `dailyUse` 合计 57.5 不一致。
- **建议**：覆盖天数 = 可用库存 / Σ该品类 `dailyUse`；无日均值时显示“—”，并允许在农资档案维护日均消耗。
- **验收**：任一 SKU 日均消耗调整后，覆盖天数同步变化。

### P1-06 农事待办实时生成

- **现状**：东2/北1/西3、张建国/李红/王强在任务种子中无对应记录。
- **建议**：待办取 `ProductionStore.tasks()` 中 `pending/processing` 按截止时间排序前 3 条，展示任务名、地块编码、负责人、剩余/逾期时长。
- **验收**：待办条目均可点击进入任务详情；不再出现虚构人名与地块名。

### P1-07 移动端消息页接入 MobileOpsStore

- **现状**：后台配置 `mb_messages`，移动端消息为静态示例。
- **建议**：`mb_home.html` 消息入口与消息列表读取 `MobileOpsStore`，仅展示 `enabled!==false` 的消息。
- **验收**：后台停用一条消息后，移动端不再展示。

### P1-08 移动端只读页接入后台数据层

- **现状**：`mb_growth`、`mb_pest_risk`、`mb_weather_predict`、`mb_yield`、`mb_device`、`mb_plan` 均为页面静态数据。
- **建议**：按现有只读绑定思路（参考 `model-bind.js`），通过 `data-*` 属性绑定 `ModelStore`/`DeviceStore`/`ProductionStore` 字段；移动端不写死业务数值。
- **验收**：后台修改模型或设备数据后，移动端刷新即同步。

### P1-09 H5 溯源环境快照标注

- **现状**：`TraceStore.environmentOf()` 为按批次生成的展示值，非实时设备数据，易被误读为实时环境。
- **建议**：H5 溯源页标注“批次环境快照 · 采样时间”，并注明数据来源；不参与生产指挥实时指标。
- **验收**：页面可见“非实时”说明；大屏不引用该快照。

### P1-10 统一 EC 单位与取值区间

- **现状**：后台与驾驶舱为 mS/cm（1.24，即 1,240 µS/cm），H5 为 µS/cm（120～210），除单位不同外，取值区间也相差约 6～10 倍。
- **建议**：全端存储统一为 µS/cm；后台/大屏展示时换算为 mS/cm（保留两位小数），H5 显示 µS/cm；同时按土壤仪实际量程重设 H5 生成区间与后台种子值，保证换算后同源同值。
- **验收**：同一地块在后台、H5、大屏换算后数值一致（允许展示精度差异），不再出现 1.24 mS/cm 与 120～210 µS/cm 并存。

### 8.4 已知边界

1. **地块几何**：模型仅提供 12 块已建模地块的 polygon，台账 23 块中其余 11 块暂无图形，页面以“未建模 11”明示，不伪造边界。
2. **农膜 / 套袋**：农资档案尚未建立这两个品类，按“缺失不伪造”原则不展示对应卡片；后续在农资管理中新增品类后即可自动出现。
3. **养分评分**：`healthDimensions()` 的养分项采用公开权重（有机质 40%、速效氮/磷/钾各 20%）计算，权重版本记为 v1，后续可按农技标准调整。
4. **EC 双单位**：设备侧原始读数为 mS/cm，土壤检测报告按 µS/cm 存储，展示层统一换算，未改动硬件协议。
5. **数据新鲜度**：演示种子集中在 2026-09～2026-11，跨月后需补录采收与农事记录，否则会进入空态提示。
6. **设备在线率波动**：在线率由台账实时计算，后台修改设备状态后大屏即时变化，演示时需固定台账基线以保证多端读数一致。
