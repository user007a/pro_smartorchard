## 1. 技术栈现状

### 1.1 语言与运行时

| 维度 | 现状 | 说明 |
| --- | --- | --- |
| 语言 | 原生 HTML5 + CSS3 + JavaScript | **无框架**（无 React/Vue/jQuery） |
| 模块化 | `<script>` 标签顺序加载 | **无 ES Module**，全局变量即依赖 |
| 构建 | **完全无构建** | 无 webpack/vite/rollup，源码即产物 |
| 运行时依赖 | **零** | 仅 [vendor/tailwind.min.js](file:///d:/dev/pro_smartorchard/html/applefarm_backhand/vendor/tailwind.min.js)（CDN 失败可降级） |
| 后端 | **无** | 全部数据在 localStorage / sessionStorage |

### 1.2 关键前提：可直接双击打开

现有 153 个 HTML 必须**双击即可在浏览器中运行**（`file://` 协议），这是硬性产品要求。直接后果：

| 后果 | 说明 |
| --- | --- |
| 不能用 ES Module | `file://` 下 CORS 限制导致 `import` 失败 |
| 不能用 fetch 读本地文件 | 同上 |
| 不能依赖 ES6+ 的浏览器 API 做核心链路 | 目标为移动端旧版 WebView 兼容 |
| 样式不能用 CSS 预处理器 | 无构建即无变量合并 |

**因此：任何"改用 ES Module""引入打包器""用 fetch 加载 JSON"的建议都是错误的，直接拒绝。**

## 2. ES 特性使用边界

实测全项目 153 个 HTML 的 ES 特性分布：

| 特性 | 出现次数 | 判定 |
| --- | --- | --- |
| 箭头函数 `=>` | 478 | ✅ 已广泛使用，可用 |
| 模板字符串 `` ` `` | 824 | ✅ 已广泛使用，可用 |
| `let` / `const` | 大量 | ✅ 已使用，可用 |
| `async` / `await` | 10 | ⚠️ 谨慎使用，仅限已接入真实接口的页面 |
| 可选链 `?.` | 30 | ⚠️ 谨慎使用，需确认目标 WebView 支持 |
| 空值合并 `??` | 0 | ❌ **本项目不使用，勿引入** |

### 2.1 硬性规定

```
允许  ES5 全部语法
允许  箭头函数、模板字符串、let/const、Array 扩展方法（map/filter/find/some）
禁止  空值合并 ??（本项目零使用，引入即造成风格分裂）
禁止  动态 import()、import/export 语句
禁止  async/await 用于新代码（现有 10 处为特定场景，新代码用 Promise.then）
禁止  可选链 ?. 在无降级兜底的路径上使用
```

### 2.2 为什么禁止 `??`

现有代码统一用 `a || b` 或 `a ? a : b` 处理默认值。引入 `??` 会导致两种等价写法并存，后续维护者无法判断哪个是刻意选择。**风格一致性优先于语法便利性。**

## 3. 禁止清单（最高效力）

以下条目**在任何任务中均不得违反**。违反即视为交付失败，不接受"功能能跑"的辩解。

`html/` 下所有脚本共享同一个全局作用域（`window`）。已声明的全局变量**禁止重新声明**：

| `Toast` `LegacyToast` | 同上 | ⚠️ **二选一** |
| `ConfirmDialog` `LegacyConfirmDialog` | common-functions.js 或 components/confirm.js | 二选一 |
| `Pagination` `Search` | common-functions.js | 分页/搜索 |
| `PageActions` | page-actions.js | 通用页面操作 |
| `MaterialStore` | material-store.js | 农资仓储 |
| `BizStore` `DataStore` `TraceStatStore` `AlertStore` | js/shared/*.js | 共享数据源 |
| `MobileBridge` | js/shared/mobile-bridge.js | 跨端桥接 |
| `MobileStore` | applefarm_mobile/js/mobile-store.js | 移动端底座 |
| `H5Auth` | applefarm_h5/js/h5-auth.js | H5 登录态 |

- 禁止 `var Modal = ...` / `const Modal = ...` 在任何页面内联脚本中重新声明上述任何名字

### 3.5 已踩坑记录（血泪教训，必须遵守）

以下问题均已实际发生并修复，**任何新代码不得重蹈**：

#### 坑 1：Modal 全局重复声明 ⚠️ 最高频

```
现象  SyntaxError: Identifier 'Modal' has already been declared
原因  common-functions.js L52 const Modal
      components/modal.js L14 const Modal
      两个 script 同时加载即冲突
后果  该页面全部弹窗（新增/编辑/详情/删除）静默失效
解决  二选一。实测现状：95 个 PC 页面中 66 个引用 common-functions.js，
      20 个引用 components/modal.js，
      仅 enterprise_plot.html 曾同时引用（现已只保留 components/modal.js）
规则  新页面默认参照同模块已有页面的选择；不确定时用 common-functions.js
```

> `components/confirm.js` 同理与 `common-functions.js` 的 `LegacyConfirmDialog` 存在命名冲突风险，一并遵守"二选一"。

#### 坑 2：Store 内存缓存导致跨页不一致

```
现象  material_info.html 改库存后，material_inventory.html 仍显示旧值
原因  MaterialStore 曾用模块级变量 materials 缓存首次读取结果
后果  多标签页/多页面数据不一致，且难以复现
解决  改为每次直读 localStorage（readStored()）
规则  任何 Store 都不得做内存缓存，参见 §4.2
```

#### 坑 3：koa-connect 包装导致 ctx.state 丢失

```
现象  采收管理下用 koa-connect 包装 Express 中间件时 ctx.state 数据丢失
解决  直接原生重写 Koa 中间件
规则  接入真实后端时，中间件一律原生实现，不用 koa-connect 之类的包装层
```

#### 坑 4：同源 localStorage 的跨端局限

```
现象  PC 后台写入的数据在移动端看不到（反之亦然）
原因  localStorage + storage 事件仅在同源同浏览器生效
后果  换设备/换浏览器/跨源即完全失效
现状  这是「无构建纯静态可双击打开」前提下的固有边界（需求说明书 L-1）
规则  这是已知设计边界，不是 bug。生产环境通过替换 Store 的 read/write 实现解决，
      页面调用处无需改动。详见 04-存储契约.md 的「生产替换点」
```

#### 坑 5：文件上传无法自动化测试

```
现象  浏览器自动化无法设置本地文件<input type="file">
后果  L-4 图片上传链路无法端到端实测
规则  涉及文件上传的验收断言，改用 Node 桩化 DOM 直接调用处理函数验证
```

#### 坑 6：分页容器 id 未统一（本项目最普遍的 DOM 遗留）

```
现象  95 个 PC 页面中只有 26 个用了标准 id="pagination-container"，
      其余散落为 paginationInfo(7) / pagination(6) / paginationContainer(1)
原因  分页是各页面自行实现（renderPagination），无统一契约约束
后果  改分页样式需逐页改；AI 容易误以为「paginationInfo 是对的」
规则  新增页面必须用 pagination-container；存量页面改分页时一并统一。
      分页格式统一为「‹ 1 2 3 › 第 X 页/共 Y 页，共 Z 条记录」
      详见 02-架构总览.md §4.1
```

#### 坑 7：页面绕过 Store 直写业务数据

```
现象  移动端 mb_device.html / mb_drone_patrol.html 直接写裸 storage key
      （smartorchard_maintenance_logs / smartorchard_drone_events / smartorchard_drone_abnormal），
      这 3 个 key 未进入 MobileStore.KEYS
原因  早期页面为赶进度绕过数据层，后续未收敛
后果  违反 §4.1 唯一入口原则；跨端回退与广播机制失效
规则  新代码严禁仿此做法。这 3 处列入遗留台账 L-A01，
      在批次 2 统一收敛（补进 MobileStore.KEYS），本批次不改代码
```

## 4. 数据层约束

### 4.1 唯一入口原则

```
页面 → Store → localStorage
```

**禁止**页面直接调用 `localStorage.getItem/setItem` 操作业务数据。仅以下三类数据可由页面直写：

| 允许直写的数据 | 原因 | key |
| --- | --- | --- |
| 登录态 | 会话级，非业务数据 | `snzg_logged_in`、`snzg_user` |
| 纯 UI 偏好 | 无业务含义 | `sidebar-tabs`、`orchard_farming_prefill` |
| H5 端本地行为数据 | C 端无跨端需求 | `h5_*` 系列 |

**任何业务数据的读写都必须经过 Store。** 直写会导致跨端联动与数据回退策略全部失效。

### 4.2 Store 铁律

| 铁律 | 说明 |
| --- | --- |
| **禁止内存缓存** | 每次读写直取 localStorage（`MaterialStore` 已因此重构） |
| **必须容错** | JSON.parse 失败、类型不符时回退种子数据，不得抛异常中断页面 |
| **禁止写坏数据** | 写入前校验结构；结构非法时拒绝写入并保持原数据 |
| **必须广播** | 写入后派发 `storage` 事件（跨标签页）+ 自定义事件（同页多订阅者） |
| **读取只读快照** | 返回 `deepClone`，防止调用方意外修改内部状态 |

### 4.3 两级回退（必须实现）

所有数据读取页统一遵循：

```
① 读权威源（Store / localStorage）
      ↓ 解析失败或结构非法
② 回退内置种子数据（页面内DEFAULT_xxx）
      ↓
③ 绝不回写权威源（不把种子数据写进 localStorage 覆盖真实数据）
```

> 第③ 条是关键：很多项目在回退时顺手把种子数据落盘，导致用户真实数据被演示数据覆盖。本项目**明确禁止**。

### 4.4 时间与命名约定

| 约定 | 规则 | 依据 |
| --- | --- | --- |
| 字段命名 | `snake_case` | 需求说明书 §12.1 |
| 时间存储 | ISO 8601 字符串（`new Date().toISOString()`） | `MobileStore.push` 自动注入 |
| 时间展示 | `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm` | `MobileStore.fmtTime` |
| 空值 | **禁止 null**，统一用空字符串或默认值 | 需求说明书 §12.1 |
| ID 生成 | `'id_' + Date.now() + '_' + random5` | `MobileStore.push` |
| 队列 ID | `'q_' + Date.now() + '_' + random5` | `MobileStore.enqueue` |
| 主键策略 | UUID 字符串（须兼容雪花 ID） | 需求说明书 §12.1 |

## 5. 代码风格约束

### 5.1 命名

```javascript
// 正确
var STORAGE_KEY = 'smartorchard_material_store_v1';   // 常量全大写下划线
function readStored() { }                             // 函数驼峰
var subscribers = [];                                 // 变量驼峰

// 错误
var storageKey = 'xxx';        // 常量不用全大写
function ReadStored() { }       // 函数不用驼峰
```

### 5.2 存储键命名

```
格式：  smartorchard_{域}_{对象}[_v版本]   |   applefarm_{域}_{对象}_v版本
示例：  smartorchard_material_store_v1
        smartorchard_farming_records
        applefarm_biz_v1

禁止：  中文键名、无前缀裸键名（避免与同浏览器其他项目冲突）
既有例外：h5_* 系列为历史遗留，禁止新增更多此类裸键
```

### 5.3 注释

```
必须写：  存储 key 名、对外API 清单、跨端依赖说明、生产替换点
禁止写：  解释"这行代码做了什么"（代码本身已表达清楚）
禁止写：  注释掉的死代码（直接删）
```

现有 Store 文件的注释风格即为范本，见 [material-store.js](file:///d:/dev/pro_smartorchard/html/applefarm_backhand/js/material-store.js#L1-L19)。

## 6. 安全约束

| # | 约束 | 现状问题 | 目标 |
| --- | --- | --- | --- |
| 1 | 密码不得明文存储 | `mb_login.html` 用 `encodePwd` 简单编码后存 `rememberedPwd` | 接入真实认证后移除本地密码存储 |
| 2 | 登录态用 sessionStorage | ✅ 已正确 | 保持 |
| 3 | 敏感字段脱敏 | 身份证/电话展示需脱敏 | 遵循需求说明书 §4.6 |
| 4 | 关键操作二次确认 | 删除、批量操作必须 ConfirmDialog | 保持 |
| 5 | 禁止 `innerHTML` 拼接未转义的用户输入 | 存在 XSS 风险 | 用户输入渲染前必须转义 |
| 6 | 证书/图片 base64 容量控制 | `cert_stamp_dataurl` 存 dataURL，有容量风险 | 见需求说明书 §30.10挂牌 PNG 归档容量防护 |

### 6.1 登录态契约

```
PC 后台：
  sessionStorage['snzg_logged_in'] = '1'        登录标记
  sessionStorage['snzg_user'] = { username, name, role }
  守卫：index.html <head> 内联脚本检查，未登录立即 location.replace('login.html')

移动端：
  sessionStorage['isLoggedIn'] = 'true'
  sessionStorage['loginUser'] = username
  sessionStorage['loginRole'] = role

H5：
  由 H5Auth 统一管理，见 applefarm_h5/js/h5-auth.js
```

> **登录守卫必须放在 `<head>` 内联脚本中**，不能放在 `<body>` 末尾或外部 js——否则页面会先渲染再跳转，产生闪屏。
