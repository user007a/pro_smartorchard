# 智慧果园管理系统 · 详细设计说明书 V5.0

> **文档性质**：本套文档是**实现契约（Implementation Contract）**，不是叙述性设计说明。
> **首要读者**：使用 AI 编程工具（Trae / Cursor / Copilot / Claude Code等）的开发人员。
> **次要读者**：人工开发者、技术评审、项目验收方。
> **基线版本**：V4.1（对应 [需求说明书 V4.1](../需求说明书.md) 与 `html/` 静态原型）

---

## 0. 一句话理解本套文档

> **需求说明书回答"要做什么"，本文档回答"必须怎么做，做完怎么算对"。**

传统详细设计的价值在于向人解释设计决策。本套文档的价值在于**消除歧义**——AI 与初级开发者的最大失败模式不是写不出代码，而是「代码能跑但与预期不符」，且偏差发生在无人察觉的地方。本套文档的所有章节设计都服务于一个目的：**让偏差无法发生，或偏差可被立即发现。**

## 1. 核心前提：原型即正式前端资产

本项目与其他项目最大的不同，必须在开始任何工作前理解：

| 维度 | 常规项目 | 本项目 |
| --- | --- | --- |
| 前端代码来源 | 从零编写 | **`html/` 下153 个静态 HTML 已是正式资产** |
| 详细设计描述什么 | 系统应该长什么样 | **从原型到生产态要改什么** |
| 开发动作 | 新建页面 | **在既有页面上定点改造** |
| DOM 结构 | 由文档定义 | **由原型锁定，不可重设计** |

因此本文档采用**代码标记制**贯穿全文。阅读任何页面详设时，只需关注标记为 `【改造】``【替换】``【补齐】``【缺口】` 的条目；`【保留】` 条目**禁止改动**。

## 4. 契约优先级（冲突裁决顺序）

当两份文档对同一事项给出不同结论时，**按此顺序裁决，高优先级覆盖低优先级**：

```
1. 01-技术栈与工程约束.md        硬约束与禁止清单（不可协商）
        ↓
2. 03~07 契约层               数据 / 存储 / 接口 / 事件 / 跨端联动
        ↓
3. 08~12 规范层                设计系统 / 组件 / 工程化 / 权限 / 部署
        ↓
4. pages/ 页面详设              单页面的具体实现约定
        ↓
5. html/ 现有代码              现状（仅当契约未覆盖时作为默认）
        ↓
6. 需求说明书 V4.1              产品意图（仅当以上均未覆盖）
```

**三条不可协商的铁律**：

| # | 铁律 | 说明 |
| --- | --- | --- |
| 1 | **原型结构 > 一切文档描述** | 契约不得要求重设计已锁定的 DOM 结构；如确需变更，须走 §变更流程 |
| 2 | **契约未覆盖的字段，禁止自行发明** | 遇到契约没写的字段/状态/枚举，必须挂起并提问，不得推测后继续 |
| 3 | **禁止清单优先级最高** | 即使需求说明书或页面详设暗示了某做法，只要在禁止清单中，一律禁止 |

## 5. 代码标记制速查

页面详设中的每一处代码改造点都带有以下标记之一。**AI 处理任务时，只处理目标标记，不触碰其他标记的内容。**

| 标记 | 含义 | 开发动作 | 是否改动代码 |
| --- | --- | --- | --- |
| `【保留】` | 生产可用，原样不动 | 禁止改动 | 否 |
| `【改造】` | 结构可用，数据/逻辑为mock 或硬编码 | 按契约替换数据源或逻辑 | 是（局部） |
| `【替换】` | 纯演示桩，生产无意义 | 整段重写 | 是（整段） |
| `【补齐】` | 生产必需但原型缺失 | 新增 | 是（新增） |
| `【缺口】` | 需求要求但原型未实现 | 新增，附验收断言 | 是（新增） |

配套的**代码锚点格式**：`file:///绝对路径#L起-L止`，点击可直接跳转，用于让 AI 精确定位改动位置。

## 7. 文档变更流程

契约文档不是只读的。出现变更需求时，按下述流程，**禁止直接在正文中改写**：

```
① 提交变更  填写「变更申请」：变更点 / 原因 / 影响面（涉及哪些契约、哪些页面）
② 影响评估  列出所有受影响的契约条目与页面详设编号
③ 统一修订  在正文修改 + 在 appendix/E-变更记录.md 追加一行记录
④ 同步任务卡 检查 13-任务卡集.md 中引用了该契约的任务卡是否需同步更新
```

变更记录必须包含：日期、变更内容、影响的契约编号、影响的页面编号、提出人。

> ⚠️ **注意**：遗留问题台账是 `appendix/D-遗留问题台账.md`，变更记录是 `appendix/E-变更记录.md`（批次 6 产出），两者不要混淆。

## 9. 术语速查

| 术语 | 含义 |
| --- | --- |
| Plot | 地块，最小种植单位 |
| Batch | 批次，溯源最小单位 |
| Adoption | 认养，消费者购买"一棵树"的权益 |
| Store | 本地数据层，全局对象，负责读写 localStorage。本项目共 6 个 PC Store + MobileStore + MobileBridge + H5Auth |
| 契约 | 本文档中一条可判定真伪的约定，含字段、规则、验收标准 |
| 任务卡 | 一张自包含的 AI 编程会话输入，含边界、禁止项、验收 |
| 代码标记 | `【保留】``【改造】``【替换】``【补齐】``【缺口】` 五级改造分类 |
| 两级回退 | 读权威源 → 解析失败回退种子 → **绝不回写权威源** |
| 生产替换点 | 接入后端时需替换的代码位置，集中在 Store 内部，页面无需改动 |
| 架构边界 | 「无构建纯静态」前提下固有、且不应修复的限制（L-1 / L-9） |
| 死代码 | 无引用 / 无写入方 / 定义后从未调用的代码 |
| DoD | Definition of Done，见 `14-测试与验收契约.md` |

完整术语表见 `appendix/A-术语表.md`。
