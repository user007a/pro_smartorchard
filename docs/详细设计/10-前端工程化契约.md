### 1.3 新增文件流程

```
① 确认是否真的需要新文件（优先复用现有 6 个 CSS / 30 个 JS）
② 归类到正确的目录（common/ 影响 153 页，需任务卡授权）
③ 命名符合规范
④ 在本页登记
⑤ 若为 Store，补充 04-存储契约.md + 03-数据契约.md
```

**禁止**：为了「让代码更清晰」而把内联 `<style>` 或 `<script>` 抽到新文件。这属结构重构，须走变更流程。

## 2. `<script>` 加载顺序（🔴 强制）

### 2.1 PC 后台页面标准顺序

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>页面标题 - 智慧果园</title>

  <!-- ① 登录守卫（仅 index.html 需要，必须在所有样式/脚本之前） -->
  <script>/* sessionStorage 检查，未登录立即 replace */</script>

  <!-- ② 第三方 CDN -->
  <script src="vendor/tailwind.min.js"></script>
  <script src="https://code.iconify.design/3/3.1.1/iconify.min.js"></script>

  <!-- ③ CSS -->
  <link rel="stylesheet" href="css/design-system.css">
  <link rel="stylesheet" href="css/sidebar-layout.css">
  <link rel="stylesheet" href="css/page-content.css">
  <link rel="stylesheet" href="css/unified-theme.css">
  <link rel="stylesheet" href="css/typography.css">
</head>
<body>
  <!-- ④ 页面内容 -->

  <!-- ⑤ 数据层（Store / Bridge） -->
  <script src="js/shared/mobile-bridge.js"></script>

  <!-- ⑥ 组件层（二选一，见下） -->
  <script src="js/components/modal.js"></script>
  <script src="js/components/confirm.js"></script>
  <!-- 或 -->
  <script src="js/common-functions.js"></script>

  <!-- ⑦ 工具层 -->
  <script src="js/page-actions.js"></script>
  <script src="js/search-helper.js"></script>
  <script src="js/export-helper.js"></script>
  <script src="js/icons.js"></script>
  <script src="js/typography.js"></script>

  <!-- ⑧ 页面内联脚本（业务逻辑） -->
  <script>/* 页面专属代码 */</script>

  <!-- ⑨ iframe 环境适配（必须在最后） -->
  <script src="js/iframe-hide.js"></script>
</body>
```

### 2.2 🔴 三条铁律

| # | 铁律 | 违反后果 |
| --- | --- | --- |
| **1** | **`components/modal.js` 与 `common-functions.js` 二选一** | `SyntaxError: Identifier 'Modal' has already been declared` → 该页所有内联脚本失效 |
| **2** | **`iconify.min.js` 必须在 `icons.js` 之前** | `Icons.icon()` 依赖 `Iconify` 全局对象，顺序反了图标不渲染 |
| **3** | **`iframe-hide.js` 必须在 `</body>` 前最后** | 它要隐藏 `.sidebar`/`.topbar`，DOM 未就绪时执行会找不到元素 |

### 2.3 为什么 `iframe-hide.js` 必须放最后

```javascript
// js/iframe-hide.js L15
if (window.self === window.top) return;   // 独立打开时不做任何事

// 立即查询 DOM，不等 DOMContentLoaded
document.querySelectorAll('.sidebar')    // 若在 head 中执行 → 找不到，隐藏失效
```

### 2.4 移动端页面标准顺序

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
  <title>页面标题 - 智慧果园</title>
  <link rel="stylesheet" href="css/mobile-design-system.css">
</head>
<body>
  <!-- 页面内容 -->
  <script src="js/mobile-store.js"></script>
  <script>/* 页面业务逻辑 */</script>
</body>
```

### 2.5 H5 页面标准顺序

```html
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
  <title>页面标题 - 智慧果园</title>
  <link rel="stylesheet" href="../applefarm_mobile/css/mobile-design-system.css">
  <!-- ② 按需引数据层 -->
  <script src="js/h5-auth.js"></script>
  <script src="js/mall-products.js"></script>
</head>
```

> ⚠️ H5 **必须**用 `viewport-fit=cover` + `env(safe-area-inset-*)`，否则刘海屏底部按钮被遮挡。

## 3. 代码风格

### 3.1 强制约定

```javascript
// ✅ 正确
var STORAGE_KEY = 'smartorchard_material_store_v1';   // 常量全大写下划线
function readStored() { }                             // 函数驼峰
var subscribers = [];                                 // 变量驼峰

// ❌ 错误
var storageKey = 'xxx';        // 常量不用全大写
function ReadStored() { }       // 函数不用驼峰
```

### 3.2 ES 特性边界

| 特性 | 允许 | 说明 |
| --- | --- | --- |
| `var` / `let` / `const` | ✅ | 全项目混用，新代码用 `const`/`let` |
| 箭头函数 `=>` | ✅ | 478 处已在用 |
| 模板字符串 `` ` `` | ✅ | 824 处已在用 |
| `Array.map/filter/find/some` | ✅ | — |
| `Object.assign` | ✅ | Store 浅合并依赖 |
| `Promise` / `.then` | ✅ | 必须用 `.then`，不用 `async/await` |
| `fetch` | ⚠️ | 仅接入后端后使用 |
| **`??` 空值合并** | ❌ | **本项目零使用，禁止引入** |
| `?.` 可选链 | ⚠️ | 需确认目标 WebView 支持 |
| `async` / `await` | ❌ | 新代码禁用（现有 10 处为特定场景） |
| `import` / `export` | ❌ | `file://` 下不可用 |
| 动态 `import()` | ❌ | 同上 |
| 默认参数 `function f(a = 1)` | ✅ | `common-functions.js` 在用 |
| 展开 `...` | ✅ | Store 浅合并在用 |
| 模板字符串嵌套 | ⚠️ | 避免多层嵌套 |

> **`??` 为什么禁用**：现有代码统一用 `a || b` 或 `a ? a : b`。引入 `??` 会导致两种等价写法并存，后续维护者无法判断哪个是刻意选择。**风格一致性优先于语法便利性。**

### 3.3 注释规范

```
必须写：
  - 文件头的功能说明 + 存储 key + 对外 API 清单
  - 跨端依赖说明（读什么 key、写什么 key）
  - 生产替换点（接入后端时改哪里）
  - 反直觉的逻辑原因（为什么这样写）

禁止写：
  - 解释"这行代码做了什么"（代码本身已表达清楚）
  - 注释掉的死代码（直接删）
  - TODO / FIXME（进任务卡，不留在代码里）
  - 变更日期注释（由 git 负责）
```

**范本**（现有 Store 文件的注释风格）：

```javascript
/**
 * 农资共享仓库（农资管理模块）
 * ------------------------------------------------------------
 * 让"农资信息 / 农资库存 / 农资出入库 / 农资退货 / 农资使用"共享同一份
 * 农资库存数据，实现出入库、退货、使用对库存的联动，并持久化到浏览器
 * localStorage，跨页面刷新后仍保持同步。
 *
 * 所有读写均直取 localStorage（无内存缓存），因此多个标签页/子页同时打开时，
 * 任一处对库存的改动都能被其他页面即时读到，不再出现各自维护一份旧副本的问题。
 *
 * 用法：
 *   MaterialStore.all()                     获取农资主数据（含当前库存）
 *   MaterialStore.applyDelta(identifier, ±n) 增减库存，不足时为 ok:false
 *
 * 生产替换点：readStored() / persistList() → REST
 */
```

### 4.3 样式书写规范

```css
/* ✅ 用 token */

border-radius: var(--radius-md);

/* ❌ 硬编码 */
```

**例外**（可接受硬编码）：

```
① 内联 SVG 的 fill / stroke（改造成本过高）
```

**空态写法**：


用 `hidden` 属性而非内联 `style.display`，避免内联样式。

## 5. 图标规范

### 5.1 标准写法

```html
<!-- ✅ 推荐：直接写 data-icon（index.html 的做法，117 处） -->
<span class="iconify" data-icon="ri:home-4-line"></span>
```

**不推荐** `Icons.icon()` / `data-uicon`：全站 0 处使用，属死代码。

### 5.2 图标命名来源

`data-icon` 的值遵循 **Remix Icon** 格式：`{集合}:{图标名}-line`

常用集合：`ri`（Remix Icon）· `bi`（Bootstrap Icons）· `mdi`（Material Design Icons）

### 5.3 尺寸约定

`typography.js` 的 `alignIcons()` 会把图标尺寸设为「相邻文本字号 + 2px」，收敛到 14/16/18/20 四档。

**因此**：不要给图标写死 `font-size`，让它跟随文本。

## 6. 提交规范

### 6.1 Git 约定

```
✅ 允许：git add <明确的文件路径>
❌ 禁止：git add -A / git add .（可能误加 .env、密钥、大文件）
❌ 禁止：git commit --amend（除非明确要求）
❌ 禁止：git push --force / git reset --hard（未经用户明确要求）
```

### 6.2 提交前自检

```
□ 无 console.log / debugger
□ 无注释掉的死代码
□ 无硬编码颜色（内联 SVG 除外）
□ 无新增全局变量与已有冲突
□ 未同时引入 modal.js 与 common-functions.js
□ iframe-hide.js 在最后
□ 页面实测无 console 报错
□ 验收断言全绿
□ 改动范围未超出任务卡清单
```

### 6.3 提交信息格式

```
类型: 简述

类型 ∈ {feat 新功能, fix 缺陷, refactor 重构, style 样式, docs 文档, chore 杂项}
```

示例：

```
fix: 修复基地管理页面分页容器 id 与规范不一致
fix: 修复移动端巡园页跨基地打卡状态串台
feat: 农事记录页接入 MobileBridge 数据源
```
