# 09 · 组件与交互契约

> **本章作用**：定义每个组件的**方法签名、DOM 结构、CSS 类名**。
> **⚠️ 本项目组件存在多套实现且互相冲突。本章的第一要务是告诉你「该用哪一套」。**

---

## 0. 选型决策表（先看这个）

| 组件 | ✅ 应该用 | ❌ 不要用 | 原因 |
| --- | --- | --- | --- |
| **Modal** | `components/modal.js` 的 `Modal` | `common-functions.js` 的 `LegacyModal` | 前者动态创建 DOM、可配置；后者只能操作静态 HTML |
| **Toast** | 二者之一（同页只能选一套） | — | 位置与默认 type 不同，见 §2.3 |
| **Confirm** | `components/confirm.js` 的 `Confirm`（Promise） | `LegacyConfirmDialog`（回调） | Promise 更好组合；且 Legacy 的按钮文案硬编码「确认删除」 |
| **Pagination** | `common-functions.js` 的 `Pagination` | ⚠️ **11 个页面内联重复声明了同名 `const Pagination`** | 见 §4.3 |
| **Table** | `PageActions.renderTable` | 各页面自写 | — |
| **Form** | `Modal.form({fields:[...]})` | 各页面自写 | — |

### 0.1 🔴 全局命名冲突（最高频事故）

```
js/components/modal.js     第 14 行  const Modal = ...
js/components/modal.js     第 442 行 const Toast = ...
js/common-functions.js     第 52 行  const Modal = ...
js/common-functions.js     第 264 行 const LegacyToast = ...
```

**同页引入两者 → `SyntaxError: Identifier 'Modal' has already been declared` → 该页所有内联脚本整体失效。**

**实测加载分布（95 个 PC 页面）**：

| 文件 | 加载页数 | 代表页 |
| --- | --- | --- |
| `js/components/modal.js` | **23** | `enterprise_plot` `data_source` `device_access` |
| `js/common-functions.js` | **65** | `mall_product` `adoption_cert` `material_usage` |
| `js/components/confirm.js` | **16** | `device_access` `patrol_route` |
| **同时加载 modal.js + common-functions.js** | **0** | ✅ 现状无此问题 |

**新页面该选哪套**：

```
① 参照同模块已有页面（最重要）
② 需要动态弹窗（内容运行时决定）→ components/modal.js
③ 弹窗是静态 HTML（写在页面里）→ common-functions.js
④ 不确定 → 用 common-functions.js（65 页的主流）
```

> `common-functions.js` 末尾有防覆盖兜底：`Modal` / `Toast` / `ConfirmDialog` **仅在 `typeof window.X === 'undefined'` 时**才挂 Legacy 版本。所以 `components/*` 是权威实现，`common-functions.js` 是兜底。

## 1. Modal 弹窗

### 1.1 方案 A：`components/modal.js`（组件版，推荐）

**全局对象**：`window.Modal`

**方法签名**：

```javascript
Modal.open(options) → HTMLElement(overlay)
  options: {
    title:      '提示',
    content:    '',            // HTML 字符串
    footer:     '',            // HTML 字符串，空则不渲染 footer
    width:      '560px',
    showClose:  true,          // 右上角 X
    closeOnOverlay: true,      // 点遮罩关闭
    closeOnEsc: true,          // ESC 关闭
    onClose:    null,
    animClass:  'modalIn'
  }

Modal.close(callback, animate = true)      // 无返回值
Modal.loading(text = '加载中...')          // → overlay，强制不可关
Modal.hideLoading()                       // = Modal.close()
Modal.form(options) → overlay
  options: {
    title: '表单', fields: [], values: {},
    submitText: '提交', cancelText: '取消',
    onSubmit(data),// 返回 !== false 才关闭
    onCancel(),
    onRender(modal),                    // 渲染后钩子，用于绑定自定义控件
    width: '520px'
  }
Modal.detail(title, data, options = {fields, width: '600px'})
Modal.success(message, duration)        // 内部转发 Toast.show，duration 被忽略
Modal.error / warning / info(...)
```

**DOM 结构**：

```html
<div class="modal-overlay" data-modal="true">      <!-- rAF 后加 .show -->
  <div class="modal-box" style="max-width: {width}">
    <div class="modal-header">
      <h3 class="modal-title">{title}</h3>
      <button class="modal-close" data-action="close"><svg…/></button>
    </div>
    <div class="modal-body">{content}</div>
    <div class="modal-footer">{footer}</div>     <!-- footer 空则不渲染 -->
  </div>
</div>
```

**CSS 类名**：`modal-overlay`（`.show`）· `modal-box`（动画 `modalSlideIn`）· `modal-header` · `modal-title` · `modal-close` · `modal-body` · `modal-footer`

**关闭方式**：右上角 X（`showClose`）· 点遮罩（`closeOnOverlay`）· ESC（`closeOnEsc`）· `Modal.close()`

> **⚠️ 无内置确认/取消回调。** footer 按钮由调用方写 HTML，再用 `querySelector('[data-action="…"]')` 自行绑定。

**三个必须知道的坑**：

```
① 单例设计：open() 会先 close(null, false) 强关上一个弹窗
   → modalStack 永远只有 1 层，不支持弹窗叠弹窗
② close() 动画延时 200ms 才 destroy()
   → 期间 .show 已移除但节点仍在 DOM，此时 open() 新弹窗可能与之重叠
③ Modal.open() 全站 0 处直接调用
   → 实际只经由 Modal.form()（7 处）、Confirm.*、PageActions.showDetail/showEdit 间接产生
```

**使用示例**（来自 `PageActions.showCreate`）：

```javascript
Modal.form({
  title: '新建地块',
  fields: [ /* 见 §6 */ ],
  submitText: '创建',
  width: '580px',
  onRender: bindEnterpriseFormInteractions,
  onSubmit: function (formData) {
    Toast.show('创建成功', 'success');
    return true;              // 返回 true 才关闭
  }
});
```

### 1.2 方案 B：`common-functions.js` 的 `LegacyModal`

**全局对象**：`window.LegacyModal`（`window.Modal` 是其别名，仅在权威实现缺席时）

```javascript
LegacyModal.show(modalId)     // 对页面里已存在的静态弹窗加 .show
LegacyModal.hide(modalId)
LegacyModal.hideAll()
```

**DOM 结构**：**不生成 DOM**，只操作静态 HTML 的 class。

```html
<!-- 写在页面里的静态弹窗 -->
<div class="modal-overlay" id="xxxModal">
  <div class="modal-box">
    <div class="modal-header">
      <h3 class="modal-title">标题</h3>
      <button class="modal-close">&times;</button>
    </div>
    <div class="modal-body">…</div>
    <div class="modal-footer">
      <button class="btn btn-secondary" onclick="Modal.hide('xxxModal')">取消</button>
      <button class="btn btn-primary" onclick="saveXxx()">确定</button>
    </div>
  </div>
</div>
```

**全局事件委托**（`DOMContentLoaded` 时注册）：

```javascript
// 点击 .modal-close 或 .modal-overlay 自身 → 移除 .show
e.target.closest('.modal-close')
e.target.classList.contains('modal-overlay')
// ESC → LegacyModal.hideAll()
```

**两套方案对比**：

| 维度 | `Modal.open()` | `LegacyModal.show()` |
| --- | --- | --- |
| 形态 | 动态创建 DOM | 操作静态 HTML |
| 参数 | options 对象 | modalId 字符串 |
| 宽度/动画 | 可配 | 靠 CSS |
| 事件绑定 | 自绑定 | 全局委托 |
| 确认回调 | ❌ 无 | ❌ 无 |
| 适用 | 内容运行时决定 | 固定内容 |

## 2. Toast 提示

### 2.1 方案 A：`components/modal.js` 的 `Toast`（23 页）

```javascript
Toast.show(message, type = 'info', duration = 2000)
// type: 'success' | 'error' | 'warning' | 'info'
// 图标：✓ ✕ ⚠ ℹ
```

**DOM 结构**：

```html
<div class="toast-container">          <!-- 固定 top:24px right:24px, z-index:9999, flex column gap:8px -->
  <div class="jg-toast success">
    <span class="jg-toast-icon">✓</span>
    <span class="jg-toast-message">创建成功</span>
  </div>
</div>
```

| 项 | 值 |
| --- | --- |
| 位置 | **右上角** |
| 入场动画 | `@keyframes slideInRight 0.3s ease` |
| 消失 | JS 内联 `opacity=0` + `translateX(100%)`，**无 `.show` 类** |
| 可手动关闭 | ❌ 无关闭按钮 |
| 默认时长 | 2000ms |

### 2.2 方案 B：`common-functions.js` 的 `LegacyToast`（65 页）

```javascript
LegacyToast.show(message, type = 'success', duration = 3000)
LegacyToast.success(message)
LegacyToast.error(message)
LegacyToast.warning(message)
LegacyToast.info(message)
```

**DOM 结构**：

```html
<div class="toast toast-success show">
  <div class="toast-icon">✓</div>
  <span class="toast-message">创建成功</span>
</div>
```

| 项 | 值 |
| --- | --- |
| 位置 | **顶部居中**（`top:24px; left:50%; translateX(-50%)`） |
| 入场动画 | 靠 `.show` 类 |
| 默认 type | **`success`** |
| 默认时长 | 3000ms |

### 2.3 两套差异（⚠️ 跨页复制代码会出问题）

| 维度 | `Toast` | `LegacyToast` |
| --- | --- | --- |
| 位置 | 右上角 | 顶部居中 |
| 默认 type | `info` | `success` |
| 默认时长 | 2000ms | 3000ms |
| 便捷方法 | ❌ **只有 `show()`** | ✅ `.success()/.error()/.warning()/.info()` |
| 类名前缀 | `jg-toast` | `toast` |

**⚠️ `Toast.show` 全站 396 次 / 60 页**，但因两套默认 type 不同，跨页复制代码会出现**提示语义与样式不一致**（同一个 `Toast.show('已删除')` 在 A 页面是蓝色 info，在 B 页面是绿色 success）。

**⚠️ `Toast`（权威版）没有 `.success()/.error()` 便捷方法**，组件页普遍自建包装函数：

```javascript
// enterprise_plot.html:948 的做法
function plotToast(msg, type) { Toast.show(msg, type || 'success'); }
```

**改造建议**：统一到一套。推荐全部使用 `LegacyToast` 的调用形式（有便捷方法），但底层用 `Toast.show`。

## 3. ConfirmDialog 确认框

### 3.1 方案 A：`components/confirm.js` 的 `Confirm`（16 页，Promise）

```javascript
Confirm.open(message, options = {}) → Promise<boolean>
  options: {
    title: '确认操作',
    confirmText: '确定',
    cancelText: '取消',
    confirmClass: 'jg-btn-primary',
    cancelClass: 'jg-btn-secondary',
    danger: false,// ⚠️ true 时自动改 confirmClass 为 jg-btn-danger
    icon: null,
    width: '400px'
  }

Confirm.delete(message = '确定要删除吗？此操作不可撤销。') → Promise
  // 🗑️ 等价于 danger: true，标题「删除确认」，按钮「删除」

Confirm.success(message, options) → Promise
  // cancelText: null → 单按钮「我知道了」

Confirm.warning(message, options) → Promise   // danger: true

Confirm.batch(message, {count, itemName, …}) → Promise
```

**使用示例**：

```javascript
Confirm.delete('确定要删除地块「' + row.name + '」吗？')
  .then(function (ok) {
    if (!ok) return;
    // 执行删除
  });
```

| 项 | 值 |
| --- | --- |
| DOM / 类名 | 同 Modal（`modal-overlay` / `modal-box` / `modal-header` …） |
| footer | `jg-btn` + `cancelClass` / `confirmClass`，带 `data-action="cancel|confirm"` |
| `cancelText: null` | **不渲染取消按钮** |
| 点遮罩 | ❌ 固定 `closeOnOverlay: false` |
| ESC | ✅ 可关 |

### 3.2 方案 B：`confirm.js` 的 `ConfirmDialog` 别名（回调式，⚠️ 危险默认值）

```javascript
ConfirmDialog.show({ title, message, confirmText = '确定',
                     danger = true,   // ⚠️⚠️ 默认 true！
                     onConfirm })
```

**🔴 高危陷阱**：`danger` 默认为 `true`，所以 `ConfirmDialog.show` **默认渲染红色删除按钮**。全站约 34 处、30 个页面用这个写法。

**修正方式**：

```javascript
// 🔴 现状（危险操作与普通确认无法区分）
ConfirmDialog.show({ message: '确定要删除吗？', onConfirm: del });

// ✅ 应改为（显式声明 danger）
ConfirmDialog.show({ message: '确定要删除吗？', danger: true, onConfirm: del });
ConfirmDialog.show({ message: '确定提交吗？', danger: false, onConfirm: submit });
```

**或直接改用方案 A**（`Confirm.open` 的 `danger` 默认 `false`，更安全）。

### 3.3 方案 C：`common-functions.js` 的 `LegacyConfirmDialog`（65 页）

```javascript
LegacyConfirmDialog.show({ title, message, onConfirm, onCancel })  // 返回 undefined
LegacyConfirmDialog.hide(btn)   // btn.closest('.modal-overlay').remove()
```

**DOM**：`.modal-overlay.show > .modal-box(max-width:420px) > .modal-header/.modal-body/.modal-footer`

**⚠️ 问题**：

```
① 图标固定 ⚠（36px），无法改
② 按钮文案硬编码「取消」/「确认删除」← 后者恒为 jg-btn-danger，无法做普通确认
③ 无 Promise、无遮罩关闭、无 ESC
```

### 3.4 三套对比与选型

| 维度 | `Confirm.*` | `ConfirmDialog.show` | `LegacyConfirmDialog.show` |
| --- | --- | --- | --- |
| 形式 | **Promise** | 回调 | 回调 |
| `danger` 默认 | `false` ✅ | **`true`** ⚠️ | 恒为危险 |
| 按钮文案可配 | ✅ | ✅ | ❌ 硬编码 |
| 单按钮模式 | ✅ | ❌ | ❌ |
| 点遮罩关闭 | ❌ | ❌ | ❌ |
| 使用处数 | 6 | 34 | 其余 |

**推荐**：新增代码统一用 `Confirm.*`。⚠️ `enterprise_plot.html:1312` 用 `typeof ConfirmDialog !== 'undefined'` 做防御，说明开发者自己也不确定该用哪套。

## 4. Pagination 分页

### 4.1 `common-functions.js` 的 `Pagination`（权威）

```javascript
Pagination.init(options)
  options: {
    currentPage: 1,
    pageSize: 10,
    totalRecords: 0,
    data: [],
    containerId: 'pagination-container',   // 默认 id
    tbodyId: 'dataTableBody',
    renderRow: null                       // function(item, index) → HTML
  }

Pagination.render()                          // 渲染分页条 + 调 renderTable()
Pagination.renderTable()                     // tbody.innerHTML = filteredData.slice(...).map(renderRow(item, idx))
Pagination.goToPage(page)                    // 越界 return，否则 currentPage = page 后 render()
Pagination.updateData(data)                  // filteredData = data; currentPage = 1; render()
Pagination.filter(keyword, fields)           // 按 fields 数组过滤（⚠️ 依赖 this._originalData，init 中未赋值）
```

**实例字段**：`currentPage` / `pageSize` / `totalRecords` / `filteredData` / `containerId` / `tbodyId` / `renderRow`

**DOM 结构**：

```html
<div id="{containerId}">
  <div class="pagination">
    <button class="page-btn" onclick="Pagination.goToPage(1)">‹</button>
    <button class="page-btn active" onclick="Pagination.goToPage(1)">1</button>
    <button class="page-btn" onclick="Pagination.goToPage(2)">2</button>
    <span class="page-ellipsis">...</span>
    <button class="page-btn" onclick="Pagination.goToPage(3)">3</button>
    <button class="page-btn" onclick="Pagination.goToPage(5)">›</button>
    <span>第 2 页/共 5 页，共 47 条记录</span>
  </div>
</div>
```

**分页文案**：`第 {currentPage} 页/共 {totalPages} 页，共 {totalRecords} 条记录`

**页码省略规则**：首页 / 末页 / 当前页 ±1 直出，±2 处输出 `...`

**CSS 类名**：`pagination` · `page-btn`（+ `active` `disabled`）· `page-ellipsis`

> ⚠️ `Pagination.filter()` 依赖 `this._originalData`，但 `init()` 中**未赋值**该字段 → 调用会出错。这是死方法。

### 4.2 `page-actions.js` 内部的 `renderPagination`

```javascript
renderPagination(total, current, containerSelector)   // 内部函数，未导出
sliceByPage(list)                                       // 内部函数，未导出
changePage(page)                                        // 已导出
```

**与 `Pagination.render()` 的差异**：`page-actions` 版本不接管表格渲染（只渲染分页条），数据切片由 `sliceByPage` 独立处理。

### 4.3 🔴 28 份分页实现拷贝（最高优先级的技术债）

| 事实 | 数据 |
| --- | --- |
| `Pagination.render()` 被调用 | **1 处**（`enterprise_plot.html:1204`） |
| `Pagination` 相关代码出现 | **28 个页面共 141 处** |
| 其中**内联重复声明 `const Pagination`** | **11 个页面** |

**11 个重复声明的页面**：

```
cert_manage.html:490        device_access.html:299      enterprise_base.html:364
enterprise_plot.html:643    gateway_config.html:319     trace_batch.html:352
trace_blockchain.html:314   trace_code.html:540         trace_config.html:285
trace_query.html:484           video_monitor.html:715
```

这些副本与 `common-functions.js` 版本**近乎逐字复制**（仅少数差异，如 `device_access.html` 的 `renderRow(item, start+i+1)` 序号从 1 起）。

**🔴 连带问题**：由于内联 `const Pagination` 与 `common-functions.js` 的 `const Pagination` 同名，**这 11 个页面不可能同时引入 `common-functions.js`**（会触发重复声明）。

**另外约 17 个页面**（`alert_*` / `harvest_*` / `farming_*` 等）**不重复声明**，直接用全局版，调 `Pagination.init/updateData`。

**改造影响**：

```
⚠️ 改分页样式或文案，必须逐页改（约 28 处），不能只改 common-functions.js
⚠️ 这 11 个页面若要改用全局版，必须先删除其内联 const Pagination
⚠️ 统一分页是批次 3~5 的跨页改造任务，需单独开任务卡（TC-PAG-001）
```

### 4.4 分页的强制规范

```
① 容器 id 必须是 pagination-container（4 种历史变体统一，见 02章 §4.1）
② 分页组件必须位于 data-section 卡片内部
③ 分页文案统一为「第 X 页/共 Y 页，共 Z 条记录」
④ 按钮区（action-bar）不显示记录条数，只在底部分页栏体现
⑤ 每页默认 10 条
⑥ 禁止在页面内联 const Pagination（会与全局冲突）
```

## 5. Table 表格

### 5.1 `PageActions.renderTable`

```javascript
PageActions.renderTable(data, columns, containerSelector)   // 无返回值
```

**`columns` 元素结构**：

```javascript
// ⚠️ 是 field / label，不是 key / title
{ field: 'name',  label: '地块名称' }
{ field: 'area',  label: '面积', render: function (value, row) { return value + ' 亩'; } }
{ field: 'status', label: '状态', type: 'status', statusType: 'plot' }
{ field: 'act',  label: '操作', type: 'action',
  render: function (row) { return '<button …>查看</button>'; } }
```

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `field` | string | 数据字段名 |
| `label` | string | 表头文字 |
| `render` | function | `(value, row) => HTML`，可选 |
| `type` | string | `'status'` / `'action'`，可选 |
| `statusType` | string | 状态类型（`getStatusText(status, type)` 用） |

**⚠️ 不支持**：`width` / `align` / `sortable`（表头是纯 `<th>`，不渲染 `col.width`）

### 5.2 `renderRowHtml` 输出结构（内部函数）

```html
<tr data-id="{row.id}" data-index="{index}">
  <td>{index + 1}</td>                              <!-- 序号列，固定 width:60px -->
  <td>{col1}</td>
  <td>{col2}</td>
  …
  <td>
    <div class="action-btns">
      <button class="action-btn" onclick="PageActions.showDetail('{id}')">查看</button>
      <button class="action-btn" onclick="PageActions.showEdit('{id}')">编辑</button>
      <button class="action-btn delete" onclick="PageActions.deleteItem('{id}')">删除</button>
    </div>
  </td>
</tr>
```

**CSS 类名**：`.data-table` · `.action-btns` · `.action-btn`（+ `.delete`）· `.status-tag`（+ `success|warning|disabled|error`）

**状态辅助函数**（内部，未导出）：

```javascript
getStatusText(status, type = 'default')   // status → 中文
getStatusClass(status)                     // status → class 后缀
```

### 5.3 🔴 三种状态都无统一实现

| 状态 | `renderTable` 的行为 | 现状 |
| --- | --- | --- |
| **空数据** | 空数组直接渲染出只有表头的空 tbody | 各页面自建 `<div class="empty-state" style="display:none">暂无…</div>` + `display` 切换 |
| **加载中** | ❌ 无处理 | 仅 `Modal.loading()` 内的 `.loading-spinner` |
| **错误** | ❌ 无处理 | **全站 0 处命中 `error-text` / `form-error`** |

**空态的现有做法**（参考 `adoption_cert.html:313` / `drone_log.html:204`）：

```html
<div id="xxxEmpty" class="empty-state" style="display:none;">暂无数据</div>
```

```javascript
emptyEl.style.display = list.length ? 'none' : 'block';
```

**⚠️ 这是技术债**：95 个页面各写一套空态，样式与文案不统一。批次 4/5 详设时应统一为：

```html
<div id="xxxEmpty" class="empty-state" hidden>暂无数据</div>
```

用 `hidden` 属性而非 `style.display`，避免内联样式。

## 7. 其它通用能力

### 7.1 `search-helper.js` — 🔴 与文档不符

**实际导出**（**没有 `Search.init()`**）：

```javascript
window.smartSearch()    // 按 FN_PRIORITY 探测并调用页面自身筛选函数
window.smartReset()     // 清空 .search-bar / .search-section 内 text/search/date/select 后重跑
```

**探测优先级数组**（`FN_PRIORITY`）：

```
handleSearch → search → filterData → applyFilter → doSearch
→ searchData → filterByStatus → renderTable
→ renderCertTable → renderQueryTable → renderPlotTable
```

命中 `window[name]` 首个存在的函数即调用。兜底：`Toast.show('提示', '当前页面暂无筛选逻辑')`。

**⚠️ 实用率极低**：全站仅 1 处 HTML 引用（`drone_log.html`）。

**🔴 存在两个同名不同实现的 `Search`**：

| 实现 | 文件 | 方法 | 调用情况 |
| --- | --- | --- | --- |
| `Search` | `common-functions.js:185` | `.execute({searchInput, filters, onSearch})` / `.getFormData(formId)` / `.resetForm(formId)` | ❌ **零调用** |
| `smartSearch` / `smartReset` | `search-helper.js` | 见上 | 1 处 |

**改造建议**：新页面不要用 `search-helper.js`（探测机制不可控，AI 难以预测会调用哪个函数）。**直接在页面内定义 `window.handleSearch` 或 `window.search`**，`search-helper.js` 会自动探测到。

### 7.2 `export-helper.js` — ⚠️ 仅 5 处调用（采收模块）

```javascript
ExportHelper.exportData({ headers = [], rows = [], filename = 'export', format })
  → Promise<'csv' | 'excel' | 'csv-fallback'>
ExportHelper.stamp()  // 'YYYYMMDD'
```

| `format` | 行为 |
| --- | --- |
| 非 `'excel'` | 原生 Blob CSV（含 `\ufeff` BOM 防 Excel 中文乱码） |
| `'excel'` | 懒加载 CDN SheetJS（`xlsx@0.18.5`），失败自动回退 CSV |

**⚠️ 两种导出实现并存**：

| 实现 | 使用方 |
| --- | --- |
| `ExportHelper.exportData()` | **5 个采收页面**：`harvest_plan:644` `harvest_post:614` `harvest_process:550` `harvest_record:821` `harvest_storage:460` |
| `PageActions.exportData()`（手写 Blob） | 其余页面的 `PageActions.init('*')` 默认导出 |

**改造建议**：统一到 `ExportHelper`（有 Excel 支持与 BOM 处理），删除 `PageActions.exportData` 的手写实现。

### 7.3 图标 — 两文件实为一源

**`js/icons.js`（权威）**：

```javascript
window.Icons = {
  map,                      // ~66 个语义常量 → Remix Icon 名
  icon(name, cls),          // 返回 '<span class="iconify [cls]" data-icon="ri:xxx-line">'
  mount(root)               // 扫描 [data-uicon] 替换为 data-icon 并调 Iconify.scan()
}
```

**依赖**：`https://code.iconify.design/3/3.1.1/iconify.min.js`（**须在其之前引入**）

**`icons/icons.js`**：**纯转发别名**，无独立实现。

```javascript
// 用 document.currentScript.src 上溯一级拼出 /js/icons.js
// 在解析阶段用 document.write 同步加载（供移动端以 ../applefarm_backhand/icons/icons.js 引用）
// 已有 script[data-icons-alias] 则跳过
```

**🔴 关键事实**：`Icons.icon()` 与 `data-uicon` 在 95 个后台页中 **0 处使用**。`index.html` 直接写 `data-icon=` **117 处**。**实际图标基本是手写内联 `<svg>`。**

**使用方式**（推荐）：

```html
<!-- ① 直接写（index.html 的做法，最简） -->
<span class="iconify" data-icon="ri:home-4-line"></span>

<!-- ② 走 Icons.mount（需引 icons.js） -->
<span data-uicon="home"></span>
```

### 7.4 `typography.js`

```javascript
window.Typography = {
  tokens(),                // 从 CSS 变量读令牌，带兜底值
  chart(),
  alignIcons(root),        // 图标尺寸 = 相邻文本字号 + 2px，收敛到 14/16/18/20 四档
  tabularNums(root),       // 给 .stat-value/.metric-value/.num/.amount/.money/.percent/.code 加等宽数字
  refresh(root)
}
```

**不加载字体文件**，只从 `css/typography.css` 的 CSS 变量读取（`--u-font-sans` / `--u-fs-*` / `--u-c-text*` / `--u-c-primary`）。

**两个机制**：

```javascript
// ① 首次 refresh() 后派发
document.dispatchEvent(new CustomEvent('typography:ready'));

// ② 捕获阶段全局 click 监听（120ms 节流）自动补刷
//    覆盖表格/分页重绘后的新元素
```

**🔴 全站 0 处监听 `typography:ready`，也无人手动调 `Typography.refresh()`。** 靠 ② 的全局 click 监听自动工作。

**`tabularNums` 覆盖的选择器**（改造页面时可用于判断哪些元素会自动获得等宽数字）：

```css
.stat-value, .metric-value, .num, .amount, .money, .percent, .code, .data-table td
```
