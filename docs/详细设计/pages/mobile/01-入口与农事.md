## 1. 入口与农事

### 1.1 模块概述

这 8 页是移动作业端的**入口骨架**与**农事主链路**。三页入口页（登录 / 首页 / 我的）承担身份与导航，5 页农事页（计划 / 记录 / 领用 / 地块 / 画地块）承担作业闭环。它们的共同风险特征与其他批次截然不同：**不是"功能没做"，而是"写操作分散在 4 套互不相通的机制里，登录态只是 sessionStorage 里的三个字符串，地块数据存在三个不同的键上，而统计数字全是硬编码常量"**。

具体表现为四条系统性断裂：

1. **登录态分裂**。`mb_login.html` L1072-L1077 写入 4 个键（`isLoggedIn` / `loginUser` / `loginRole` 在 sessionStorage，`smartorchard_current_user` 在 localStorage），但**除本页外没有任何一页读取它们**——8 页全部不做登录态校验，`mb_mine.html` L758-L760 退出登录时也只删 sessionStorage 的 2 个键，遗留 `loginRole` 与 `smartorchard_current_user`。
2. **地块数据三键并存**。`mb_draw_plot.html` L457 写 `smartorchard_plots`（经 `MobileStore.KEYS.plots`），`mb_plot.html` L837 又额外读一个裸键 `plots`，PC 后台 `enterprise_plot.html` 用的是**第三个键** `smartorchard_plot_master`（L728），`mb_map.html` L224 读的是这个第三键。三者互不相通。
3. **写操作机制不统一**。8 页里同时存在 4 种写法：经 `MobileStore.push/upsert`（MB-005 / MB-006 / MB-008）、直接 `localStorage.setItem`（MB-001 L1020-L1021 / L1075）、`innerHTML` 拼字符串（MB-003 / MB-004 / MB-005）、以及"只读不写但统计数字写死"（MB-002 / MB-003 / MB-004 / MB-007）。
4. **统计数字与列表数据脱钩**。MB-002 的「整体评分 86 / 土壤水分 68% / 近 7 日降雨 18.5mm / 今日价格 ¥1.45 / 28°C」、MB-003 的「农事记录 128 / 管理地块 8 / 巡园次数 156」、MB-004 的 4 个计划、MB-007 的 4 张地块卡全部是 HTML 里的纯文本常量，**不读任何数据源**；其中 MB-007 L887-L908 的 `updateStats()` 只把「静态卡片数 + 手绘地块数」相加，而静态卡片数（4）与静态面积（15+18+22+25=80 亩）仍是从 DOM 文本里反解出来的，与后台真实地块表毫无关系。

- **触发时机**：脚本执行即读；`restoreRemembered()` L842-L852 同步回填 `#username` / `#password` / `#rememberMe`；`checkLogin()` L791-L795 同步判断是否跳首页。
- **无分页、无加载更多**：账号表生产环境来自服务端，登录页不做分页。
- **目标形态**：登录改为服务端一次性校验（`POST /auth/login` 返回 token + profile），账号表**完全不出现在前端**；前端只维护"表单校验 → 提交 → 落会话 → 跳首页"这条最短链路。

#### 10 边界态

- **空数据**：`mb_staff_accounts` 不存在或为空数组 → `loadAccounts()` L812 条件不成立 → 回退 `DEFAULT_ACCOUNTS`（L823-L827），登录**永远可用**。生产环境必须去掉回退，改为"账号表不可用 → 提示联系管理员"。
- **搜索无果**：本页无搜索。对应场景是"输入不存在的账号" → `setError('usernameGroup','usernameError','账号不存在')` L993 + `showErrorToast('账号不存在')` L996，✅ 有明确反馈。
- **字段超长**：`#username` 无 `maxlength`，超长输入仅影响宽度（`.input-group input` L241-L252 无 `text-overflow`）；`#infoBody` 已设 `max-height:52vh; overflow-y:auto`（L765），✅ 长协议可滚动。
- **并发写冲突**：`rememberedUser`/`rememberedPwd` 是"最后写入者胜"；多标签页各持一份登录态（sessionStorage 按标签页隔离），无冲突但也无法共享会话。
- **权限不足**：**无任何角色判断**。`doLogin()` L1064-L1095 不看 `role`，任何账号登录后权限完全相同（`loginRole` 写了就没人读，见 `L-MB1-01`）。
- **未登录拦截**：**反向缺失**——本页不校验是否已登录就放行/跳转，且其余 7 页不校验是否已登录（`L-MB1-01`）。
- **离线**：**无离线分支**。L1004 的密码比对是纯本地操作，离线可用；但生产环境改为服务端校验后，离线必须给"当前离线，无法登录"提示，否则用户会反复重试。
- **锁定边界**：`MAX_ATTEMPTS = 5` / `LOCK_MS = 30000`（L829-L830）。问题有三：① `failCount` 是内存变量，刷新即清零（L831）；② `account.disabled` 分支（L999-L1003）与 `!account` 分支（L992-L998）**都不累加 `failCount` 的锁定判定之外的行为不一致**——前者 `return` 前不加锁、后者加锁；③ 锁定提示在 `errorToast` 里 2 秒消失（L964-L966），没有倒计时组件。

#### 10 边界态

- **空数据**：**本页无空态概念**（9 个面板全部无条件拼字符串）。目标：每个面板补「暂无记录」+ 「去 XX」引导（契约 `C-MB-003-07`）。
- **搜索无果**：本页无搜索。对应场景是"无菜单权限"——当前**任何角色都看到全部 9 个菜单**，无权限过滤（契约 `C-MB-003-05`）。
- **字段超长**：`.mb-list-title`（设计系统 L1259）无 `text-overflow`；`.material-meta`（L295）无 `max-height`；昵称 input（`.form-input` L364）无 `maxlength`。
- **并发写冲突**：本页只删键，无并发问题。
- **权限不足**：**无任何角色判断**。9 个菜单对所有角色可见可点（`L-MB3-13` 同源问题，本页属另一处实现）。
- **未登录拦截**：**无**（`L-MB1-01`）。未登录用户打开本页会看到「张顺发 / 地块负责人」的完整假身份。
- **离线**：本页**无任何离线分支**，也无同步状态栏（未引 `MobileStore`，无 `#syncBar`）。目标：接入 `MobileStore` 后本页应有 `#syncBar`，与其他作业页一致。
- **退出登录后残留**：`doLogout()` L758-L759 只删 2 键，`loginRole` 与 `smartorchard_current_user` 残留 → 重新登录前若其他页面读该键会读到旧身份（`L-MB1-01`）。

#### 10 边界态

- **空数据**：① `#materialList` 空 → 回退 6 条静态兜底（L505-L510）+ `renderStocks()` 标注「后台库存未初始化」（L567）✅；② `#myApplyList` 空 → 「暂无我的申请记录」（L359）✅；③ **但静态兜底被 `renderMyApplies()` 影响**——`#myApplyList`（L197）与 4 条静态 `.record-item`（L199-L245）是**同级兄弟节点**，`renderMyApplies()` 只清 `#myApplyList` 的 innerHTML，**静态 4 条永远显示**（L198 甚至明写了「以下为演示数据」）。
- **搜索无果**：本页无搜索。
- **字段超长**：`.material-name`（L35）无 `text-overflow`；`.material-desc`（L36）无行数限制；`.record-info`（L53）是 `display:flex; justify-content:space-between`，长备注（L381-L383 的拼接串）会撑破容器。
- **并发写冲突**：`MobileStore.push()` L108-L116 是「读全量 → unshift → 写全量」，同键多标签页同时提交会后写覆盖先写（`mobile-store.js` L102-L106 `saveList`）。生产环境应改为服务端写入或按用户分键。
- **权限不足**：**无**。任何用户可提交领用申请；`submitApply()` L572-L617 **无登录态校验、无地块权限校验**——可为他人的地块提交领用申请（且下拉框只有 2 个假地块，`L-MB1-11`）。
- **未登录拦截**：**无**（`L-MB1-01`）。未登录用户提交的申请没有 `operator`，PC 审批时无法判断申请人。
- **离线**：**无离线处理**（未调 `MobileStore.isOnline()` / `enqueue()`）。`MobileStore.subscribe` L626-L629 只监听本地变更。离线提交 → 数据只在本地，**PC 后台不可见**，网络恢复后也不会自动上传（契约 `C-MB-006-05`）。
