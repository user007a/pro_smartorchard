# 附录 E · 变更记录

> **本章作用**：登记本文档体系自身的每一次修订——**谁、何时、改了什么、为什么改、影响了哪些契约条目与页面**。
> **权威依据**：`README.md` §7 文档变更流程 · `13-任务卡集.md` §6 变更控制 · `14-测试与验收契约.md` §2.3 交付检查。
> **数据基线**：本章全部数字为 **2026-10-23 实测**（PowerShell 扫描 `docs/详细设计/`、`html/` 与 `git log`/`git diff` 所得），非估算。未能证实的一律标「待核实」，不补写。

## ⚠️ 与 D-遗留问题台账 的区别（先读这一条）

| 台账 | 回答的问题 | 记录对象 | 生命周期终点 |
| --- | --- | --- | --- |
| `appendix/D-遗留问题台账.md` | **代码/产品层面**哪里不对？ | 契约层核查发现的「代码与契约不符」存量问题（62 条） | 被任务卡修复后关闭 |
| **`appendix/E-变更记录.md`（本章）** | **文档层面**改过什么？为什么改？ | 本套文档的每一次修订流水 | 永久保留（历史不可删） |

两条硬边界：

```
① D 台账记「代码有问题」   → 结论落在 html/ 上，落点是任务卡 TC-*
② E 台账记「文档改过」   → 结论落在 docs/ 上，落点是契约编号 + 页面编号
③ 一条 D 台账条目被修复时，可能触发 3~5 条 E 台账记录（改契约 + 改详设 + 改台账 + 改计数）
④ E 台账中不得出现「某功能有 bug」类描述 —— 那是 D 台账的职责，写在这里即视为登记错位
```

## 0. 变更管理约定

### 0.1 什么算一次变更

| # | 变更类型 | 是否登记 | 示例 |
| --- | --- | --- | --- |
| 1 | **文档新增** | ✅ 登记 | 新增 `14-测试与验收契约.md` |
| 2 | **文档删除** | ✅ 登记（🔴 原则上不删，只标「作废」） | 无先例 |
| 3 | **章节内容修订** | ✅ 登记 | `12` §6.3 键数 152 → 54 |
| 4 | **编号体系调整** | ✅ 登记（额外进 §2） | `mobile/03` 缺陷前缀改为 `L-MB3-*` |
| 5 | **口径统一**（计数类数字） | ✅ 登记（额外进 §3） | PC 页数 95 → 96；localStorage 键 52 → 54 |
| 6 | **裁决记录**（发现事实并定处置） | ✅ 登记（额外进 §4） | 「区块链存证」判为前端自算，定 P0 |
| 7 | 错别字、标点、排版 | ⚪ 不登记 | — |
| 8 | 行号漂移修正（代码被改后锚点位移） | ⚪ 不登记，但**必须在同一条记录的证据栏注明修正前后的行号** | — |
| 9 | 🔴 任何**降低**验收严格度的修改 | ✅ 登记，且必须写明批准人与理由 | — |

> 🔴 **第 8 条的纪律**：本项目所有代码锚点都是 `file:///…#L起-L止`。任何人改了 `html/` 下的代码，受影响详设的行号即失效。**行号失效不算变更，但重新对齐行号必须在最近的一条相关记录里留痕**，否则无法判断某条证据是哪个时点测出来的。

### 0.2 变更记录的最小字段

沿用 `README.md` §7 与 `13-任务卡集.md` §6.2 的规定，缺一不可：

```
必填：日期 · 版本 · 变更内容 · 影响的契约编号 · 影响的页面编号 · 提出人
本体系追加：变更类型 · 原因 · 证据（file:/// 锚点或 git 证据）
```

| 字段 | 写法 | 反例（禁止） |
| --- | --- | --- |
| 版本 | `V5.x`，与 `README.md` §10 版本表一一对应 | 「最新版」「v5」 |
| 日期 | `YYYY-MM-DD` | 「昨天」「近期」 |
| 影响契约 | `ST-H5-021` / `L-MENU-01` / `§4.2` 等可定位编号 | 「存储相关文档」 |
| 影响页面 | `PC-SYS-004` / `MB-020~031` 等页面编号 | 「相关页面」 |
| 证据 | `file:///d:/dev/...#L175` 或 `git diff <file>` 或实测命令与输出 | 无 |
| 提出人 | 署名或「契约编写方」 | — |

### 0.3 谁来提、谁来批、怎么落地

```
① 提交   任何人发现文档与代码/需求不符 → 按 §0.2 字段填写变更申请
② 评估   用检索列出受影响的 TC-* / L-* / 页面编号 / 契约条目，逐条确认
③ 修订   在正文改 + 在本章 §1 追加一节（版本号递增）
④ 同步   检查 13-任务卡集.md §1 中引用了该契约的卡是否需同步更新，重新评估 §2 前置关系
⑤ 留痕   README.md §10 版本表追加一行
```

**审批分级**（与 `13-任务卡集.md` §6.1 一致）：

| 变更类型 | 审批要求 |
| --- | --- |
| 修正文字 / 行号漂移 / 计数勘误 | ✅ 无需审批，改完记一行 |
| 调整优先级、拆分 / 合并任务卡 | ✅ 需给出理由 |
| 修改 `01` 章硬约束或禁止清单 | 🔴 走 §7 四步正式流程 |
| 新增业务域前缀 | 🔴 走 §7 四步正式流程 |
| 修改 `03~12` 中已落定的字段 / 枚举 / 事件名 / 存储键 | 🔴 走 §7 四步正式流程 |
| 修改任务的**目标或验收标准** | 🔴 走 §7 四步正式流程（等于改变契约） |

### 0.4 与 D-遗留问题台账 的分工

```
① 禁止只在正文改而不留痕 —— 半年后没人知道某个数字为什么是这个

```
