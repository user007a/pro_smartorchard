# 03 · 数据契约

> **本章作用**：定义每个数据实体的字段结构、类型、必填性、取值域、校验规则。
> **本章是字段的唯一权威来源。** 任何页面代码、Store 代码中出现本章未定义的字段名，一律按 `00-文档使用说明.md` §3.1「挂起而非猜测」处理。

---

## 0. 本章的两个版本

**重要**：本章采用**双字段名制**。

```
camelCase  —— 现状字段名，现有 153 个 HTML 正在使用，不可一次性改动
snake_case —— 目标字段名，V5.0 生产态统一采用
```

原因：全量改字段名会同时改动 5 个 Store、11 个 `MobileBridge` 映射函数、92 个 PC 页面、33 个移动端页面、16 个 H5 页面，并使浏览器中已有的 localStorage 数据全部失效。这是一个需要独立任务卡与迁移函数的工程，不能混在功能开发里做。

**执行规则**：

| 场景 | 用哪个字段名 |
| --- | --- |
| 改造现有页面 / 修改现有 Store | **camelCase**（保持现状），除非任务卡明确要求改名 |
| 新建实体 / 新建 Store | **snake_case** |
| 写后端接口 / 建表 | **snake_case** |
| 本章两张表不一致时 | 以 `§1 命名规范` 的映射表为唯一转换依据 |

### CT-MAT-001 农资 SKU

**存储**：`smartorchard_material_store_v1.materials[]` · **主键** `code` · **种子** 23 条

| 字段（camelCase 现状 / snake_case 目标） | 类型 | 必填 | 缺省 | 取值域 | snake_case |
| --- | --- | --- | --- | --- | --- |
| code | string | 是 | — | `M-001`…`M-023` | `code` |
| name | string | 是 | — | 中文名 | `name` |
| type | string | 是 | — | 见 §2.3 | `type` |
| typeName | string | 是 | — |肥料/农药/工具 | `type_name` |
| spec | string | 是 | — | 含单位，如 `40kg/袋` | `spec` |
| unit | string | 是 | — | 袋/瓶/把/个/盏 | `unit` |
| warehouse | string | 是 | — | 见 §2.4 | `warehouse` |
| warehouseCode | string | 是 | — | `warehouse1`/`warehouse2` | `warehouse_code` |
| safety | number | 是 | — | 15–200，安全库存 | `safety_stock` ⚠️改名 |
| stock | number | 是 | 0 | ≥0，**唯一运行时可写字段** | `stock` |
| dailyUse | number | 是 | — | ≥0，可小数 | `daily_use` |
| leadDays | number | 是 | — | 7/10/14 | `lead_days` |

**校验规则**：
```
R1  code 唯一，格式 ^M-\d{3}$
R2  type 与 typeName 必须匹配（§2.3）
R3  warehouse 与 warehouseCode 必须成对一致（§2.4）
R4  stock ≥ 0
R5  safety ≥ 0
```

**边界行为（`applyDelta` / `setStock`）**：

| 调用 | 条件 | 返回 |
| --- | --- | --- |
| `applyDelta(id, ±n)` | 标识符未找到 | `{ok:false, stock:null, message:'未找到该农资，库存未变动'}`，**不落盘** |
| | `stock + delta < 0` | `{ok:false, stock:当前值, message:'库存不足，当前库存：X单位'}`，**不落盘** |
| | 正常 | `{ok:true, stock:新值}`，落盘 |
| `setStock(id, v)` | 标识符未找到 | `{ok:false, stock:null, message:'未找到该农资'}` |
| | `v` 非数字 | `parseInt` 失败 → 记为 `0` |
| | `v` 为负 | `Math.max(0, v)` → 记为 `0` |

> **⚠️ `safety` → `safety_stock` 是改名而非snake_case 转换**（`safety` 本身无驼峰）。改名会破坏 23 条种子的兼容性，需与字段改造一同实施。若不做改名，则保持 `safety`。

### CT-MOB-011 离线同步队列

**存储**：`smartorchard_sync_queue[]`

| 字段 | 类型 | 取值 | snake_case |
| --- | --- | --- | --- |
| id | string | `'q_' + Date.now() + '_' + rand5` | `id` |
| type | string | **必填**，缺失则 `enqueue` 返回 `null` | `type` |
| refId | string | 关联业务记录 id | `ref_id` |
| payload | object | 整条业务记录 | `payload` |
| queuedAt | string | ISO，入队时间 | `queued_at` |
| retry | number | 默认 0，失败 +1 | `retry_count` ⚠️ |
| status | string | 恒为 `'pending'` | `status` |
| syncedAt | string | 同步成功后回写 | `synced_at` |

**队列契约**（接入后端时必须保持不变）：

```
enqueue(item)  缺少 type → 返回 null，不入队
              入队后若在线则立即 flush()
flush()       离线（navigator.onLine === false）→ 返回 {ok:false, reason:'offline'}
              同步中（syncing 为 true）→ 返回 {ok:false, reason:'offline'}（直接 return）
              队列空 → {ok:true, count:0}
              成功 → {ok:true, count, remain}，出队已成功项，回写 syncedAt
              失败 → 保留全部，retry +1，返回 {ok:false, reason:'upload-failed'|'error'}
```

**生产替换点**：仅 `simulateUpload(arr)` 一处——把 `setTimeout(400)` 换成 `fetch` 即可，队列/状态栏/重试/去重逻辑全部不动。

### ⚠️ `snzg_permissions` 双key 空间（最危险的一处）

同一对象内并存两种格式的键：

```
格式①  '{roleCode}:{module}:{action}'  →  boolean
       例  'admin:farming:edit' → true
       action ∈ view / add / edit / delete / export

格式②  '{roleCode}:{菜单名}[:{子菜单}]'  →  boolean
       例  'admin:生产管理' → true
       'admin:生产管理:农事计划' → true
```

两套key **语义不同但共存于同一对象**，且删除某角色权限时需同时清理两种格式的键，遗漏即残留脏数据。改造时必须拆分到 `snzg_role_permissions`（操作级）与 `snzg_role_menus`（菜单级）两个 key。见 `appendix/D` L-D06。

## 8. snake_case 改造方案

### 8.1 改造范围与影响

| 影响对象 | 数量 | 说明 |
| --- | --- | --- |
| 5 个 PC Store |全部字段 | 种子数据 + DEFAULT_DATA + 全部读写方法 |
| `MobileBridge` | 11 个映射函数 | 产出 PC 端表格结构，字段名全部需改 |
| `MobileStore` | 9 个 key 的自动注入 | `id`/`createTime` 生成逻辑 |
| PC 页面 | 92 个 | 读取字段、渲染 `data.xxx` |
| 移动端页面 | 33 个 | 同上 |
| H5 页面 | 16 个 | 同上 |
| 大屏页面 | 10 个 | 同上 |
| `demo-seed.js` | 52 KB，15 个场景 | 所有种子数据的字段名 |
| **已有localStorage 数据** | 全量 | **改造后全部失效，必须写迁移函数** |

### 8.2 迁移方案

**必须在 `04-存储契约.md` 指定的迁移入口统一执行**，禁止各页面自行迁移。

```
① 版本标记：每个 Store 的 version 字段从 1 升到 2
② 启动时检测：version === 1 → 递归转换所有键名 → 写回 → version = 2
③ 转换函数：deepSnake(obj) 递归处理对象与数组
④ 不可转换项（白名单）：
   - 键的值不做转换（type/status/level 等枚举值已是 snake 或保持原样）
   - id字符串内容不做转换
   - 已知非字段的键：{version, materials}
⑤ 迁移失败：保留原数据并记录日志，不得覆盖为种子数据
```

> **⚠️ 迁移是高风险操作**：递归转换可能误伤用户自由文本（若某字段值恰好是对象）。建议迁移函数只处理**白名单字段表**（即本章 §1.2 映射表 + 各实体的 snake_case 列），而非无差别递归。

### 8.3 分阶段执行

| 阶段 | 内容 | 任务卡前缀 |
| --- | --- | --- |

> **S1-S2 必须先完成并通过全量回归**，否则 S3/S4 会出现大面积半改状态。

## 9. 全局校验规则汇总

所有数据写入（Store 方法与页面写入）必须满足：

```
V1 禁止写入 null，缺失值用空字符串 / 0 / [] / {} 代替
V2 枚举字段的值必须取自 §2 的枚举表
V3 时间字段落库用 ISO 8601（new Date().toISOString()），
   展示时格式化为 'yyyy-MM-dd' 或 'yyyy-MM-dd HH:mm'
   ⚠️ 现状：h5_* 的 time 字段用的是本地文本而非 ISO，改造时统一
V4 金额字段必须有单位后缀（_wan / _yuan）
V5 布尔字段用 true/false，不用 0/1 或 '是'/'否'
V6 数组字段为空时写 []，不写 null、不省略
V7 主键唯一；upsert 按主键匹配，重复主键视为覆盖
V8 写入前校验结构，结构非法则拒绝写入并保持原数据（不得部分写入）
```
