# 14 · 测试与验收契约

> **本章作用**：定义「怎么判定做对了」。本章不是测试用例集，而是**判定规则**——给验收方（人工或 AI）一套可执行的口径，使其在**没有需求说明书**的情况下，仅凭本章 + `pages/` 层逐页详设，就能对任意一个页面给出「通过 / 不通过」的可判定结论。
> **首要读者**：验收方、AI 编程工具（自检用）。
> **次要读者**：任务执行者（据此自检后再提交）。
> **数据基线**：本章全部数字为 **2026-10-23 实测**（PowerShell 扫描 `docs/详细设计/pages/` 与 `html/` 目录所得），非估算。
> **⚠️ 本章不做的事**：不设计新页面、不重画 DOM、不引入任何构建/测试框架。原型 DOM 已由 `pages/` 层锁定，本章只判定「是否改对了」。

## 0. 验收哲学

### 0.1 为什么本项目需要「验收契约」而非「测试用例」

传统测试用例的前提是「需求已明确、实现已定型、测试环境可重复」。本项目**三条前提全部不成立**：

| 传统前提 | 本项目现状 | 后果 |
| --- | --- | --- |
| 需求说明书可读 | ❌ 验收方手上只有 `html/` 原型与本套契约 | 「符合需求」无法判定 ⇒ 必须改判「符合契约」 |
| 实现已定型 | ⚠️ 实现正在从原型向生产态改造，**DOM 结构锁定但数据层与行为在变** | 断言必须能区分「原型现状」与「目标态」 |
| 测试环境可重复 | ❌ 纯静态、`file://`、零依赖、无 CI | 自动化测试框架无处安放 ⇒ 断言必须**零依赖可执行** |

因此本章的产物是**契约**，不是用例：

```
用例：  测什么 → 怎么做 → 期望什么
契约：  怎么判定真伪 → 在哪一层判定 → 不通过时定位到哪一条编号
```

三条派生原则：

```
① 断言必须指向可观测对象（DOM 选择器 / 存储键值 / 数值 / 文件字节），
   禁止「页面看起来正常」这类不可判定的表述。
② 断言必须绑定编号（AC- ），不通过时能反查缺陷编号（L-）与契约条款（§）。
③ 判定必须分层（L0~L4），因为不同端的可测深度不同：
   大屏无交互表单，就不可能做 L2 行为验收。
```

### 0.2 三条铁律（与 `README.md` §4 契约优先级呼应）

| # | 铁律 | 在验收中的含义 |
| --- | --- | --- |
| 1 | **原型结构 > 一切文档描述** | 验收时**不得**以「DOM 与文档描述不符」为由判不通过；DOM 与原型一致是**通过**项。文档与原型冲突时，按 `README.md` §4 逐级裁决，裁决结果写入验收记录 |
| 2 | **契约未覆盖的字段/状态/枚举，禁止自行发明** | 验收时发现契约没写的行为，**不判 FAIL，判「挂起待裁决」**，并在记录中列出待裁决项。擅自在验收中发明标准 = 违反铁律 |
| 3 | **禁止清单优先级最高** | `01-技术栈与工程约束.md` §3 禁止清单中的任何一条被违反 ⇒ **直接 FAIL，不接受「功能能跑」的辩解**（`01` §3 原文） |

**验收方的裁决权边界**：

```
可判 FAIL ： 违反禁止清单 / 违反本层通过标准 / 断言 Given-When-Then 不成立
可判 PASS ： 全部必过断言成立 且 无阻断级缺陷
只能挂起 ： 契约未覆盖的事项（禁止自行发明判定标准）
禁止动作 ： 以「我觉得这样更好」判 FAIL / 要求重设计已锁定 DOM
```

### 0.3 可判定性标准：一条合格断言长什么样

合格断言 = **给定一个具体前置状态 + 一个具体动作 + 一个具体可观测结果**，三者缺一不可。

**✅ 合格断言（正例，取自 `pages/h5/01-商城与认养.md` §3.2 `TC-H5-004`）**：

```markdown
- [ ] **Given** `h5_addresses` 为空数组，**When** 打开 `h5_checkout.html`，
      **Then** 页面显示「请添加收货地址」，且**不出现**「刘友宝」「151****0531」
      「麓云路159号佳境小区15#1406」任何一段文本，`.address-tag`「默认」不可见；
      点「提交订单」被拦截且 `h5_orders` 长度不变
      —— **当前实现 L264 直接 `return` 保留静态 DOM、L349 又把硬编码地址写进订单**
      （`L-H5-13`/`L-H5-15` 验收点）**
```

三要素齐全：前置（`h5_addresses` 为空数组）、动作（打开页面）、可观测结果（4 个 DOM/存储断言 + 长度不变）。
末句给出**当前实现不满足的原因**与**缺陷编号** ⇒ 验收方无需翻代码即可定位。

**❌ 不合格断言（反例）**：

| 反例 | 为什么不合格 |
| --- | --- |
| 「结算页显示正常」 | 「正常」不可观测；无选择器、无键名、无阈值 |
| 「加购功能可用」 | 未定义「可用」= 什么状态算可用；未指明数据落在哪 |
| 「页面风格与设计系统一致」 | 主观判断；且违反铁律 1（DOM 由原型锁定） |
| 「按需求说明书实现订单退款」 | 验收方无需求说明书；且 `05-接口契约.md` §3.9 已定义流转表，应引用它 |
| 「没有 console 报错就行」 | 缺失前置条件（哪些操作会触发报错）与判定范围（全部页面还是本页） |

**不合格断言的处理**：验收方**不得**自行改写为「看起来 OK 则通过」。正确处理是**回退给契约层补写断言**，并按 `README.md` §7 走变更流程。本章 §3 给出补写格式。

## 1. 验收层级（L0~L4）

分层的依据是**可自动化程度**与**依赖浏览器程度**，从低到高：

```
L0 静态验收 ── 不跑浏览器，只读文件与源码
   ↓
L1 结构验收 ── 跑浏览器，验 DOM 契约（元素 id/class/数量/层级）
   ↓
L2 行为验收 ── 跑浏览器，验交互（点击→状态变化、提交→落盘）
   ↓
L3 数据验收 ── 跑浏览器，验存储键值、跨端联动、统计口径
   ↓
L4 回归验收 ── 全量冒烟，验「改动没打破别的页面」
```

**每一层的通过标准必须全部为「二值可判定」**，禁止出现「基本通过」「大部分正常」。

### 1.1 L0 静态验收（不跑浏览器）

| 项 | 内容 |
| --- | --- |
| **谁执行** | 提交者（自检） + 验收方（复核） + AI 工具（自动化） |
| **怎么执行** | ① 文件存在性与编码检查；② 编号唯一性检查；③ 代码锚点行号有效性检查；④ 禁止 API 静态扫描；⑤ DOM 契约的字面量检查 |
| **通过标准** | ① 157 个 HTML 文件全部存在、全部 UTF-8 **无 BOM**（当前实测 **6 个文件带 BOM**：5 个 H5 端 + `common/js/vr-hotspots.js`，其中 `h5_order.html`/`h5_store.html`/`h5_trace_detail.html` 为**双 BOM** `EF BB BF EF BB BF`）；② `pages/` 层 353 个缺陷编号 + 172 个任务卡编号**零重号**；③ `pages/` 层 **2411** 处 `file:///…#L起-L止` 锚点，行号**全部落在目标文件实际行数内**（当前实测 **2410 有效 / 1 越界**：大屏详设引 `dashboard-design-system.css#L1-L591`，而该文件实际 **590 行**）；④ §5 全部静态规则无 FAIL（当前实测 **10 条未通过**，全部对应 pages 层已登记缺陷）；⑤ 无 `console.log`（全项目 **0** 处 ✅）、无 `??`（源码 **0** 处 ✅）、无 `import`/`export`（**0** 处 ✅）、无 `node_modules/`（**0** ✅）；无 `package.json`/`package-lock.json`/`playwright.config.js`（**0** ✅，2026-10-23 已清理残留物） |
| **失败如何定位** | 每条静态规则在 §5 有唯一编号（`SR-` 前缀），扫描脚本输出必须携带 `SR-` 编号 + 文件路径 + 行号 |

### 1.2 L1 结构验收（DOM 契约）

| 项 | 内容 |
| --- | --- |
| **谁执行** | 验收方（人工浏览器）+ AI 工具（控制台脚本） |
| **怎么执行** | 按 `pages/` 层第 3/5/8/9 区块（DOM 骨架 / 表格列契约 / 分页契约 / 弹窗契约）逐条核对 DOM 实际结构 |
| **通过标准** | ① 元素 `id` / `class` 与详设**完全一致**（含大小写、连字符形式）；② 表格列数与详设「表格列契约」表行数一致；③ 分页容器 id / pageSize / 分页文案三项与详设第 8 区块一致；④ 弹窗 id 清单与详设第 9 区块一致；⑤ 详设中标为 `【保留】` 的 DOM **零改动**（对照原型 diff） |
| **失败如何定位** | 定位到「页面编号 + 区块号 + 详设行号」，例如 `H5-005` 第 8 区块「容器 `div#pagination-container`（L164）✅ 标准」 |

> ⚠️ **L1 的判定基准是详设，不是「更好的写法」**。若详设写的是现状（`paginationContainer`），而改造后变成 `pagination-container`，**按详设判定**——是否统一由 `TC-PAG-001` 决定，不在单页验收中夹带。

### 1.3 L2 行为验收（交互）

| 项 | 内容 |
| --- | --- |
| **谁执行** | 验收方（人工浏览器） + AI 工具（控制台注入事件） |
| **怎么执行** | 按详设第 7/9/10 区块（操作栏契约 / 弹窗契约 / 边界态）与第 12 区块断言逐条触发 |
| **通过标准** | ① 每个可点元素点击后有**可观测状态变化**（DOM 变化 / 存储写入 / 提示出现 / 跳转发生），「点了没反应」= FAIL；② 弹窗提交走「必填校验 → 阻断 → 成功提示」三态，缺任一态 = FAIL；③ 边界态四类全覆盖：**空数据 / 搜索无果 / 字段超长 / 并发写冲突**（详设第 10 区块）；④ 连续快速点击同一提交按钮**不得产生重复写入**（对应 `L-H5-02` 等幂等类缺陷） |
| **失败如何定位** | 定位到「页面编号 + 操作栏/弹窗契约行 + 缺陷编号」 |

### 1.4 L3 数据验收（存储 / 跨端 / 口径）

| 项 | 内容 |
| --- | --- |
| **谁执行** | 验收方（DevTools → Application → Local Storage） + AI 工具（控制台读 `localStorage`） |
| **怎么执行** | ① 按详设第 4 区块「数据绑定」表核对读键 / 写键；② 按 `04-存储契约.md` + `appendix/C-存储键台账.md` 核对键名与归属；③ 按 `07-跨端联动契约.md` 的 11 条链路做跨端读写；④ 按 `appendix/B-错误码全表.md` 核对错误分支 |
| **通过标准** | ① 读键与写键**双向可追溯**：详设第 4 区块写明的每个键，页面确实读写；② 写操作**真落盘**（刷新后仍在）——「提交成功但刷新即丢」= FAIL（对应 `L-MAT-03`/`L-HARV-01` 等「零持久化」类缺陷）；③ 业务键**不得由页面直接 `localStorage.setItem`**（`01` §4.1 唯一入口原则，白名单见 §5 SR-04）；④ 跨端链路在**同一浏览器同一源**下可通（`07` §0.2 三个必然失效场景属架构边界，**不判 FAIL**，判「预期失效」）；⑤ 统计口径在同源两页一致（如 `L-DA-17` 净利率 18.5% vs 16.1% 这类「同项目不同数」= FAIL） |
| **失败如何定位** | 定位到「键名 + 写入方页面 + 读取方页面 + 契约条款（§4.x / §7.x）」 |

> ⚠️ **`file://` 协议下 `storage` 事件不跨标签页**是浏览器行为（`01` 坑 4）。L3 的跨端验证**必须在同一标签页内**用「写方操作 → 读取方主动重读」验证，或按 `12-部署与配置契约.md` §2 起本地服务器后验证。判「换浏览器看不到数据」为 FAIL 是**验收方误判**。

## 2. DoD（Definition of Done）

### 2.1 单张任务卡的 DoD（可勾选清单）

任务卡编号取自 `13-任务卡集.md`（批次 6 产出）；卡内断言编号取自 `pages/` 层第 12 区块。

```markdown
## 任务卡 DoD · TC-XXX-NNN

### 代码
- [ ] 只改了任务卡「允许改动文件」清单内的文件（`git diff --name-only` 与清单逐项比对）
- [ ] 未改动 `html/common/**`、设计系统 CSS（token 取值除外）、任何未授权的 `.html`
- [ ] 未引入 npm 依赖 / 打包器 / 框架 / CSS 预处理器（`01` §3.1）
- [ ] 未引入 `??`、`import`/`export`、`async/await`（新代码）、无兜底的可选链 `?.`（`01` §2.1）
- [ ] 未新增 `console.log`；未用 `alert()`/`confirm()` 替代 Toast/ConfirmDialog
- [ ] 未重设计已锁定的 DOM（只改了标记为【改造】的片段）
- [ ] 新增/改名的 localStorage key 已登记进 `appendix/C-存储键台账.md` 与 `04-存储契约.md`

### 断言
- [ ] 本卡全部断言逐条给出 PASS/FAIL，**无「大致完成」类表述**（`00` §3.4）
- [ ] 每条 FAIL 均写明：期望值 / 实际值 / 缺陷编号
- [ ] 【缺口】类改造已补齐对应验收断言（`00` §5）

### 数据
- [ ] 写操作真落盘（刷新后仍在）
- [ ] 读操作走 Store（或在 `01` §4.1 白名单内）
- [ ] 解析失败 / 类型不符时回退种子数据，**且不回写权威源**（`01` §4.3 第③条）
- [ ] `setItem` 有 try/catch，失败可观测（返回 false + 提示），**不静默失败**

### 静态检查
- [ ] §5 全部静态规则在本卡涉及文件上 PASS
- [ ] 代码锚点行号仍有效（改动后行号漂移的，同步更新详设锚点）

### 回归
- [ ] 浏览器打开本卡涉及页面，console 报错数 = 0
- [ ] 若改动了共享文件 → 已按 §1.5 回归矩阵完成对应回归

### 回报
- [ ] 按 `00` §3.4 的六段格式回报（任务卡 / 完成 / 断言 / 实测 / 存疑）
- [ ] 存疑项已明确标注「契约未覆盖的 XX 点，我按 YY 方式处理，请确认」
```

## 3. 验收断言规范

### 3.1 断言的三段式（Given-When-Then）

```
Given  前置状态（数据/存储/登录态/视口/角色），必须可被具体构造
When   单一动作（打开页面 / 点击某元素 / 提交表单 / 等待某事件），必须唯一
Then  可观测结果（DOM 断言 / 存储断言 / 数值断言 / 跳转断言），必须可二值判定
```

**硬性要求**：

| # | 要求 | 反例 | 正例 |
| --- | --- | --- | --- |
| 1 | Given 必须是**可构造的初始态**，含具体键名与具体值 | 「用户已有数据」 | 「`localStorage['h5_cart']` 中有 3 条商品，其中第 1 条 `checked === true`」 |
| 2 | When 必须是**单一动作**，不夹带多个操作 | 「点击加购并结算」 | 「在首页弹窗选「10斤装」、数量调 2 后点「提交订单」」（同一交互序列内的连续动作允许） |
| 3 | Then 必须是**可观测断言**，至少一条 | 「显示正确」 | 「`h5_cart` 中该项 `spec === '10斤装'` 且 `price === 128`」 |
| 4 | Then 中的**每个数值必须有期望值**，不得只说「一致」 | 「两处金额一致」 | 「两处数值**完全相等**且 `#checkoutTotal` 为 `¥80.00`」 |
| 5 | 空值必须**显式断言**（不是「不报错」） | 「页面不报错」 | 「`document.querySelectorAll('img[src=\"x\"]').length === 0`」 |
| 6 | 负向断言优先写成**可数断言** | 「没有 XSS」 | 「`.adoption-card[onmouseover]` 数量为 0 且 `document.scripts.length` 不增加」 |

### 3.2 断言的可判定性要求

**必须指向以下四类对象之一**（这是「可判定」的充分必要条件）：

```
① DOM 选择器 + 具体属性/文本/数量
   → document.querySelectorAll('#cartList .cart-item').length === 3
   → document.querySelector('.profile-name').textContent === '张建国'

② 存储键 + 具体键值
   → JSON.parse(localStorage['h5_orders']).length === 1
   → sessionStorage.getItem('isLoggedIn') === 'true'

③ 数值 + 具体期望值（含容差声明）
   → document.querySelector('#totalPrice').textContent === '¥80.00'
   → 毛利率 45.0%、利润率 38.0%（容差 0.0%，理由：契约定义）

④ 导航/事件状态
   → location.pathname.endsWith('/h5_cart.html')
   → document.querySelector('#successModal').classList.contains('show')
```

**禁止的断言形态**：

| 禁止 | 原因 |
| --- | --- |
| 「体验流畅」「加载速度快」 | 无阈值即不可判定 |
| 「与设计系统一致」 | 主观；且 DOM 由原型锁定 |
| 「无明显 bug」 | 不可枚举 |
| 「按需求实现」 | 验收方无需求说明书 |

### 3.4 「当前实现不满足 → 改造后必须满足」类断言的特殊要求

`pages/` 层已有大量此类断言（`L-H5-01`~`L-H5-78` 等 353 条缺陷中绝大多数），标准写法是：

```markdown
- [ ] **Given** …，**When** …，**Then** … —— **当前实现 <文件:行号> <做了什么>，
      导致 <可观测后果>（`L-XXX-NN` 验收点）**
```

**验收方对这类断言的判定规则**：

```
1. 断言的 Then 部分在「改造前」**必须不成立**，在「改造后」**必须成立**。
   ⇒ 验收方须先验证现状（可复现缺陷），再验证改造后（缺陷消失）。
   ⇒ 只验证改造后成立 = 证据不足，不能判 PASS，只能判「通过（未验证改造前）」。

2. 「当前实现…」括号内的说明是**证据线索**，不是判定依据。
   若实际代码与说明不符（行号漂移/已修复），以实际代码为准，并记录「详设描述已过期」。

3. 断言引用了缺陷编号（`L-XXX-NN`）时：
   - 该编号在 pages/ 层缺陷表中存在且级别为 P0 → 修复前判 FAIL，修复后判 PASS；
   - 该编号为 P1/P2/P3 → 允许在本批次记为「已知未修」，**不阻断本卡交付**，但必须在批次 DoD 中列出。

4. 断言隐含的前置数据必须由验收方**自行构造**（写入 localStorage 或用演示数据播种器），
   不得以「构造不出这个数据」为由跳过断言。
```

### 8.1 本项目「无构建无框架」对测试的真实约束

必须先承认四条硬约束（`01` §1.1、`01` §1.2、`12` §1.1 实测）：

```
① 零构建：无 webpack/vite/rollup，源码即产物 ⇒ 没有「编译期检查」这道关卡
② 零依赖：无 package.json、无 node_modules ⇒ 没有 npm 生态的测试运行器
③ 零后端：数据全在 localStorage/sessionStorage ⇒ 没有接口 mock 层 / 契约测试框架
④ file:// 可双击打开：不能用 ES Module、不能用 fetch 读本地文件
   ⇒ 不能用任何需要「打包后才能 import」的测试工具
```

**这四条约束的直接后果**：

```
⇒ 没有「跑一遍测试套件就出覆盖率报告」这种东西
⇒ 没有 CI 能自动跑回归（`12` §8 已把「CI 缺失」登记为遗留 `L-DEP-09`）
⇒ 验收只能是：静态扫描（PowerShell / grep）+ 浏览器控制台脚本 + 人工目视
⇒ 每一条验收结论都必须能追溯到「一条可复现的命令」或「一个可粘贴的脚本」
```

**🔴 三条使用纪律**：

```

   确需写入时，必须在脚本头部注明「本脚本会写入 localStorage 的 XXX 键」。
② 脚本执行后必须**刷新页面**再做后续断言，避免内存态与落盘态不一致。
③ 任何「看起来对」的判断必须落到**一个数值或一段文本**上，否则不算通过。

### 8.4 一份可直接粘贴的控制台自检脚本

> **使用方式**：打开目标页面 → F12 → Console → 整段粘贴 → 回车 → 复制输出。
> **脚本性质**：**只读**（不修改页面状态、不写 localStorage）。仅 §8.4.2 的第二段是 L3 的构造式脚本，会写入 localStorage，已在头部注明。
> **判定口径**：与 §3 的断言规范一致——每条判定都落到**具体选择器 / 具体键值 / 具体数值**。

#### 8.4.1 L0/L1/L3 通用自检脚本（只读）

```javascript
/**
 * 数农智果 · 验收自检脚本 v1.0
 * ------------------------------------------------------------
 * 依据：docs/详细设计/14-测试与验收契约.md §5（SR 规则）/ §8.4
 * 用法：目标页面打开 → F12 → Console → 整段粘贴 → 回车
 * 性质：只读。不修改页面状态，不写 localStorage。
 * 判定：每条给出 PASS / FAIL / N-A，并附实测值。
 */
(function () {
  'use strict';

  var R = [];
  function ok(id, name, cond, detail) {
    R.push({ id: id, name: name, level: cond === null ? 'N-A' : (cond ? 'PASS' : 'FAIL'), detail: detail });
  }
  function txt(s) { return (s === null || s === undefined) ? '(null)' : String(s); }

  var doc = document;
  var html = doc.documentElement.outerHTML;
  var isPC = /applefarm_backhand/.test(location.pathname) || /admin|index/.test(doc.title);
  var isMobile = /applefarm_mobile|applefarm_h5/.test(location.pathname);
  var isDash = /applefarm_dataanlye/.test(location.pathname);

  /* ---------- SR-01 Modal 二选一 ---------- */
  var hasCommon = /<script[^>]*src=["'][^"']*common-functions\.js["']/i.test(html);
  var hasCompModal = /<script[^>]*src=["'][^"']*components\/modal\.js["']/i.test(html);
  ok('SR-01', 'Modal 二选一（common-functions.js 与 components/modal.js 不共存）',
     hasCommon && hasCompModal ? false : true,
     'common-functions.js=' + hasCommon + ' components/modal.js=' + hasCompModal);

  /* ---------- SR-02 禁止内联 Pagination ---------- */
  var inlinePagination = /(^|\n)\s*(const|let|var)\s+Pagination\s*=/.test(
    Array.prototype.map.call(doc.scripts, function (s) { return s.textContent || ''; }).join('\n')
  );
  ok('SR-02', '页面未内联声明 Pagination', inlinePagination === false,
     '内联声明=' + inlinePagination);

  /* ---------- SR-10 script 顺序 ---------- */
  var iconifyIdx = html.indexOf('iconify.min.js');
  var iconsIdx = html.indexOf('js/icons.js');
  ok('SR-10a', 'iconify.min.js 早于 js/icons.js',
     (iconifyIdx < 0 || iconsIdx < 0) ? null : (iconifyIdx < iconsIdx),
     'iconify@' + iconifyIdx + ' icons.js@' + iconsIdx);
  var lastScriptIdx = html.lastIndexOf('<script');
  var iframeIdx = html.indexOf('iframe-hide.js');
  ok('SR-10b', 'iframe-hide.js 为最后一个 script',
     iframeIdx < 0 ? null : (iframeIdx > lastScriptIdx),
     'iframe-hide@' + iframeIdx + ' lastScript@' + lastScriptIdx);

  /* ---------- SR-08 禁止 alert() ---------- */
  var inlineScripts = Array.prototype.map.call(doc.scripts, function (s) { return s.textContent || ''; }).join('\n');
  var alertSites = (inlineScripts.match(/(^|[^.\w])alert\s*\(/g) || []).length;
  ok('SR-08a', '页面无原生 alert()', alertSites === 0, 'alert() 命中 ' + alertSites + ' 处');
  var confirmNoDanger = (inlineScripts.match(/ConfirmDialog\.show\s*\(/g) || []).length -
                        (inlineScripts.match(/ConfirmDialog\.show\s*\(\s*\{[^}]*danger/g) || []).length;
  ok('SR-08b', 'ConfirmDialog.show 均显式声明 danger',
     confirmNoDanger <= 0, '未声明 danger 的调用 ' + Math.max(0, confirmNoDanger) + ' 处');

  /* ---------- SR-11 禁止构建依赖（本页可见信号） ---------- */
  var hasModuleScript = /<script[^>]*\stype=["']module["']/i.test(html);
  var hasImportStmt = /(^|\n)\s*(import|export)\s/.test(inlineScripts);
  ok('SR-11', '无 ES Module / import-export 语句', !hasModuleScript && !hasImportStmt,
     'type=module:' + hasModuleScript + ' import/export:' + hasImportStmt);

  /* ---------- SR-12 ES 边界 ---------- */
  var nullish = (inlineScripts.match(/[^?]\?\?[^?]/g) || []).length;
  ok('SR-12a', '无空值合并 ??', nullish === 0, '?? 命中 ' + nullish + ' 处');
  var asyncAwait = (inlineScripts.match(/\b(async|await)\b/g) || []).length;
  ok('SR-12b', '无 async/await（存量例外见 §5 SR-12）', asyncAwait === 0, 'async/await 命中 ' + asyncAwait + ' 处');

  /* ---------- SR-13 BOM（当前文档不可自检，仅提示） ---------- */
  ok('SR-13', '编码 BOM 检查（需外部脚本，见 §8.4.2 段三）', null, '浏览器内无法自检');

  /* ---------- SR-06 分页容器 ---------- */
  if (isPC) {
    var pagIds = Array.prototype.map.call(doc.querySelectorAll('[id^="pagination"]'), function (e) { return e.id; });
    var badPag = pagIds.filter(function (id) { return id !== 'pagination-container'; });
    ok('SR-06', '分页容器 id 为 pagination-container', badPag.length === 0,
       '发现分页容器 id: [' + pagIds.join(', ') + ']');
    var pagText = (doc.querySelector('#pagination-container') || {}).textContent || '';
    var pagOk = !pagIds.length || (/(第\s*\d+\s*页\s*\/\s*共\s*\d+\s*页)/.test(pagText) && /共\s*\d+\s*条记录/.test(pagText));
    ok('SR-06b', '分页文案为「第 X 页/共 Y 页，共 Z 条记录」', pagOk, '实际文案: ' + txt(pagText.trim().slice(0, 60)));
  }

  /* ---------- SR-03 innerHTML 拼接风险（本页存在性提示） ---------- */
  var innerHTMLSites = (inlineScripts.match(/innerHTML\s*(=|\+=)/g) || []).length;
  ok('SR-03', 'innerHTML 拼接点计数（需人工核是否转义）', null,
     '本页 innerHTML 赋值 ' + innerHTMLSites + ' 处 —— 转义正确性须逐条核（§5 SR-03 判定规则）');

  /* ---------- SR-05 setItem 有无 try/catch（本页可见部分） ---------- */
  var setSites = (inlineScripts.match(/localStorage\.setItem\s*\(/g) || []).length;
  var trySites = (inlineScripts.match(/\btry\s*\{/g) || []).length;
  ok('SR-05', '本页 setItem 均有 try/catch 保护', setSites <= trySites,
     'setItem ' + setSites + ' 处 / try 块 ' + trySites + ' 处（数量相等仅作粗筛，须人工核空吞 catch）');

  /* ---------- SR-31 登录守卫位置 ---------- */
  if (isPC && !/login\.html$/.test(location.pathname)) {
    var headEnd = html.indexOf('</head>');
    var guardIdx = html.indexOf('snzg_logged_in');
    ok('SR-31', '登录守卫在 <head> 内联脚本中',
       guardIdx < 0 ? null : (guardIdx < headEnd),
       'guard@' + guardIdx + ' </head>@' + headEnd);
  }

  /* ---------- SR-45 / SR-27 空态 ---------- */
  var emptyState = doc.querySelectorAll('.empty-state').length;
  var hasList = doc.querySelectorAll('tbody, .data-table, [class*="list"]').length > 0;
  ok('SR-27', '列表页具备空态节点', !hasList ? null : (emptyState > 0),
     'empty-state 节点 ' + emptyState + ' 个 / 列表容器 ' + (hasList ? '存在' : '无'));

  /* ---------- SR-29 敏感键 ---------- */
  var sensitive = [];
  for (var i = 0; i < localStorage.length; i++) {
    var k = localStorage.key(i) || '';
    if (/pwd|password|credential|secret|token/i.test(k)) { sensitive.push(k); }
  }
  for (var j = 0; j < sessionStorage.length; j++) {
    var k2 = sessionStorage.key(j) || '';
    if (/pwd|password|credential|secret|token/i.test(k2)) { sensitive.push('session:' + k2); }
  }
  ok('SR-29', '存储中无敏感键名（pwd/password/credential/secret/token）', sensitive.length === 0,
     sensitive.length ? '命中: ' + sensitive.join(', ') : '无');

  /* ---------- SR-48 表单 name 属性 ---------- */
  if (isPC) {
    var ctrls = Array.prototype.slice.call(doc.querySelectorAll('input, select, textarea'))
      .filter(function (e) { return e.type !== 'hidden' && e.type !== 'button' && e.type !== 'submit'; });
    var noName = ctrls.filter(function (e) { return !e.getAttribute('name'); });
    ok('SR-48', '表单控件均带 name 属性', noName.length === 0,
       '无 name 的控件 ' + noName.length + ' 个' +
       (noName.length ? '：' + noName.slice(0, 8).map(function (e) { return e.id || e.className || e.tagName; }).join(', ') : ''));
  }

  /* ---------- SR-37 提交按钮幂等保护 ---------- */
  var submitBtns = Array.prototype.slice.call(doc.querySelectorAll('button, [type="submit"]'))
    .filter(function (b) { return /提交|保存|确认|新增|新建|submit/i.test(b.textContent || ''); });
  var noGuard = submitBtns.filter(function (b) {
    var t = (b.getAttribute('onclick') || '') + (b.getAttribute('onsubmit') || '');
    return !/prevent|disabled|loading|isSubmitting/i.test(t);
