# 12 · 部署与配置契约

> **本章作用**：定义部署形态、环境划分、配置项、发布流程、回滚方案。
> **⚠️ 当前项目无构建、无后端，「部署」指的是静态资源托管。** 本章分「现状」与「生产目标」两部分。

---

## 1. 部署现状

### 1.1 当前形态：零构建静态交付

```
双击 index.html / portal.html 即可运行
无需安装、无需编译、无需服务器
```

**技术特征**：

| 项 | 值 |
| --- | --- |
| 构建工具 | **无**（无 webpack/vite/rollup） |
| 包管理 | **无**（无 package.json 依赖） |
| 运行时依赖 | 仅 `vendor/tailwind.min.js`（407 KB，本地文件） |
| 后端 | **无** |
| 数据 | localStorage / sessionStorage |
| 外部依赖 | 2 个 CDN（见 §1.3） |

### 1.2 目录即产物

```
html/ 目录  =  最终交付物
```

**任何文件修改后无需编译**，刷新即生效。这是「零构建」的核心价值，也是**没有版本化构建产物**的隐患（见 §6）。

### 1.3 🔴 外部 CDN 依赖（2 个）

| CDN | 引用位置 | 用途 | 降级策略 |
| --- | --- | --- | --- |
| `code.iconify.design/3/3.1.1/iconify.min.js` | 几乎所有 PC 页面 | 图标字体 | ❌ **无降级**（`Icons.icon()` 依赖它） |
| `cdn.jsdelivr.net/npm/xlsx@0.18.5` | `export-helper.js` 懒加载 | Excel 导出 | ✅ 失败自动回退 CSV |

**⚠️ 影响**：

```
① 内网/离线环境 → 图标全部失效（`data-icon` 无内容）
② CDN 被墙/超时 → 页面变慢（阻塞渲染）
③ 供应链风险 → 第三方 CDN 可被注入恶意代码
```

**处置**：将 `iconify.min.js` 下载到 `vendor/`，改为本地引用。

### 1.4 字体依赖

```
fonts/YouSheBiaoTiHei.woff    862 KB
fonts/YouSheBiaoTiHei.woff2   632 KB
```

**⚠️ 两份字体共 1.5 MB**，`woff2` 优先，`woff` 兜底。字体仅大屏与门户使用。

## 2. 环境划分

### 2.1 三环境规划

| 环境 | 用途 | 数据源 | 后端 |
| --- | --- | --- | --- |
| **dev 开发** | 本地开发调试 | localStorage + `demo-seed.js` 播种 | 无（`file://` 或本地静态服务器） |
| **test 测试** | 联调与验收 | 后端测试环境 | 测试环境 API |
| **prod 生产** | 正式运行 | 后端生产库 | 生产 API |

### 2.2 🔴 环境隔离的实现障碍

**当前问题**：**代码中无任何环境判断逻辑**。

```javascript
// 现状：所有页面读的都是 localStorage，没有 API 地址配置
var list = JSON.parse(localStorage.getItem('h5_orders') || '[]');
```

**后果**：

```
① 无法区分 dev / test / prod
② 切换环境需改代码（而非改配置）
③ 前端配置（API 地址）在接入后端前无载体
```

**处置**：接入后端时引入 `config.js`（见 §3.2）。

### 2.3 推荐的本地开发环境

**⚠️ 不建议用 `file://` 打开**（尽管可以），原因：

```
① localStorage 在部分浏览器的 file:// 下行为不一致
② 无法测试跨标签页 storage 事件
③ 无法验证 Service Worker / fetch
```

**推荐方式**：

```bash
# 任选其一
npx serve html -p 8080
python -m http.server 8080 --directory html
php -S localhost:8080 -t html
```

访问 `http://localhost:8080/index.html`。

> ⚠️ **必须用同一域名+同一端口**，否则 localStorage 不共享（`localhost` 与 `127.0.0.1` 是不同 origin）。

## 3. 配置项

### 3.1 现状：零配置项

所有可变项**硬编码在代码中**：

| 硬编码项 | 位置 | 影响 |
| --- | --- | --- |
| 5 个演示账号密码 | `login.html:557-561` | 不可配置 |
| `DSEED_DISABLED` 开关 | localStorage | 需手工写入 |
| `GEO_BASE` 坐标 | `mobile-store.js:231` | 天水麦积区，真实项目需改 |
| 各 Store 的 `STORAGE_KEY` | 各 Store 文件 | 一般不改 |
| 追溯码兜底映射 | `trace_h5.html` | 应改为后端 |

### 3.2 目标：外置配置文件

**新建**：`html/config.js`（**注意：不参与构建，是纯 JS 文件**）

```javascript
/**
 * 全局配置
 * ⚠️ 此文件不含敏感信息。密钥必须由服务端持有，前端不存。
 */
window.APP_CONFIG = {
  // 运行环境
  env: 'dev',                     // dev | test | prod

  // API 基础地址（接入后端后启用）
  apiBaseUrl: '',
  wsBaseUrl: '',

  // 应用标识（参与签名）
  appId: '',

  // 功能开关
  features: {
    enableDemoSeed: true,         // 是否播种演示数据
    enableOfflineQueue: true,     // 是否启用离线队列
    enableTraceFallback: false,   // ⚠️ 生产必须 false（见 07 章 XC-H5-001）
  },

  // 业务配置
  biz: {
    pageSize: 10,                 // 默认每页条数
    dateFormat: 'yyyy-MM-dd',
    datetimeFormat: 'yyyy-MM-dd HH:mm',
    timezone: 'Asia/Shanghai',
  },

  // 超时与重试
  network: {
    timeout: 15000,
    maxRetry: 2,
  },

  // 调试开关（生产必须全 false）
  debug: {
    verbose: false,
    logStoreChange: false,
  }
};
```

**加载位置**（必须在所有业务脚本之前）：

```html
<head>
  <script src="config.js"></script>
  <script src="vendor/tailwind.min.js"></script>
  <!-- … -->
</head>
```

**使用方式**：

```javascript
if (window.APP_CONFIG.features.enableDemoSeed) {
  DemoSeed.run();
}
```

### 3.3 环境配置差异

| 配置项 | dev | test | prod |
| --- | --- | --- | --- |
| `env` | `dev` | `test` | `prod` |
| `apiBaseUrl` | `http://localhost:8080/api/v1` | `https://test-api.example.com/api/v1` | `https://api.example.com/api/v1` |
| `wsBaseUrl` | `ws://localhost:8080/ws` | `wss://test-api.example.com/ws` | `wss://api.example.com/ws` |
| `enableDemoSeed` | `true` | `false` | **`false`** |
| `enableTraceFallback` | `true` | `false` | **`false`** |
| `debug.verbose` | `true` | `true` | **`false`** |
| `debug.logStoreChange` | `true` | `false` | **`false`** |

> **🔴 生产环境 `enableDemoSeed` 必须为 `false`**，否则会向真实库写入演示数据。
> **🔴 生产环境 `enableTraceFallback` 必须为 `false`**，否则查不到追溯批次时会展示错误产品的溯源信息（数据真实性事故）。

### 3.4 🔴 敏感信息处理

**禁止放入 `config.js`**：

```
❌ API 密钥 / AppSecret
❌ 数据库连接串
❌ 第三方服务私钥
❌ 用户密码
```

**原则**：签名密钥（`AppSecret`）**必须由服务端持有**，前端只发 `AppId`；服务端用 `AppId` 查对应 `AppSecret` 计算签名。

**当前已存在的安全问题**：

| 项 | 位置 | 风险 |
| --- | --- | --- |
| 5 个演示账号密码明文 | `login.html:557-561` | 生产必须移除 |
| `snzg_passwords` 明文密码 | `system_settings.html` | 🔴 见 `11` 章 L-PERM-07 |
| `snzg_user_accounts.password` 明文 | `home.html` / `system_settings.html` | 🔴 同上 |
| `rememberedPwd` Base64（非加密） | `mb_login.html` | 生产必须移除 |
| 网关凭据 `username`/`password` | `device-store.js` | 🔴 见 `04` 章 L-D09 |

### 4.2 静态资源部署

| 端 | 路径 | 说明 |
| --- | --- | --- |
| PC 后台 | `/admin/` | 95 个页面 + 6 CSS + 14 JS |
| 移动端 | `/mobile/` | 33 个页面 + 1 CSS + 1 JS |
| H5 端 | `/h5/` | 16 个页面 + 5 JS |
| 大屏 | `/screen/` | 10 个页面 |

**⚠️ 路径隔离**：当前代码用**相对路径**（`css/design-system.css`），部署到子路径时无需改动。若改为绝对路径（`/admin/css/...`），全部 95 个页面都要改。**保持相对路径。**

### 4.3 后端服务

见 `05-接口契约.md` §3 的 16 组接口清单。

### 4.4 静态资源缓存

| 资源类型 | Cache-Control | 版本策略 |
| --- | --- | --- |
| HTML | `no-cache`（必须每次校验） | 每次发布变更 |
| CSS / JS | `max-age=31536000, immutable` | **文件名带 hash** 或 query 版本号 |
| 字体 | `max-age=31536000, immutable` | 同上 |
| 图片 | `max-age=2592000` | 同上 |
| `index.html`（根跳转页） | `no-cache` | — |

**版本策略**（当前无构建，需手动管理）：

```
方案 A（推荐）：CDN URL 加版本 query
  <link rel="stylesheet" href="css/design-system.css?v=20261023">
  → 每次发版统一改 v 值（可由脚本批量替换）

方案 B：文件名带版本
  design-system.20261023.css
  → 需要改所有引用，93 个页面 × 5 个 CSS
```

> ⚠️ **当前 95 个页面引用 CSS 时都没有版本号**，更新 CSS 后用户可能拿到旧缓存。这是接入生产前必须解决的问题。

### 4.5 Nginx 配置要点

```nginx
server {
  listen 443 ssl http2;
  server_name orchard.example.com;

  # TLS 1.2+
  ssl_protocols       TLSv1.2 TLSv1.3;
  ssl_ciphers         HIGH:!aNULL:!MD5;
  ssl_certificate     /etc/ssl/certs/orchard.pem;
  ssl_certificate_key /etc/ssl/private/orchard.key;

  # 静态资源缓存
  location ~* \.(css|js|woff2?|jpg|png|svg)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
    # ⚠️ 但 config.js 不应缓存
  }

  location = /config.js {
    expires -1;
    add_header Cache-Control "no-store";
  }

  # HTML 不缓存
  location ~* \.html$ {
    expires -1;
    add_header Cache-Control "no-cache";
  }

  # API 反向代理
  location /api/ {
    proxy_pass http://backend_upstream;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Real-IP $remote_addr;
  }

  # WebSocket
  location /ws/ {
    proxy_pass http://backend_upstream;
    proxy_http_version 1.1;
    proxy_set_header Upgrade    $http_upgrade;
    proxy_set_header Connection "upgrade";
  }

  gzip on;
  gzip_types text/css application/javascript application/json image/svg+xml;
  gzip_min_length 1024;
}
```

## 5. 发布流程

### 5.1 当前流程（手动）

```
1. 修改文件（本地）
2. 浏览器直接打开验证
3. git commit
4. git push
5. 部署：把 html/ 目录整体上传到服务器 / OSS
6. 通知用户强制刷新（Ctrl+F5）
```

**⚠️ 问题**：

```
① 无版本化产物（覆盖式部署，无法回滚到上一版）
② 无环境分离（dev 改完直接上 prod）
③ 无自动化测试
④ 用户可能拿到旧缓存（无版本号）
```

### 5.2 生产目标流程

```
① 提 MR → code review → 合并到 main
② CI 触发：lint + 单元测试 + 构建（若有）
③ 部署到 test 环境 → 自动化验收测试
④ 人工验收（对照 14-测试与验收契约.md）
⑤ 部署到 prod 环境（灰度 → 全量）
⑥ 监控核心指标（错误率、接口耗时）
⑦ 异常时回滚（见 §6）
```

### 5.3 回滚方案

| 方案 | 做法 | 适用 |
| --- | --- | --- |
| **OSS 版本回滚** | OSS 开启版本控制，回滚到上一版本 | ✅ 推荐（静态资源） |
| **CDN 刷新** | 回滚 OSS 后刷新 CDN 缓存 | 必须配OSS 版本控制 |
| **git revert** | 代码层面回滚后重新部署 | 需重新走全流程，慢 |
| **蓝绿部署** | 新旧两套环境并存，切流量 | 资源成本高 |

> **推荐**：OSS 版本控制 + CDN 刷新。可做到分钟级回滚。

## 6. 监控与告警

### 6.1 前端监控（接入后端后）

| 指标 | 采集方式 | 告警阈值 |
| --- | --- | --- |
| JS 错误率 | `window.onerror` + `unhandledrejection` 上报 | > 1% |
| 接口错误率 | `api-client.js` 的 `onError` | > 2% |
| 接口耗时 P95 | `api-client.js` 计时 | > 2s |
| 资源加载失败 | `window.addEventListener('error', ..., true)` 捕获资源错误 | 任意 |
| 存储配额 | 读取 `localStorage` 用量 | > 4 MB |
| 离线队列积压 | `MobileStore.pending()` 上报 | > 100 条 |

### 6.2 错误上报接口（待实现）

```javascript
// 建议在 api-client.js 中实现
window.addEventListener('error', function (e) {
  if (e.target !== window && e.target.tagName) {
    // 资源加载失败
    reportResourceError(e.target.src || e.target.href);
    return;
  }
  reportError({
    type: 'js_error',
    message: e.message,
    filename: e.filename,
    lineno: e.lineno,
    colno: e.colno,
    stack: e.error && e.error.stack
  });
});

window.addEventListener('unhandledrejection', function (e) {
  reportError({ type: 'promise_rejection', reason: String(e.reason) });
});
```

**上报接口**：`POST /api/v1/monitoring/client-errors`

**⚠️ 隐私要求**：上报时禁止包含用户输入内容、手机号、身份证号。

### 6.3 存储容量监控

**现状**：54 个 localStorage 键，约 75–95 KB，占 5 MB 容量的 < 2%。

**风险键**（见 `04-存储契约.md` §3.2）：

| 键 | 风险 | 监控方式 |
| --- | --- | --- |

for (var i = 0; i < localStorage.length; i++) {
  var k = localStorage.key(i);
  total += ((localStorage.getItem(k) || '').length + k.length) * 2;  // UTF-16
}

## 7. 兼容性矩阵

### 7.1 目标浏览器

| 端 | 浏览器 | 最低版本 |
| --- | --- | --- |
| PC 后台 | Chrome / Edge | 最近 2 个大版本 |
| 数据大屏 | Chrome / Edge（1920×1080 全屏） | 最近 2 个大版本 |
| 移动工作端 | iOS Safari / Android Chrome / 微信内置 WebView | ⚠️ 保守，**iOS Safari 14+** |
| H5 端 | 同上 + 主流 App 内置 WebView | ⚠️ 同上 |

### 7.2 移动端特别注意

| 项 | 要求 |
| --- | --- |
| GPS | 必须有降级路径（`MobileStore.geolocate` 已实现） |
| 离线 | `navigator.onLine` 不可靠，所有写操作走队列 |
| 安全区 | `viewport-fit=cover` + `env(safe-area-inset-*)` |
| 键盘 | 输入框在软键盘弹出时不遮挡（`max-height` + 滚动） |
| 字体 | 不依赖 `font-family-number: DIN Alternate`（iOS 无此字体） |

### 7.3 大屏特殊要求

| 项 | 要求 |
| --- | --- |
| 分辨率 | 1920×1080 基准，**不随窗口缩放** |
| 全屏 | 需处理 F11 全屏与浏览器全屏的差异 |
| 常驻 | 需定时轮询刷新数据（建议 5 分钟） |
| 字体 | 使用 `fonts/YouSheBiaoTiHei.woff2` |
