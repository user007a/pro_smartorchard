## 1. 接口风格

| 项 | 约定 |
| --- | --- |
| 协议 | HTTPS（TLS 1.2+），全站加密 |
| 风格 | RESTful |
| 路径版本化 | `/api/v1/...` |
| 数据格式 | JSON，`Content-Type: application/json;charset=utf-8` |
| 编码 | UTF-8 |
| 时间 | 传输用 ISO 8601 带时区偏移（`2026-10-23T14:30:00+08:00`），**存 UTC** |
| 字段命名 | **snake_case**（见 `03-数据契约.md` §1） |
| 分页 | `page` / `page_size` / 返回 `total` / `items` |
| 幂等 | 写操作支持 `Idempotency-Key` 请求头 |
| 链路追踪 | 响应头 `X-Trace-Id`，响应体也返回 `traceId` |
| 文档 | OpenAPI 3.1（Swagger UI 自动生成） |

### 1.1 统一响应结构

**成功**：

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "trace_id": "a1b2c3d4e5f6"
}
```

**失败**：

```json
{
  "code": 104001,
  "message": "地块不存在",
  "data": null,
  "trace_id": "a1b2c3d4e5f6"
}
```

**列表分页**：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "total": 128,
    "page": 1,
    "page_size": 10
  },
  "trace_id": "a1b2c3d4e5f6"
}
```

> **⚠️ 与 `api-mock.js` 的差异**：mock 用 `code: 200` 表示成功，且 HTTP 层无状态码区分。本契约改为**业务码 `code: 0` 表示成功**（0 而非 200，避免与 HTTP 200 混淆），HTTP 状态码仍按语义正确返回。

### 1.2 错误码规范（6 位）

```
格式： [3 位业务域][3 位状态码]
示例： 104001= 农事域(100) + 资源不存在(401)
```

| 业务域 | 区间 | 业务 |
| --- | --- | --- |
| 通用 | `100xxx` | 参数校验、认证、权限、资源不存在、冲突 |
| 农事 | `110xxx` | 计划、记录、巡园、巡检、农事标准 |
| 农资 | `120xxx` | SKU、库存、出入库、退货、供应商、标签 |
| 设备 | `130xxx` | 设备台账、网关、接入配置、视频通道、遥测 |
| 溯源 | `140xxx` | 批次、编码、区块链、查询、统计 |
| 认养 | `150xxx` | 认养树、挂牌、农事绑定、证书、相册 |
| 销售 | `160xxx` | 订单、客户、发票、优惠券、促销 |
| AI | `170xxx` | 生长、物候、气象、病虫害、产量、价格模型 |
| 预警 | `180xxx` | 预警查询、状态流转、设置 |
| 报表 | `190xxx` | 成本、营收、利润、绩效 |
| 文件 | `200xxx` | 上传、下载、图片、视频 |
| 移动端 | `210xxx` | 离线同步、轨迹采集、GPS |
| 数据运营 | `220xxx` | 数据源、归集、模型监控、成效 |
| 经营分析 | `230xxx` | 收入构成、成本、应收、指标 |

**通用状态码（后 3 位）**：

| 后3 位 | HTTP | 含义 |
| --- | --- | --- |
| 000 | 200 | 成功 |
| 001 | 400 | 参数错误 |
| 002 | 401 | 未认证 |
| 003 | 403 | 无权限 |
| 004 | 404 | 资源不存在 |
| 005 | 409 | 资源冲突 |
| 006 | 422 | 业务规则拒绝 |
| 007 | 429 | 限流 |
| 008 | 500 | 服务端错误 |
| 009 | 503 | 服务不可用 |

**示例**：

| code | 含义 |
| --- | --- |
| `100001` | 参数错误 |
| `100004` | 资源不存在 |
| `110006` | 农事业务规则拒绝（如农事记录已审核不可改） |
| `120001` | 库存不足 |
| `210001` | 离线同步冲突 |

## 2. 接口签名与防重

### 2.1 签名算法

```
StringToSign = HTTPMethod + "\n" +
              RequestURI + "\n" +
              SortedQueryString + "\n" +
              SHA256(Body) + "\n" +
              Timestamp + "\n" +
              Nonce

Signature = HMAC-SHA256(StringToSign, AppSecret) + "." + Timestamp + "." + Nonce
```

请求头：

| 头 | 说明 |
| --- | --- |
| `X-App-Id` | 应用标识 |
| `X-Timestamp` | 毫秒时间戳 |
| `X-Nonce` | 随机串（建议 UUID），5 分钟内有效且**一次性** |
| `X-Signature` | 上面的签名值 |
| `Idempotency-Key` | 写操作的幂等键（UUID），24 小时有效 |

**校验规则**：

```
时间戳偏移 ≤ 5 分钟
Nonce 已被使用过 → 拒绝（防重放，需 Redis 记录）
QueryString 按参数名 ASCII 排序后拼接
```

### 2.2 幂等约定

| 操作 | 幂等键 | 服务端行为 |
| --- | --- | --- |
| POST 创建 | ✅ 必填 `Idempotency-Key` | 相同键返回首次结果 |
| PUT 全量更新 | ✅ 必填 | 同上 |
| PATCH 局部更新 | ✅ 必填 | 同上 |
| DELETE 删除 | ❌ 不需要 | 重复删除返回成功 |

> **离线队列的幂等**：`MobileStore.enqueue` 生成 `id: 'q_' + record.id`，`record.id` 1:1 关联业务记录。上传时以 `record.id` 作为服务端幂等键，保证「同一条离线记录多次提交只入库一次」。

```
POST /api/v1/mobile/sync
Content-Type: application/json
Idempotency-Key: q_1780000000000_abcde

{
  "items": [
    {
      "type": "farming_record",
      "ref_id": "farm_1780000000000",
      "queued_at": "2026-10-23T10:30:00+08:00",
      "retry": 0,
      "payload": { /* CT-MOB-001 定义的业务记录 */ }
    }
  ]
}

成功（全部成功）：
{
  "code": 0,
  "data": {
    "succeeded": ["q_1780000000000_abcde"],
    "failed": [],
    "synced_at": "2026-10-23T10:30:02+08:00"
  }
}

部分失败：
{
  "code": 0,                    // ← HTTP 200，业务部分失败
  "data": {
    "succeeded": ["q_xxx"],
    "failed": [
      { "ref_id": "farm_yyy", "code": 110006, "message": "农事记录已审核不可改" }
    ]
  }
}

前端处理（与现有 flush 逻辑一致）：
  200 且 succeeded → 出队，回写 synced_at
  200 但有 failed → 失败项保留在队列，retry + 1
  非 2xx        → 全部保留，retry + 1，返回 {ok:false, reason:'error'}
```

> **`retry` 次数与上限**：服务端返回 4xx（业务拒绝）时**不重试**，直接丢弃并提示用户；返回 5xx 或网络错误时前端重试，超过 5 次后标记为失败并提示用户手动处理。

### 7.1 对外 API

```javascript
window.ApiClient = {
  get(url, params),
  post(url, body, options),
  put(url, body, options),
  patch(url, body, options),
  del(url, options),

  setToken(token),

  onResponse(fn),     // 响应后处理（统一错误处理、token 刷新）
  onError(fn)         // 网络错误处理
};
```

### 7.2 约束

| 约束 | 说明 |
| --- | --- |
| 不引入任何依赖 | 用原生 `fetch` + `Promise` |
| 统一签名 | 所有请求自动带 `X-App-Id` / `X-Timestamp` / `X-Nonce` / `X-Signature` |
| 自动幂等键 | POST / PUT / PATCH 自动生成 `Idempotency-Key` |
| Token 自动注入 | 从 `sessionStorage['snzg_token']` 读 |
| 401 自动刷新 | 拦截 401 → 调 `/auth/refresh` → 重放请求（**最多重试 1次**） |
| 统一错误提示 | 业务码非 0 时 toast `message`，**不重复弹窗** |
| 超时控制 | 默认 15s，超时视为网络错误 |

### 7.3 与 Store 的替换关系

```
现状：页面 → Store → localStorage
目标：页面 → Store → ApiClient → HTTP → 服务端

页面调用处不改
```
