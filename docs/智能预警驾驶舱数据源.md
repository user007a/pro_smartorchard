# 智能预警驾驶舱数据源核查

> 核查对象：`html/applefarm_dataanlye/da_alert.html`（智慧果园 · 智能预警驾驶舱）
> 核查日期：2026-11-10
> 核查范围：后台管理系统（`html/applefarm_backhand`）、消费者 H5（`html/applefarm_h5`）、移动作业端（`html/applefarm_mobile`）、数据大屏（`html/applefarm_dataanlye`）
> 结论口径：以驾驶舱页面实际读取的字段/接口为准，逐项反查三端是否存在可复用的源数据，不以页面视觉上的同名文案作为依据。
> 修复方案与实施计划：`docs/智能预警驾驶舱修复实施计划.md`

## 一、核查结论

### 1.1 总体结论

- 智能预警驾驶舱的**业务数字全部来自前端共享数据层 `window.AlertStore`**（`html/applefarm_backhand/js/shared/alert-data.js`，localStorage 键 `applefarm_alert_state_v1`），后台只是同一个 Store 的另一个消费端，**不存在独立的后端接口/数据库**。
- **同源前提**：`AlertStore` 基于浏览器 localStorage，仅在同一浏览器、同一源下共享；跨浏览器、跨设备、跨终端不会自动同步，也未落服务端数据库。
- **后台管理系统：有源**。预警总览、设备预警、农事预警、内部报告、预警设置、后台顶栏通知均读写同一个 `AlertStore`；气象/病虫害/产量模型和农资库存页面还会通过 `syncSource` 写入模型类、库存类预警。
- **移动端：有源**。`mb_alert.html` 读取全量预警并执行状态流转；`mb_patrol.html` 巡园异常会上报为 `source=manual` 的人工预警。
- **H5 端：无源**。H5 共 16 个页面（商城、会员、订单、社区、溯源等），**没有任何页面引用 `AlertStore`，也没有预警模块或预警字段**。
- 驾驶舱自身存在 **8 项纯前端硬编码/静态资源**（重点预警提示、地图 12 地块边界/品种/责任人、遥感底图等），**后台、移动端、H5 均无对应源数据**。
- 另有 **20 项属于“部分有源”**：底层字段存在，但驾驶舱的统计口径、字段解析方式或字典范围与后台不一致，需要在文档第 4 节逐项确认后再对外使用。

### 1.2 数据项核查统计

共核查驾驶舱业务数据项 **44 项**：

| 结论 | 数量 | 说明 |
| --- | ---: | --- |
| 有源（后台有源，移动端同库可读） | 16 | 级别计数、处置链路、来源分布、平均响应等 |
| 部分有源 / 口径不一致 | 20 | 近24h指标、SLA、地图预警聚合、7日趋势、时效表等 |
| 无源（前端硬编码/静态资源） | 8 | 重点预警提示、地图地块与品种/责任人、底图、达标阈值等 |

### 1.3 三端覆盖情况

| 端 | 是否有源数据 | 关键依据 |
| --- | --- | --- |
| 后台管理系统 | 有 | `alert_overview.html`、`alert_device.html`、`alert_farming.html`、`alert_internal_report.html`、`alert_settings.html`、`index.html` 顶栏；模型页与库存页负责写入 |
| 移动端 | 有 | `mb_alert.html` 读写全量预警；`mb_patrol.html` 写入人工上报；`mb_home.html` 仅有静态消息与入口 |
| 消费者 H5 | 无 | 全目录检索不到 `AlertStore` / `alert-data.js` / “预警”相关引用 |
| 数据大屏（本驾驶舱） | 读取 | 直接 `<script src="../applefarm_backhand/js/shared/alert-data.js">`，读取 `all()` / `stats()` / `topN()` |

### 1.4 取数链路

```text
da_alert.html（智能预警驾驶舱）
  └─ window.AlertStore（js/shared/alert-data.js）
       └─ localStorage: applefarm_alert_state_v1
            ├─ 种子数据：46 条预警（设备 23 + 农事 23）+ 25 条规则 + SLA/静默配置
            ├─ 后台读取：alert_overview / alert_device / alert_farming
            │            alert_internal_report / alert_settings / index.html 顶栏
            ├─ 后台写入：model_weather / model_pest / model_yield（model 来源）
            │            material_inventory（inventory 来源）
            ├─ 移动读写：mb_alert.html（读 + 状态流转）
            │            mb_patrol.html（写入 manual 来源）
            └─ H5：无任何引用
```

## 五、附录：驾驶舱使用的源字段与 API

### 5.1 源字段（`AlertStore` 预警对象）

| 字段 | 含义 | 驾驶舱用途 |
| --- | --- | --- |
| `level` / `levelText` | 级别（urgent/important/reminder/notice） | 级别计数带、Top10、趋势、SLA |
| `source` | 来源（device/manual/model/inventory/system/cert） | 来源分布 |
| `category` | 业务分类（device/pest/weather/soil/growth/environment/yield/inventory/quality/manual） | 类型分布饼图 |
| `status` / `statusText` | 六态（pending/processing/closed/ignored/transferred/voided） | 升级链路、SLA |
| `title` | 预警标题 | Top10、地图详情 |
| `location` | 位置文本 | 地图正则解析、Top10 地块列 |
| `base` / `plot` | 结构化基地/地块 | 后台列表与筛选已使用，驾驶舱尚未使用 |
| `time` | 预警创建时间 | 今日判定、7 日趋势、响应/处置时长 |
| `acceptedAt` | 受理时间 | 平均响应 |
| `closedAt` | 闭环时间 | 平均处置/平均闭环 |
| `respondDue` / `handleDue` | 响应/处置截止 | 超时率 |
| `history` | 处理历史 | 后台详情 |

### 5.2 源 API

| API | 用途 | 驾驶舱调用位置 |
| --- | --- | --- |
| `AlertStore.all()` | 全量预警 | `snapshot()` |
| `AlertStore.stats()` | 级别/状态/来源/分类统计、闭环率 | `renderStats()`、级别带 |
| `AlertStore.topN(10)` | 按级别+时间取前 N 条 | `renderTop()` |
| `AlertStore.typeTrend(30, source)` | 按日分箱趋势 | 后台使用，驾驶舱未用（自行分箱） |
| `AlertStore.config()` | SLA / 静默配置 | 后台使用，驾驶舱未用 |
| `AlertStore.subscribe()` | 数据变更订阅 | 30 秒刷新 + 订阅 + storage 事件 |

### 5.3 核查方法

1. 静态检索 `da_alert.html` 中全部 `getElementById` 与 `AlertStore.*` 调用，形成数据项清单。
2. 反查 `alert-data.js` 的 `stats / topN / slaMetrics / snapshot` 实现，确认字段与口径。
3. 在后台目录检索 `AlertStore`、`alert-data.js`、`syncSource`、`预警`，确认读写端。
4. 在移动端目录检索 `AlertStore`、`预警`，确认读写端。
5. 在 H5 目录全量检索 `AlertStore`、`alert-data.js`、`预警`、`alert`，确认无引用。
6. 对照 `enterprise_plot.html` 的 `smartorchard_plot_master` 与 `da_alert.html` 的 `PLOTS`，确认地块主数据未接入。
