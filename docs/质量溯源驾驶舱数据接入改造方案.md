# 质量溯源驾驶舱接入真实 TraceStore 数据改造方案

- 适用对象：质量溯源驾驶舱 `html/applefarm_dataanlye/da_trace.html`
- 上游依据：[质量溯源驾驶舱数据源.md](./质量溯源驾驶舱数据源.md)
- 目标：在不改动大屏视觉与布局的前提下，把驾驶舱的演示种子数据替换为由 `TraceStore`（业务主数据）+ `CertStore`（资质）+ `HarvestStore`（采收/发货）实时聚合的真实数据；无数据源的指标明确降级展示，不再用假数字填充。
- 编制日期：2026-11-10

---

## 一、改造原则

1. **单一事实来源**：批次、追溯码、扫码、存证、召回统一以 `TraceStore` 为准；证书以 `CertStore` 为准；采收/包装/发货以 `HarvestStore` 为准。驾驶舱不再自行维护业务数字。
2. **渲染层零侵入**：`da_trace.html` 的 DOM、ECharts 配置、SVG 地图逻辑保持不变，只替换 `TraceStatStore` 的取数来源，并增加空值兜底。
3. **聚合下沉**：所有派生计算集中在 `trace-stat-store.js`，页面与后台统计页共享同一套口径，避免两端各算一遍。
4. **不伪造数据**：无法真实获取的指标（平均响应、满意度、证书覆盖批次）在补齐埋点前返回 `null`，前端显示「— / 暂无数据」，禁止继续用常量冒充。
5. **可回退**：保留 `demo` 模式，演示环境可一键切回种子数据；真实数据为空时自动降级，保证大屏不空白。

---

## 二、目标架构

```text
HarvestStore ──→ TraceStore（批次/码/扫码/事件/召回） ─┐
                                                       ├─→ TraceStatStore.derive()
CertStore ─────────────────────────────────────────────┘            │
                                                      内存缓存 + 订阅失效
                                                                    │
                                          ┌─────────────────────────┴──────────────┐
                                          ▼                                        ▼
                                  da_trace.html（大屏）              trace_statistics.html（后台统计）
```

关键变化：

- `TraceStatStore` 由「种子仓库」升级为「聚合视图 + 演示兜底」。
- 新增订阅链路：`TraceStore.subscribe` / `CertStore.subscribe` / `storage` → `TraceStatStore` 重算 → 广播 `traceStatStoreChange` → 大屏重渲染。
- 派生结果**不写 localStorage**（避免脏缓存），只在内存缓存一次，源数据变更即失效。

## 三、数据口径与派生规格

### 3.1 顶部北极星指标

| 指标 | 派生口径 | 数据源 | 空值/边界处理 |
|---|---|---|---|
| 累计上链批次 | `events()` 中 `type === 'batch'` 的 `batchNo` 去重计数 | `TraceStore.events()` | 无事件时回落 `batches().length`；均为 0 时显示 0 |
| 激活追溯码 | `codes().filter(c => c.status === 'active').length` | `TraceStore.codes()` | 0 正常显示 |
| 今日扫码量 | `scans().filter(s => s.at.slice(0,10) === today).length` | `TraceStore.scans()` | 0 正常显示，不再沿用末点 |
| 扫码覆盖省份 | `new Set(scans().map(s => provinceOf(s.region)))` 去掉空值后的数量 | `TraceStore.scans()` | 无扫码时为 0 |
| 批次合格率 | `stats().inspectionRate`（= 有有效检测报告的批次数 / 批次总数 ×100） | `TraceStore.stats()` | 批次为 0 时返回 `null` → 显示「—」 |
| 平均查询响应 | `scans()` 中 `responseMs` 的算术平均（保留 1 位） | `TraceStore.scans()`（需新增埋点） | 无埋点返回 `null` → 显示「—」 |
| 溯源覆盖率 | `codes()` 覆盖到的批次号去重数 / `batches().length × 100` | `TraceStore` | 批次为 0 时 `null` |
| 消费者满意度 | `ratings()` 评分的算术平均（保留 1 位） | `TraceStore.ratings()`（需新增） | 无评价返回 `null` → 显示「—」 |

### 3.2 左栏：区块链存证与追溯码

| 指标 | 派生口径 | 空值/边界处理 |
|---|---|---|
| 区块高度 | `chainStats().latestHeight` | 无事件时 0 |
| 最近 5 个区块 | `events().slice(-5).reverse().map(e => ({ height: e.blockHeight, hash: '0x' + e.hash.slice(0,4), time: e.chainTime }))` | 不足 5 条按实际条数渲染 |
| 上链成功率 | `verifyChain()`：`(total - broken.length) / total × 100`（保留 2 位） | `total === 0` 返回 `null` |
| 追溯码状态分布 | 已激活 `active`、未激活 `inactive`、已过期 `expired`、已作废 = 所属批次存在 `recalls.status === 'active'` 的码数 | 四项合计恒等于累计发码；为 0 时占比显示 0% |
| 累计发码 | `codes().length` | — |

> 说明：`TraceStore` 当前没有码级「作废」状态，最贴近的业务语义是批次召回。改造后「已作废」= 生效召回批次下的追溯码，避免凭空造数。

### 3.3 中栏：批次流向

| 指标 | 派生口径 | 备注 |
|---|---|---|
| 基地节点 | `batches()` 按 `base` 分组计数（值 = 批次数） | 名称直接使用真实基地名，如「天水麦积区基地」 |
| 采收节点 | 按 `grade`（等级）分组计数 | 无等级归入「未分级」 |
| 包装节点 | 按 `spec`（规格）分组；为空时按 `product`（品种）分组 | 不再使用「礼盒装/电商箱装/散装」等无字段支撑的分类 |
| 渠道节点 | 按 `shipment.customer` 关键词归类：含「超市/直营店」→ 商超连锁；含「电商/拼多多/京东」→ 电商平台；含「批发市场/农产品市场」→ 批发市场；含「果品/贸易/进出口」→ 经销出口；其余 → 其他 | 归类规则集中在 `classifyChannel()` |
| 消费者节点 | `shipment.status === 'signed'` 的发货单数 → 家庭用户；「礼品馈赠」暂无字段，不渲染 | 需后续在发货单新增 `consumerType` 才能拆分 |
| 总批次 | 同「累计上链批次」 | 与顶部保持同一数值 |
| 本周新增 | `batches().filter(b => b.createdAt.slice(0,10) >= today-6).length` | 种子数据较旧时会显示 0，属真实结果 |
| 流向渠道数 | `new Set(shipments.map(s => s.customer)).size` | — |
| 平均流通时长 | `avg(发货日期 - 采收日期)`，单位天，保留 1 位 | 无有效发货单时 `null` → 显示「—」 |

### 3.4 右栏：地理热力与认证证书

| 指标 | 派生口径 | 备注 |
|---|---|---|
| 省份扫码量 / TOP5 | `scans()` 按 `provinceOf(region)` 分组求和，按降序取前 12 | `provinceOf` 用「省/自治区/直辖市/特别行政区」正则归一化 |
| 覆盖省份数 | 分组结果的键数量（与列表同源，杜绝 31 vs 12 的矛盾） | — |
| 证书名称 / 编号 / 状态 | `CertStore.qualifications()`，状态取 `computeStatus(c)` 的 `text` 与 `level` | 先按 `level`（有效 > 即将到期 > 已过期 > 已撤销）排序，取前 6 |
| 证书覆盖批次 | `batches().filter(b => (b.certCodes \|\| []).indexOf(c.certNo) >= 0).length` | 关联字段落地前显示 `0`，不再用 `18240 + i×8600` 估算 |
| 在有效期 X / Y | `X = level === 'normal' 的数量`，`Y = 证书总数` | 卡片标题同步改为「状态分布」，避免与「即将到期」混淆 |

### 3.5 底部支撑条

| 指标 | 派生口径 | 边界 |
|---|---|---|
| 近 7 日扫码趋势 | 以今天为终点回溯 6 天，逐日统计 `scans()` 数量，缺失日补 0 | 日期标签动态生成 `MM-DD` |
| 今日扫码 / 环比 | 末点值；环比 = `(今日 - 昨日) / 昨日 ×100` | 昨日为 0 时环比返回 `null` → 显示「—」 |
| 来源渠道占比 | `scans()` 按 `source` 映射：`wechat`→微信扫码、`alipay`→支付宝、`app`→果园 App、`web`→网页查询；历史值 `H5`→微信扫码、`PC`→网页查询 | 四类固定顺序，占比由实际数量计算 |
| 溯源提示示例批次 | 取 `events()` 最新一条，展示其 `batchNo`、`hash`（前 10 位）、对应检测报告号 | 无事件时整块隐藏 |

## 四、代码改造方案

### 4.1 `trace-stat-store.js`：新增聚合层

在现有 `TraceStatStore` 中增加以下内部能力（保持 IIFE / ES5 风格）：

```js
var MODE_KEY = 'applefarm_trace_stats_mode';   // 'auto' | 'demo'
var cached = null;                              // 派生结果内存缓存
var lastSource = 'demo', lastAt = '';

function mode(){
  try { return localStorage.getItem(MODE_KEY) === 'demo' ? 'demo' : 'auto'; }
  catch(e){ return 'auto'; }
}

function invalidate(){ cached = null; }

/** 真实数据聚合：TraceStore 为唯一主源 */
function derive(){
  var T = global.TraceStore;
  if (!T || typeof T.batches !== 'function') return null;
  var batches = T.batches() || [];
  if (!batches.length) return null;

  var codes = T.codes() || [];
  var scans = T.scans() || [];
  var events = (T.events ? T.events() : []) || [];
  var stats = T.stats ? T.stats() : {};
  var chain = T.chainStats ? T.chainStats() : {};
  var verify = T.verifyChain ? T.verifyChain() : null;

  // ...按第三节口径计算
  return {
    totalBatches: countOnChainBatches(events, batches),
    totalIssued: codes.length,
    scanTrend: buildScanTrend(scans, 7),
    provinces: buildProvinces(scans),
    provinceTotal: buildProvinces(scans).length,
    channels: buildChannels(scans),
    codeStatus: buildCodeStatus(codes, T.recalls ? T.recalls() : []),
    chainBlocks: buildChainBlocks(events, 5),
    chainNodes: 6,
    chainConsensus: 'Raft',
    chainSuccessRate: verify && verify.total ? round2((verify.total - verify.broken.length) * 100 / verify.total) : null,
    certificates: buildCertificates(batches),
    flow: buildFlow(batches, scans),
    passRate: stats.inspectionRate == null ? null : stats.inspectionRate,
    avgResponse: avgOf(scans, 'responseMs'),
    traceCoverage: batches.length ? round1(coveredBatches(codes) * 100 / batches.length) : null,
    satisfaction: avgOf(T.ratings ? T.ratings() : [], 'score')
  };
}

/** 统一取数入口：auto 优先真实，失败降级种子 */
function view(){
  if (mode() === 'demo') { lastSource = 'demo'; return ensure(); }
  if (!cached) {
    cached = derive();
    lastSource = cached ? 'real' : 'demo';
    lastAt = nowStamp();
  }
  return cached || ensure();
}
```

然后改造现有 8 个 getter，只需把 `ensure()` 换成 `view()`：

```js
overview: function(){ var d = view(); /* 计算逻辑保持不变 */ },
scanTrend: function(){ return deepClone(view().scanTrend || []); },
provinces: function(){ return deepClone(view().provinces || []); },
channels:  function(){ return deepClone(view().channels || []); },
codeStatus:function(){ return deepClone(view().codeStatus || []); },
chainBlocks:function(){ return deepClone(view().chainBlocks || []); },
certificates:function(){ var v = view(); return deepClone(v.certificates || []); },
flow:      function(){ return deepClone(view().flow || {}); }
```

`overview()` 内需要补两处空值保护：

```js
var dod = (yesterday && today != null) ? round1((today - yesterday) * 100 / yesterday) : null;
```

`recordScan()` 改为一律路由到真实业务层，避免再写演示计数器：

```js
recordScan: function(meta){
  var T = global.TraceStore;
  if (T && typeof T.recordScan === 'function' && meta && meta.code) {
    return T.recordScan(meta.code, meta);
  }
  return { ok: false, message: '缺少追溯码，无法记录扫码' };
}
```

新增模式与来源信息 API（供大屏角标与联调使用）：

```js
setMode: function(m){
  try { localStorage.setItem(MODE_KEY, m === 'demo' ? 'demo' : 'auto'); } catch(e){}
  invalidate(); emit('mode');
},
sourceInfo: function(){ return { mode: mode(), source: lastSource, updatedAt: lastAt }; }
```

订阅与失效：

```js
function bindSource(){
  if (global.TraceStore && global.TraceStore.subscribe) {
    global.TraceStore.subscribe(function(){ invalidate(); emit('trace'); });
  }
  if (global.CertStore && global.CertStore.subscribe) {
    global.CertStore.subscribe(function(){ invalidate(); emit('cert'); });
  }
  window.addEventListener('storage', function(e){
    if (e.key === 'smartorchard_trace_v1' || e.key === 'smartorchard_cert_v1' ||

```

> 注意：`emit()` 只做 `notify()` + `dispatchEvent`，**不做 save**，避免把派生结果写回 `applefarm_trace_stats_v1`；现有 `broadcast()` 保留给种子模式使用。

### 4.2 关键派生函数（口径实现）

```js
function provinceOf(region){
  var s = String(region || '');
  var m = s.match(/^(北京市|上海市|天津市|重庆市|内蒙古自治区|广西壮族自治区|西藏自治区|宁夏回族自治区|新疆维吾尔自治区|香港特别行政区|澳门特别行政区|[^省]{2,8}省)/);
  if (!m) return '';
  return m[1].replace(/省|市|自治区|特别行政区|壮族|回族|维吾尔/g, '') || m[1];
}

function buildScanTrend(scans, days){
  var out = [], base = new Date();
  for (var i = days - 1; i >= 0; i--) {
    var dt = new Date(base.getTime() - i * 86400000);
    var key = ymd(dt);
    out.push({ date: key.slice(5), value: scans.filter(function(s){ return String(s.at).slice(0,10) === key; }).length });
  }
  return out;
}

function buildChannels(scans){
  var map = { wechat:0, alipay:0, app:0, web:0 };
  scans.forEach(function(s){
    var src = String(s.source || '').toLowerCase();
    if (src === 'h5') src = 'wechat';
    if (src === 'pc') src = 'web';
    if (map[src] === undefined) src = 'web';
    map[src]++;
  });
  var total = scans.length || 1;
  return [
    { name:'微信扫码', value: map.wechat, ratio: Math.round(map.wechat * 100 / total) },
    { name:'支付宝',   value: map.alipay, ratio: Math.round(map.alipay * 100 / total) },
    { name:'果园 App', value: map.app,    ratio: Math.round(map.app * 100 / total) },
    { name:'网页查询', value: map.web,    ratio: Math.round(map.web * 100 / total) }
  ];
}

function classifyChannel(customer){
  var s = String(customer || '');
  if (/超市|直营店|华联/.test(s)) return '商超连锁';
  if (/电商|拼多多|京东|淘宝|天猫/.test(s)) return '电商平台';
  if (/批发市场|农产品市场|雨润|万邦|濛阳/.test(s)) return '批发市场';
  if (/果品|贸易|进出口|经销/.test(s)) return '经销出口';
  return '其他';
}
```

> 其余 `buildProvinces`、`buildCodeStatus`、`buildChainBlocks`、`buildCertificates`、`buildFlow` 按第三节表格逐条实现，均为纯函数，输入为 `TraceStore` 的只读快照。

### 4.3 `trace-store.js`：补齐埋点与关联字段

| 项 | 改动 |
|---|---|
| 存储版本 | `VERSION` 由 3 升至 4；`ensure()` 内做软迁移：`d.ratings = d.ratings \|\| []; batches.forEach(b => b.certCodes = b.certCodes \|\| [])` |
| 扫码来源 | `recordScan(code, meta)` 增加枚举校验：`meta.source ∈ {wechat, alipay, app, web, H5, PC}`，非法值回落 `web` |

| 证书关联 | 批次对象新增 `certCodes: []`；新增 `setBatchCerts(batchNo, codes)`，并在赋码/检测合格时按产品品类预置默认资质 |

## 六、验收标准

在大屏页面控制台执行以下断言，全部通过方可验收：

```js
(function(){
  var T = window.TraceStore, S = window.TraceStatStore;
  var o = S.overview(), st = T.stats(), ch = T.chainStats();

  console.assert(o.totalBatches === T.batches().length, '累计批次应与业务库一致');
  console.assert(o.totalIssued === T.codes().length, '累计发码应与业务库一致');
  console.assert(o.activated === st.activeCodes, '激活码应与业务库一致');
  console.assert(o.chainHeight === ch.latestHeight, '区块高度应与存证链一致');

  var csTotal = S.codeStatus().reduce(function(a, x){ return a + x.value; }, 0);
  console.assert(csTotal === o.totalIssued, '码状态四项合计应等于发码总量');

  var trend = S.scanTrend();
  console.assert(trend.length === 7, '趋势必须为 7 天');
  console.assert(trend[6].date === new Date().toISOString().slice(5, 10), '趋势末点应为今天');

  var flow = S.flow();
  var baseSum = (flow.base || []).reduce(function(a, x){ return a + x.value; }, 0);
  console.assert(baseSum === T.batches().length, '基地节点合计应等于批次数');

  var certs = S.certificates();
  console.assert(certs.every(function(c){
    var n = T.batches().filter(function(b){ return (b.certCodes || []).indexOf(c.code) >= 0; }).length;
    return c.batches === n;
  }), '证书覆盖批次应为真实关联数');
})();
```

行为验收：

1. 后台新增采收批次 → 大屏 3 秒内「累计上链批次」「流向基地节点」同步变化。
2. 后台赋码 → 「累计发码」「激活追溯码」「溯源覆盖率」同步变化。
3. H5 扫码 → 「今日扫码量」「近 7 日趋势」「来源渠道」同步变化。
4. 断链或哈希异常 → 「上链成功率」下降，「最近 5 个区块」展示最新异常记录。
5. `TraceStatStore.setMode('demo')` 后数字回到种子值，切回 `auto` 恢复真实值。

## 七、风险与注意事项

1. **同源要求**：大屏与后台需运行在同一 origin（同一 HTTP 服务）下，localStorage 才能共享；`file://` 直开在部分浏览器中 origin 隔离，会导致派生为空而降级为演示数据。验收必须在 `http://127.0.0.1:<port>` 下进行。
2. **脚本加载顺序**：`trace-store.js` 初始化时依赖 `HarvestStore`，必须先于其加载；`da_trace.html` 当前未引用这两个脚本，遗漏会导致 `derive()` 恒返回 `null`。
3. **数据量**：当前聚合为全量遍历（批次 20 余条、扫码上限 1000 条），性能无压力；若后续接入真实生产数据，需在 `derive()` 外增加节流（建议 500ms 防抖）与分页聚合。
4. **不伪造地域**：在接入 IP 归属地或扫码上报经纬度前，省份热力将只显示默认地区，属于预期结果，禁止用随机省份填充。
5. **演示模式残留**：`applefarm_trace_stats_v1` 旧数据保留但不再参与 `auto` 模式，升级后需清理浏览器端旧缓存以避免误解。
6. **后台统计页联动**：该页与驾驶舱共用 getter，改造后其概览区数字会立即变为真实业务数据，需同步检查页面空值文案与风控区口径，避免演示讲解时口径冲突。
