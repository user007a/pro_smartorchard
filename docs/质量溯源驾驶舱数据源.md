# 质量溯源驾驶舱（大屏）数据源核查报告

- 核查对象：`html/applefarm_dataanlye/da_trace.html`（智慧果园 · 质量溯源驾驶舱）
- 对照端：后台管理系统（`html/applefarm_backhand`）、消费者 H5（`html/applefarm_h5`）、移动作业端（`html/applefarm_mobile`）
- 核查方式：静态代码走查（页面渲染逻辑 + 数据层 API + 种子数据），未改动任何代码
- 核查日期：2026-11-10

---

## 一、结论摘要

1. 驾驶舱所有指标统一从 `TraceStatStore`（`html/applefarm_backhand/js/shared/trace-stat-store.js`，存储键 `applefarm_trace_stats_v1`）读取，`da_trace.html` 本身不含业务数据。
2. 后台「溯源管理 → 溯源统计」页面（`trace_statistics.html`）与驾驶舱**读取同一个 `TraceStatStore`**，因此两端数字完全一致，但**该 Store 的数据是独立硬编码种子**，并非由溯源业务数据（批次 / 追溯码 / 扫码日志 / 存证事件）聚合而来。
3. 真正的溯源业务数据层是 `TraceStore`（`trace-store.js`，存储键 `smartorchard_trace_v1`），后台批次档案、赋码管理、链上存证、查询验真以及 H5 溯源页均读取它。**`TraceStatStore` 与 `TraceStore` 之间没有聚合同步链路**，`TraceStatStore.recordScan()` 在整个项目中无任何调用方。
4. 因此：驾驶舱 8 项北极星指标中，**7 项当前未接入后台业务源**（其中激活追溯码、批次合格率、溯源覆盖率 3 项具备可派生的业务数据，仅缺聚合），仅「认证与质量证书」通过 `CertStore` 取到真实数据（但覆盖批次数为公式估算）。
5. H5 端只有 `trace_h5.html` 真正消费 `TraceStore`（批次、检测、追溯码、存证、环境）；`h5_trace_detail.html` 的环节详情为页面内硬编码内容，`trace_intro.html` 只是启动引导页（无溯源数据）。移动作业端**没有任何溯源数据页面**（仅 `mb_label.html` 读取标签库存），对驾驶舱贡献为零。

## 二、取数链路总览

| 层级 | 文件 / 页面 | 数据层 | 说明 |
|---|---|---|---|
| 大屏 | `applefarm_dataanlye/da_trace.html` | `TraceStatStore` + `CertStore` | 只做渲染，`render()` 内 8 次调用 |
| 后台统计页 | `applefarm_backhand/trace_statistics.html` | `TraceStatStore` + `TraceStore` | 概览区与驾驶舱完全同源；风控区取 `TraceStore` |
| 统计种子 | `js/shared/trace-stat-store.js` | localStorage `applefarm_trace_stats_v1` | 硬编码 `DEFAULT_DATA`，无写入入口 |
| 业务主数据 | `js/shared/trace-store.js` | localStorage `smartorchard_trace_v1` | 批次/检测/追溯码/存证/扫码/风控/标签 |
| 证书 | `js/shared/cert-store.js` | CertStore | 企业资质，`trace_stat-store` 仅读其名称/编号/状态 |
| H5 | `applefarm_h5/trace_h5.html` | `TraceStore` | 消费者扫码验真，扫码结果写回 `TraceStore.scans` |
| H5 | `applefarm_h5/h5_trace_detail.html`、`trace_intro.html` | 页面内常量 | 7 个溯源环节展示，非 `TraceStore` |
| 移动端 | `applefarm_mobile/mb_label.html` | `MobileStore` / 标签库存 | 仅标签领用申请，无溯源查询 |

结论标记说明：**有源**＝驾驶舱数字可由现有业务数据真实计算；**部分有源**＝业务数据存在但未接入聚合；**无源**＝仅存在于硬编码种子，无任何业务实体支撑。

## 五、问题清单

| 级别 | 问题 | 影响 |
|---|---|---|
| P0 | `TraceStatStore` 与 `TraceStore` 是两套互不相通的 localStorage；`TraceStatStore.recordScan()` 无调用方 | 后台新增批次、赋码、扫码、上链后，驾驶舱数字完全不变 |
| P0 | 驾驶舱 `totalBatches` 108,420 / `totalIssued` 155,300 / `activated` 96,300 与业务库实际（批次 20~22、追溯码 23、激活 7）相差 3 个数量级 | 数据不可信，演示与业务对不上 |
| P0 | 区块高度 108,420 与 `TraceStore.chainStats()` 约 184.7 万冲突，且两套区块哈希无交集 | 存证可信度受质疑 |
| P1 | 趋势数据日期停留在 2026-10-21，而当前为 2026-11-10 | 曲线长期不更新 |
| P1 | 「覆盖省份 31」与省份数组实际 12 省矛盾；扫码地区样本仅 5 个 | 指标自相矛盾 |
| P1 | 溯源提示示例批次硬编码 `SC-MJ-20260918-0321`，不符合批次号规则 `PC-YYYYMMDD-NNNN` | 示例数据无效 |
| P1 | 证书「覆盖批次」用 18,240 + i×8,600 公式估算；「在有效期 X/Y」与 `CertStore.computeStatus()` 实际状态口径不一致 | 证书卡片数字不可追溯 |
| P2 | 来源渠道枚举（微信/支付宝/App/网页）在 `TraceStore.scans` 中无对应字段 | 渠道占比无法真实统计 |
| P2 | 平均查询响应、消费者满意度无任何数据实体与埋点 | 指标无法落地 |
| P2 | 移动端无溯源数据入口，`h5_trace_detail.html` 内容不可由后台维护 | 三端连通性不完整 |

## 六、改造建议（按指标给出派生口径）

建议新增 `TraceStatStore.aggregate()`，在 `TraceStore` 数据变更时（`TraceStore.subscribe`）自动重算，驾驶舱继续只读 `TraceStatStore`，保持渲染层零改动。

| 驾驶舱指标 | 建议派生口径（全部基于 `TraceStore` / `CertStore` / `HarvestStore`） |
|---|---|
| 累计上链批次 | `events()` 中 `type === 'batch'` 的 `batchNo` 去重计数 |
| 激活追溯码 / 累计发码 | `codes().filter(status === 'active').length` / `codes().length` |
| 追溯码状态分布 | `codes()` 按 `status` 分组（active / inactive / expired；「已作废」取 `recalls` 生效批次下的码） |
| 今日扫码量 / 近 7 日趋势 | `scans()` 按 `at` 日期分组求和 |
| 扫码覆盖省份 / TOP5 | `scans()` 按 `region` 前缀（省）聚合去重 |
| 来源渠道占比 | 扩展 `TraceStore.recordScan(meta.source)` 枚举为 `wechat / alipay / app / web`，H5/PC 端传真实值 |
| 批次合格率 | `stats().inspectionsValid / stats().inspectionsTotal` |
| 溯源覆盖率 | 拥有追溯码的批次数 / `batches().length` |
| 区块高度 / 最近 5 区块 | `chainStats().latestHeight`、`events().slice(-5)` 的 `hash`/`chainTime` |
| 上链成功率 | 校验通过事件数 / 事件总数（复用 `verifyChain()`） |
| 批次流向五级 | `batches()` 的 `base` → `grade` → `spec` → `shipment.customer` → 消费者（H5 订单可补） |
| 本周新增批次 / 渠道数 / 流通时长 | `batches().createdAt` 近 7 日 / `shipment.customer` 去重 / 采收至签收天数均值 |
| 认证证书 | `CertStore.qualifications()` + 真实「证书-批次」关联表；状态统一用 `computeStatus()` |
| 溯源提示示例 | 取 `events()` 最新一条，联动展示其批次号、事件哈希、检测报告号 |
| 平均查询响应 / 满意度 | 需新增 `scans.responseMs` 埋点与 H5 评价表，暂无业务源，建议先下线或标注「示意」 |
