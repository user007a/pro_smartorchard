# 巡园路线 / 飞行日志旧页面迁移收敛计划

## 背景（Context）

「生产管理」菜单已收敛为 6 项，`patrol_route.html`、`drone_log.html` 已无菜单入口，但两个文件仍承担移动端数据桥接：

- `patrol_route.html` 负责写入 `localStorage.mb_patrol_routes`，移动端 `applefarm_mobile/mb_patrol.html` 依赖它渲染打卡点。
- `drone_log.html` 负责展示移动端 `smartorchard_drone_events` / `smartorchard_drone_abnormal`。

直接删除会丢失移动端能力。因此按已确认方案执行：**先把路线配置、移动端飞行事件并入现有页签，再删除两个旧文件**。

## 关键发现

1. `js/shared/production-store.js` 的 `routeList` 只有摘要（`pointCount/requiredCount`），没有 `points`；且 `ensure()` 统一按 `id` 过滤，而路线数据用 `routeId` 作主键，导致**页面二次加载后 routeList 会被清空**。迁移前必须修复主键规则。
2. 移动端 `mb_patrol.html` 读取 `mb_patrol_routes` 的结构为：
   `{ routeId, routeName, base, points[{ id, name, lat, lng, nearRadius, required, order }], enabled, remark, updatedAt }`，按 `base` 聚合基地，取该基地下首条 `enabled && points.length` 的路线。
3. `drone_patrol.html` 目前只引入 `production-store.js`，飞行日志只读 `PS.flightLogs()`；因未加载 `mobile-bridge.js`，其 `PS.importMobile()` 实际为空操作。
4. `index.html` 仅剩 `pageTitleMap` 中 `drone_log.html` / `patrol_route.html` 两行引用；`demo-seed.js` 与 `docs/需求说明书.md` 仍有旧页面描述。

## 实施步骤

### 1. 共享数据层：`html/applefarm_backhand/js/shared/production-store.js`

**1.1 修复 routeList 主键与持久化**

- `ensure()` 过滤集合时，路线集合允许 `x.id || x.routeId` 作为主键，并补写 `x.id = x.routeId`。
- `ROUTE_SEED` 三条路线补充 `id` 与完整 `points`（复用 `patrol_route.html` 中 RT-001/002/003 的默认点位）。

**1.2 新增路线 API**

- `MOBILE_ROUTE_KEY = 'mb_patrol_routes'`。
- `validateRoute(route)`：路线名称、基地必填；至少 1 个点位；点位 `id/name` 必填，经纬度合法（lat -90~90、lng -180~180）、`nearRadius > 0`、`order > 0`；同路线内点位 ID 不得重复。
- `saveRoute(route)`：
  - 校验失败写入 `lastError` 并返回 `null`；
  - 自动补 `id = routeId`、`pointCount`、`requiredCount`、`updatedAt`；
  - 走现有 `upsert('routeList', item)` 持久化；
  - 成功后调用 `syncRoutesToMobile()`。
- `removeRoute(id)`：调用现有 `remove('routeList', id)`，成功后同步移动端。
- `syncRoutesToMobile()`：把 `routeList` 全量映射为移动端结构（含停用路线，便于移动端展示基地选项），写入 `mb_patrol_routes`；写入失败写入 `lastError`。
- `initRoutes()`：
  - 若 `mb_patrol_routes` 已有数据：以其为初始真相，按 `routeId` 合并进 `routeList`（保留 points），保证既有演示/移动端路线可直接编辑；
  - 若不存在：用 `routeList` 种子同步生成移动端数据。
- 导出 `saveRoute`、`removeRoute`、`syncRoutesToMobile`、`initRoutes`，并在 `validate` 下导出 `route`。

### 2. 巡园管理页：`html/applefarm_backhand/farming_patrol.html`

**2.1 路线配置页签增强**

- 表头新增「操作」列；表格上方增加「新增路线」按钮。
- 复用现有 `.modal-overlay/.modal-box` 弹窗体系，新增路线编辑弹窗：
  - 字段：路线编号（只读/自动生成）、路线名称、覆盖基地、状态（启用/停用）、备注；
  - 点位编辑区：点位 ID、名称、纬度、经度、就近半径、顺序、是否必到，支持增删行；
  - 样式复用 `patrol_route.html` 的 `.point-row/.point-grid` 结构（迁入本页 `<style>`）。

**2.2 交互逻辑**

- `renderRoutes()` 增加「编辑 / 启用停用 / 删除」按钮。
- 新增函数：`openRouteEdit(id)`、`addRoutePointRow()`、`removeRoutePointRow(btn)`、`collectRoutePoints()`、`submitRouteEdit()`、`toggleRouteEnabled(id)`、`deleteRoute(id)`。
- 保存统一走 `PS.saveRoute(route)`；删除走 `PS.removeRoute(id)` + `ConfirmDialog`；启停通过读取原路线、翻转 `enabled` 后 `PS.saveRoute`。
- 所有用户数据渲染前做 HTML 转义。
- `DOMContentLoaded`：先 `PS.initRoutes()`，再 `fillRouteOptions()` / `renderRoutes()`；`productionStoreChange` 时同步刷新路线表与下拉。
- 保存/删除/启停后重新渲染并提示 `Toast`，失败时展示 `PS.lastError()`。

### 3. 无人机巡检页：`html/applefarm_backhand/drone_patrol.html`

**3.1 引入移动端桥接**

- 在 `production-store.js` 之前引入 `js/shared/mobile-bridge.js` 与 `js/shared/demo-seed.js`。

**3.2 飞行日志合并展示**

- 新增 `mobileLogs()`：读取 `MobileBridge.droneEvents()`，映射为日志行：
  - `id` 保留事件 ID；`sortieNo`、`base`、`plot` 显示 `—`；
  - `event`：`pause→暂停`、`resume→恢复`、`return→返航`；
  - `time = createTime`，`remark = text`，`source = 'mobile'`。
- `logList()` 合并 `PS.flightLogs()` 与 `mobileLogs()`，保留事件/关键词筛选并按时间倒序。
- `renderLogRow()` 对缺失的航高/速度/电量显示 `—`；移动端行增加「移动端」来源标记（小号标签）。
- 搜索关键词范围扩展到事件、备注、时间。

**3.3 初始化**

- `DOMContentLoaded` 顺序：`DemoSeed.ensure(['drone-events','drone-abnormal'])` → `PS.importMobile()` → 渲染任务/日志/异常。
- 这样移动端无人机异常也能并入「巡检异常」页签，替代旧 `drone_log.html` 的异常视图。

### 4. 删除旧文件与清理引用

- 删除 `html/applefarm_backhand/patrol_route.html`、`html/applefarm_backhand/drone_log.html`。
- `html/applefarm_backhand/index.html`：移除 `pageTitleMap` 中 `drone_log.html`、`patrol_route.html` 两行（约 L664-L668）。
- `html/applefarm_backhand/js/shared/demo-seed.js`：
  - 更新文件头注释，不再指向旧页面；
  - 保留 `drone-events` / `drone-abnormal` / `patrol-routes` 场景（`clear()` 仍会清理这些 key，其他演示页复用现有机制）。
- `docs/需求说明书.md`：
  - 6.2.2.4 / 6.2.2.5 改为说明「飞行日志已并入无人机巡检页签」「巡园路线已并入巡园管理›路线配置」；
  - 更新目录表、页面-数据映射表、localStorage 说明中的旧页面入口描述；
  - 明确 `mb_patrol_routes` 由「巡园管理›路线配置」写入、移动端只读。
- 全局搜索 `drone_log.html` / `patrol_route.html`，清理残余引用。

## 验证方式

1. 启动本地服务：`python -m http.server 8765`（工作目录 `html`）。
2. 打开 `applefarm_backhand/farming_patrol.html`：
   - 路线配置页签可见路线列表；新增路线并添加 2 个点位后保存；
   - 浏览器控制台确认 `localStorage.mb_patrol_routes` 含新路线与点位；
   - 刷新页面，路线仍存在（验证主键修复）；
   - 启停、删除（带确认）正常，删除后移动端 key 同步更新。
3. 打开 `applefarm_mobile/mb_patrol.html`：基地下拉包含新路线基地，打卡点数量与新路线点位一致。
4. 打开 `applefarm_backhand/drone_patrol.html`：
   - 飞行日志页签同时出现 `PS.flightLogs()` 与移动端暂停/恢复/返航事件；
   - 事件筛选、关键词搜索正常；
   - 巡检异常页签能看到移动端异常（`AB-D-*`）。
5. 语法检查：用 Node `vm.Script` 提取各页内联脚本逐块解析，确保无语法错误。
6. 逐页检查控制台无报错；因浏览器缓存，测试时给资源加 `?v=N` 强刷。
