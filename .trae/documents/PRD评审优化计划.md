# 智慧果园管理系统需求说明书评审计划

## 评审目标与范围

**评审对象**：`docs/需求说明书.md`（V2.0，约201KB，29章+附录）

**评审目标**：
- 识别文档在结构完整性、需求清晰度、可追溯性、一致性、可执行性等方面的缺陷
- 发现功能需求、数据模型、接口定义、权限矩阵中的潜在冲突或遗漏
- 评估PRD对研发、测试、设计团队的指导价值
- 输出可落地的优化建议，提升文档质量与项目成功率

---

## 当前状态分析

通过初步阅读，已发现以下需要重点关注的问题：

1. **编号体系隐患**：功能需求编号超过F-300，需验证是否存在跳号或重复
2. **章节编号异常**：第二十四章内出现"23.1/23.2/23.3/23.4"子标题，与章节号"第二十四章"不一致（疑似复制粘贴遗留）
3. **跨端映射盲区**：6.5.3跨端功能映射表中，部分业务功能在移动端或H5端标注为"-"，需确认是否属于设计遗漏
4. **MVP范围膨胀**：17.2 MVP包含8个完整模块，2个月周期可能需要进一步聚焦
5. **术语重复定义**：附录中"物候期"出现两次，定义略有差异
6. **权限矩阵粒度**：7.2权限矩阵仅覆盖到模块级，未细化到按钮/字段级权限
7. **BDD覆盖度**：18.7仅提供12个核心功能的BDD用例，相对于200+功能数量覆盖不足

## 评审维度

| 维度 | 权重 | 说明 |
|------|------|------|
| **结构完整性** | 高 | 章节是否齐全，层次是否清晰，目录与实际内容是否对应 |
| **需求清晰度** | 高 | 需求描述是否明确、无歧义，验收标准是否可量化 |
| **可追溯性** | 高 | 需求编号是否全链路贯通，用户故事-功能需求-测试用例是否可追踪 |
| **一致性** | 高 | 术语、数据模型、权限定义、编号体系前后是否一致 |
| **可执行性** | 高 | 需求是否可在现有资源和技术约束下实现，MVP范围是否合理 |
| **可测试性** | 中 | 验收标准是否支持测试验证，BDD用例是否覆盖核心场景 |
| **技术可行性** | 中 | 架构设计、技术选型、性能指标是否合理 |
| **安全合规性** | 中 | 数据安全、隐私合规、法律风险是否充分考虑 |
| **文档规范性** | 中 | 格式、术语表、更新日志、版本控制是否规范 |

## 红线规则（一票否决项）

| 编号 | 红线规则 | 检查方法 |
|------|----------|----------|
| R-01 | **需求无唯一编号**：功能需求未编号或编号重复、跳号 | 全局扫描F-XXX编号序列，检查连续性与唯一性 |
| R-02 | **核心流程存在断点**：业务流程图中存在无法闭环的路径 | 逐条验证8.1-8.4及Mermaid流程图的闭环性 |
| R-03 | **权限矩阵存在越权漏洞**：角色-功能权限定义存在逻辑矛盾 | 交叉验证7.2权限矩阵与6.x功能需求 |
| R-04 | **关键验收标准不可量化**：P0需求缺少可测量的验收标准 | 检查18.5验收标准是否含具体数值 |
| R-05 | **数据模型与功能需求冲突**：表结构定义与功能描述字段不一致 | 比对第十六章表结构与第六章功能详述 |
| R-06 | **跨端功能映射缺失**：同一业务在多端的功能对应关系不完整 | 验证6.5.3跨端功能映射表覆盖率 |
| R-07 | **版本规划与MVP范围矛盾**：MVP包含非P0功能或遗漏核心P0功能 | 比对17.2 MVP范围与6.x优先级标注 |
| R-08 | **安全风险未定义应对措施**：高等级风险缺少具体应对方案 | 检查19.1-19.4中"高"等级风险的应对措施可执行性 |
| R-09 | **术语定义存在二义性**：同一术语在不同章节定义不一致 | 比对附录A术语表与正文术语使用 |
| R-10 | **接口与数据字典不一致**：接口参数类型、枚举值与数据字典定义冲突 | 比对第十一章接口与第十二章数据字典 |

## 评审方法

### 静态审查（文档内审）

| 方法 | 工具/手段 | 目标 |
|------|----------|------|
| 编号连续性扫描 | Grep + 正则表达式 | 检查F-XXX编号是否连续无重复 |
| 术语一致性检查 | 术语表 vs 全文关键词匹配 | 发现同一概念的不同表述 |
| 交叉引用验证 | 目录 vs 章节标题 vs 锚点链接 | 验证内部链接有效性 |
| 表格完整性校验 | 统计各章表格数量与信息密度 | 发现缺失列或空值行 |

### 逻辑审查（内容评审）

| 方法 | 操作步骤 |
|------|----------|
| 闭环验证 | 对8.1-8.4每个业务流程，从触发条件开始逐步推演至结束状态，标注所有分支 |
| 权限穿透测试 | 选取每个角色，模拟登录后检查可操作功能是否与矩阵一致 |
| 数据流追踪 | 选取一个业务对象（如"追溯码"），追踪从创建到消费的全生命周期数据变化 |
| 边界条件推演 | 对每个P0功能，列举极端输入（空值、最大值、并发请求）检查异常处理 |
| MVP可行性评估 | 统计MVP范围内的P0功能数量，评估2个月周期的团队配置是否匹配 |

### 可执行性审查（落地验证）

| 方法 | 验证点 |
|------|--------|
| 页面-功能映射 | 验证13章页面清单是否覆盖6章所有P0功能 |
| 接口-功能覆盖 | 验证11.2核心接口是否覆盖6章所有跨模块交互 |
| 测试用例-需求覆盖 | 验证18.6测试用例数量与功能模块复杂度是否匹配 |
| 数据模型-功能支撑 | 验证16章表结构是否支持6章所有数据操作需求 |

## 执行步骤

### 阶段一：结构层评审
1. 验证文档骨架完整性（29章是否齐全）
2. 检查编号体系一致性（章节编号、功能编号、表编号）
3. 验证目录与正文对应关系

### 阶段二：需求层评审
4. 逐章阅读功能需求详述（6.1-6.4），标注模糊描述
5. 交叉验证用户故事（3.1）与功能需求（6.x）的映射
6. 验证优先级标注的合理性（P0/P1/P2分布是否均衡）

### 阶段三：逻辑层评审
7. 推演业务流程闭环（8.1-8.4）
8. 权限矩阵逻辑验证（7.2）
9. 数据模型与功能需求一致性验证（16章 vs 6章）

### 阶段四：质量层评审
10. 验收标准可测试性检查（18.5-18.7）
11. 风险应对措施可执行性检查（19章）
12. 非功能性需求量化检查（9章）

### 阶段五：规范层评审
13. 术语表完整性检查（附录）
14. 更新日志规范性检查（附录）
15. 文档格式与可读性评估

## 预期输出

评审报告将包含以下章节：

| 章节 | 内容 |
|------|------|
| **评审概述** | 评审范围、方法、文档版本信息 |
| **总体评估** | 文档质量评级，主要优势与短板 |
| **红线问题清单** | 按R-01至R-10分类的严重缺陷，每项含位置、描述、影响、建议 |
| **优化建议清单** | 按章节列出的中低优先级问题，含具体修改建议 |
| **一致性缺陷汇总** | 术语冲突、编号重复、数据模型不一致等交叉问题 |
| **可执行性风险评估** | MVP范围、技术选型、里程碑的可行性评估 |
| **附录：详细检查记录** | 按章节的完整检查记录表 |

## 假设与决策

1. **评审标准**：以行业通用PRD规范为基准，结合prd-document skill的最佳实践
2. **输出格式**：Markdown评审报告，保存至工作目录
3. **不修改原文**：评审阶段仅识别问题并给出建议，不直接修改需求说明书
4. **范围边界**：仅评审现有文档内容，不补充缺失的业务需求

---

## 验证步骤

1. 检查评审报告是否覆盖全部29章+附录
2. 验证发现的问题是否能在原文中找到确切位置
3. 确认每条建议都是可操作的（含具体的修改方向）
4. 检查是否有遗漏的关键评审维度
